# projects/stackchan/ —— 電線の上の層

**ロボットが何をしているか、どの顔をしているか、何色に光るか、どの身振りを意味するかを決める。どれだけ動くかは決めない。**

⛔ **機体2の数を持たず、機体2の数を1つも借りない。** 手元の個体のゼロ点、符号、枠は、このパッケージの中に無い。⇒ **この層が選ぶ身振りは1つの語であり、語が数になるのは機体の側である**——`projects/stackchan-firmware/main/main.cpp`、2026-10-18 に手元の個体で測られたもの（`projects/stackchan-firmware/records/2026-10-18-the-gestures.md`）。`Decision.sent` が `True` になるのは、ポートが名指され、かつホストの tty が行の全体を受けたときだけである。

⚠️ **Stack-chan の道のうち、ファームを1行も焼かずに検査できる部分がここである。** 事象から段階への対応は機体の測定を要さない。運動は要する。**この層は、検査が鳴れる側の線の上に建っている。**

✅ **2026-10-18 の4つの裁定が、この頁の形である:** ロボットは**相棒**であり鏡ではない。**体が動くのは遷移のときだけ**。電線が運ぶのは**身振りコマンド**であり、20 ms のストリームではない。そして**12個の RGB LED は第一級のチャンネルであり、常に点いている**。

## どこに繋がっていて、どこに繋がっていないか

✅ **Pet の `State` を import する。写しではない。** 5つの表情は一度だけ描かれた（決定 A、`projects/pet/expressions.py`）。2つ目の組を持てば、同じ問いに2つ目の答えを持つことになる。

✅ **2026-10-18 から、機体に繋がっている**——デーモンが枠ごとに1行を基板のコンソールへ書く——**それ以前は繋がっていなかった。** ⛔ **繋がりは一方向で、1行を運ぶ**: この層は自分では何も開かず、何も読み返さず、ホストの tty が行の全体を受けたことだけを言える。検査の外の消費者は、自分の CLI、デーモンのログ、そしてデーモンが名指すポートである。⚠️ **Claude Code にも、2026-10-18 までは繋がっていなかった。** ✅ **それ以来は繋がっている**——`~/.claude/settings.json` の33の事象すべてが `projects/stackchan/hook/` を走らせ、launchd のユーザーエージェントがログイン時にデーモンを起動する。⛔ **このディレクトリは層であって、設置ではない**: ここの plist は複製であり、記録は `docs/stackchan-daemon.md` である。

## 6つの段階

**5つの顔は Pet のものであり、6つの段階はこの層のものである。** 段階はロボットがしていることであり、顔はそれが見せるものである。

| 段階 | 入る事象 | 顔 | 光 | 体 |
|---|---|---|---|---|
| `present` | 表情が尽きたとき／起きたとき | `curious` | `breathe` | 動かない |
| `greeting` | `SessionStart` | `greeting` | `warm` | `look_up` |
| `working` | `UserPromptSubmit` | `curious` | `dim` | **動かない** |
| `blocked` | `PermissionRequest` | `curious` | `alert` | `look_side` |
| `closing` | `Stop` / `StopFailure` | `happy` / `angry` | `warm` / `error` | `nod` / `recoil` |
| `resting` | 90秒の無事象、または `SessionEnd` | `sleepy` | `off` | `rest`（去るときだけ） |

⚠️ **`working` を支えるのは、体で表さない25の事象である。** `PreToolUse` と `PostToolUse` は**体では表さないが、届いている**——**そのたびに idle の時計が戻る。** ⛔ **だから、長いビルドの間もロボットは眠らない。**

⚠️ **表情には寿命がある。** `greeting` と `closing` は3秒で `present` へ戻る。**これは製品の決定であり、測定値ではない。** **次の事象まで残る顔は、その瞬間がどれだけ続いたかについて嘘をつく。**

## 33の事象、3つの種類

**33の名前。フック文書の表から、2026-10-18 に読んだ。** ⛔ **名前はここで発明しない。** 一覧に無い名前は `UnknownEvent` を送出する——**上流で増えた事象が、黙った既定ではなく、誤りとして現れる。**

⛔ **分かれ方は「反応する／しない」ではない。同じ事象の、3つの受け取り方である。**

### 遷移——6つ。段階を変える

| 事象 | 段階 | なぜ |
|---|---|---|
| `SessionStart` | `greeting` | セッションが始まった |
| `UserPromptSubmit` | `working` | 人の番が終わり、機械の番が始まった |
| `PermissionRequest` | `blocked` | **唯一の割り込み**——機械が人を要している |
| `Stop` | `closing` | ターンが終わった |
| `StopFailure` | `closing` | API の誤りでターンが死んだ |
| `SessionEnd` | `resting` | セッションが去ってゆく |

### 証拠——12。読むが、表さない

| 事象 | なぜ |
|---|---|
| `PreToolUse`, `PostToolUse`, `PostToolBatch` | ターンが生きている。体は道具の呼び出しごとには喋らない |
| `PostToolUseFailure` | 数える。ターンで3回目が、最初の合図である |
| `PermissionDenied` | 待ちが終わった——拒否も終わりである |
| `Notification` | ロボットを起こし、idle の時計を戻す。⛔ **人の返事ではない** |
| `MessageDisplay` | 始まりが無い。文が表示されている間ずっと鳴る |
| `SubagentStart`, `SubagentStop`, `TeammateIdle`, `TaskCreated`, `TaskCompleted` | ターンの内側。合図は外側の `Stop` である |

### 無視——15。読まない。それでも生存の証拠である

| 事象 | なぜ |
|---|---|
| `Setup`, `InstructionsLoaded`, `ConfigChange`, `CwdChanged`, `DirectoryAdded`, `FileChanged`, `WorktreeCreate`, `WorktreeRemove` | セッションの文脈が変わった。体はその話をしていない |
| `UserPromptExpansion` | `UserPromptSubmit` の直後に鳴る |
| `PreCompact`, `PostCompact`, `PreModelSwitch`, `PostModelSwitch`, `Elicitation`, `ElicitationResult` | 数を伴う振る舞いがまだ無い——⛔ **そして語は、数の前に足さない** |

⚠️ **`ignored` は「届いていない」ではない。** 33のすべてが idle の時計を戻し、`resting` からロボットを起こす。**「表さない」は「見ていない」ではない。**

⚠️ **`no-behavior` は「振る舞いが無い」ではなく「数を伴う振る舞いが無い」である。** 語彙は対応表であり、対応表に無い語は語彙に無い（`references/README.md`）。⇒ **これらのどれかに反応すれば、機体にできる何かに変えないまま、語を1つ使うことになる。**

## 4つのチャンネル

| チャンネル | 音 | 既定 | 何を運ぶか |
|---|---|---|---|
| 画面 | 無音 | 常に | 顔——見たときの情報 |
| **RGB LED ×12** | **無音** | **常に** | 呼吸・暖色・注意・消灯——**周辺視の中の在席** |
| 首（2軸） | サーボ音 | `--motion on` | **遷移のときだけ** |
| スピーカー | 有音 | `--sound off` | **6つの遷移のうち4つで1語**——`hello`、`pip`、`chime`、`fall`。鳴らすのは基板である |

⛔ **ここに「無音モード」は無い。名前が嘘になるからである。** サーボは鳴る。**運動と音は1つの enum ではなく2つの軸であり**、顔と光はどちらにも従わない——**それらは音を立てない。**

✅ **光は意味であり、RGB ではない。** `Light` は `off`、`dim`、`breathe`、`warm`、`alert`、`error` である。12個の画素への変換はファームの仕事であり、**この個体の LED の並びも色の順も、ここのどの記録にも無い。** ストックのファームは `set_led_color` を公開しているが、この層はそれを呼ばない。

## 密度——遷移だけ

⚠️ **身振りは段階の遷移でだけ選ばれ、リズムは事象そのものが上限を決める:** ターンが開くときに `look_up` が1つ、長いターンが閉じるときに `nod` が1つ——**1ターンにリズムの身振りは2つである。** `PermissionRequest` はリズムではなく割り込みであり、この数から除かれる。**ただし体そのものの下限からは除かれない。**

⛔ **前の身振りから1秒未満の身振りは、並べずに捨てる**——体の欄は `cooldown` になり、`Companion.dropped` が数える。理由は2つ。**並べれば、指令の間隔をこの層が決めることになる。** そして**10/04 の個体では、約1秒より近い間隔がサーボを止め、電源系を落とした**（`MOVE_SETTLE = 1.0`）。⚠️ **その 1.0 秒は、このパッケージで唯一の借り物の数である**——**別の個体の下限であり、この個体の測定値ではない。** **安全側に借り、借り物と名乗り、この個体を測った日に置き換える。**

✅ **光は体を待たない。** サーボが cooldown でも、段階は変わり、LED も変わる。**唯一の割り込みは首を失うことがあり、色を失うことはない。**

## 2つ以上の窓、1つの部屋

⚠️ **VSCode の窓を2つ以上開き、複数のセッションを同時に走らせることがある**（作者の要求、2026-10-18）。**首は1本、顔は1枚である**——全部を映すことはできず、**交互に振り向くこともできない**。交互なら身振りは毎回1秒の下限に入り、**首は端末のあいだで震える。**

✅ **だから注目は1つだけで、外れにくい**（`Focus`）——**最初に喋った窓が取り、その窓は黙るまで持ち続ける。** 持ち主が **90秒**黙れば——**同じ `IDLE_SECONDS` であり、新しい数ではない**——注目は空き、次に喋った窓が取る。**数えるのは、持ち主が1人かどうかだけである。**

✅ **注目は、人が動いた窓へ移る**——`SessionStart` と `UserPromptSubmit`——**そして、機械が人を要する瞬間**——`PermissionRequest` へ。⛔ **背後の窓の `Stop` は移さない**: 機械が終わったことは、人がそこを見ていることではない。移せば、**背後の仕事が終わるたびに首が振れる。**

⚠️ **ほかの窓は、捨てられない。** その事象は部屋の idle の時計を戻し、理由 `distant` で報告される——**「見えた、生きている、この窓ではない」**。⛔ **`sent` はそこでも `False` である。**

## 失敗——3回続けて

⚠️ **道具の失敗1回は日常であり、やり直される。** それは `observed` を受け取り、それだけである。

- **同じターンで `PostToolUseFailure` が3回続けて**——あいだに成功した `PostToolUse` が無いまま——`concern` になる。**光が `alert` になり、顔は変わらない。** ⛔ **テストの失敗に怒る、という反応はしない。**
- **`angry` は `StopFailure` に予約されている**——ターンが API エラーで死んだ場合である。それが異常事態であり、その顔に値する唯一のものである。
- **成功した `PostToolUse` が数を0に戻す。**

## 首を、エンジンが動かす（0.19.10）

✅ **`projects/stackchan/neck/` は、このリポジトリで初めて姿勢の行を書くホストである。** `motion.py` は純粋である: 2つの姿勢と長さを入れ、`engine/trajectory` の標本が電線自身の符号器で符号化されて出る。`__main__.py` は縁である: 各標本自身の時刻を絶対の期限で追い、1刻みに1行を `os.open`/`os.write`/`os.close` で書く——デーモンと同じ経路である。

```
python3 -m projects.stackchan.neck --dry-run --start 80 500 --end 350 500 --duration 1.3
python3 -m projects.stackchan.neck --port /dev/cu.usbmodem101 \
    --start 80 500 --end 350 500 --duration 1.3 --period 0.02 --hold 0.8
```

⛔ **両端はコマンド行で、度の10倍の整数として名指される。これは意図である**: 測った姿勢は基板のものであり（`main/main.cpp`）、パッケージは機体2の数を今も1つも持たない。**姿勢の行は数を運び、遷移の枠は運ばない。** このモジュールが前者を書き、デーモンが後者を書く。

⚠️ **長さは好みではなく制約である——ただし、その数は 0.19.11 で変わった。** それまでこの段落は「サーボは約40°/s で追う」と言っていた——それは `speed=100`、**ファームが書いていた減速であって、サーボの天井ではない。** **2026-10-18、純正自身の呼び出し（`time=20, speed=0`）と比べて測った: 112カウント（35°）を200 ms 未満、約175°/s。** ✅ **ファームはいま純正の呼び出しを書き、参照はサーボ自身の限界まで、およそ `度 / 93` まで速くてよい。** 下の7区間は約 `度 / 60`（山 ≈112°/s）で流した。⛔ **ここのどのテストもそれを見えない**——テストはサーボを持たない。

✅ **同じ日、この個体の上で測った: 7つの区間、822が適用され、拒否ゼロ、clamp ゼロ**、47°の移動は目標から1カウントで終わった。✅ **そしてファームの書き方が変わったあと、同じ7区間を1/3の長さで: 228姿勢、遅刻0、基板で410が適用（228＋保持182）、拒否0、clamp 0——著者の判定は「かなり良い。これでOKだと思う。」である**（`projects/stackchan-firmware/records/2026-10-18-the-neck.md`）。検査されているのは機構である: `tests/test_stackchan_neck.py`、40のテスト。

### 継ぎ目——0.19.14 から、1つの事象が全部を動かす

✅ **フックの遷移は、いま顔と光と首を動かす。** デーモンは**自分の `select` の輪の中に `Stream` を1つ**持ち——子プロセスも、2つ目の時計も無い——枠に刻印したのと同じ `at` から、同じ事象のために姿勢の行を流す。⛔ **その事象が出す枠は `gesture: null` を運ぶ**: 基板の `PlayGesture` はメインループを数秒塞ぎ、その間に書かれた姿勢は遅れて適用される——**1つの出来事が頭を2度動かしてはならない。** ⚠️ **ログの行とクライアントへの返答は、層が選んだ身振りをいまも名乗る**; 消えたのは電線の上の欄である。

- **5つの姿勢は基板の表の写しであり**（`neck/gestures.py`）、写しは `main/main.cpp` を読む検査が留める: 表が動けば、テストが赤くなる。⛔ **正本の順序は変わっていない**——機体が正本であり、これは写しである。
- **`nod` は1本の時間軸に繋いだ2つの区間である。** ⛔ **継ぎ目に標本が2つ並べば頭が1刻み止まる**、そしてそれが著者の言う「動きが硬い」の形である。
- **デーモン起動後の最初の遷移は流さない。** このホストは頭の位置を読まない——機体は何も報告しない——ので、知らない始点を名指す最初の行はその位置への移動になる。**その1回の身振りは基板に任せ**、ホストは表の終わりの姿勢を覚える。⚠️ **それは推測であり、そう名乗る**: 基板が演じ切ったかは観察されない。
- **それ以降のどの運動も、実際に書いた最後の姿勢から始まる**——前の計画の終わりではない。割り込まれた計画は、目指した場所とは違うところで終わる。
- ⛔ **短い書き込みは流れを止め**、行は `sent: false` になる。次の身振りは、書いた最後の姿勢から始め直す。
- ⛔ **流れは1つの身振りのあいだポートを保持し、姿勢ごとには開かない**（0.19.15）。枠はいまも `os.open`/`os.write`/`os.close` を1回ずつで、枠と枠のあいだは何も持たない; **流れはポートを1度開き、各姿勢を `PORT_WAIT = 0.5` の上限の下で書き、要約で閉じる。** ⚠️ **最初の形がデーモンを固まらせることが測られた**: 50 Hz で open/write/close を繰り返すと4度目か5度目で `open()` の中で塞がり、そこへ信号は届かない。**何も受け取らないポートは流れを終わらせ、開けないポートは身振りを枠に残して基板に委ねる。**

⚠️ **機構は機体で1度測られたが、目はまだそこに無い。** 2026-10-19、コンソールに読み取り手を付けて、流れを生で再生した。基板は `pose: stream started — goals on the present positions (yaw 504, pitch 780), torque on` と印字し、沈黙の後に `pose: stream lost after 500 ms — torque released` と `pose: 23 applied, 0 refused, 0 clamped` と印字した; その身振りについてデーモンの要約は `{"neck": "look_side", "applied": 23, "late": 19, "held": 29}` だった。⛔ **23のうち19が遅れて適用された**——基板のメインループがまだ前の身振りを抱えていた。⛔ **首が目に見えて動いたかどうかは、まだ書かれていない**、そしてそれは目を要する——記録の背骨は観察されたことなので（`CLAUDE.md`）。

## フックにまだ要るもの

⛔ **Claude Code のフックは、1事象につき1プロセスである。`Companion` は段階・期限・cooldown を事象のあいだ保つ1つの object である。** その状態をプロセスをまたいで運ぶものは、ここに無い。

⇒ **長命のプロセスが、いま在る**——`projects/stackchan/daemon/` であり、時計と companion とソケットを持つ。**中核（`room.py`）は時計もソケットも読まず、縁（`__main__.py`）がその2つを1人で持つ。** ✅ **設置されている**: launchd のユーザーエージェントがログイン時に起動し、33のフック事象すべてがクライアントを通ってそこへ届く。 ⚠️ **この CLI に直結したフックは、事象のたびに段階と idle の時計を初期化する**——防ぐはずの洪水であり、さらに悪いことに、**ロボットは一度も落ち着かず、眠れない。**

✅ **そして同じ日に、クライアントが在る**——`projects/stackchan/hook/` が標準入力から事象を1つ読み、1行を送り、**何も印字せず、何があっても 0 で終わる。** ✅ **33の事象すべてについて `settings.json` に登録されている。**

✅ **クライアントが送るのは、事象の名前と窓の名前であり、プロンプトではない。** 時刻は行の到着時にデーモンが刻むので、クライアントは時計も状態も持たない。ロボットが知る必要があるのはターンが始まったことであり、何が言われたことではない。**窓の名前が要るのは、窓が1つの体を共有するからである。** **プライバシーを構造で守る——方針ではなく。** ⚠️ **起動と停止の設計は `docs/stackchan-daemon.md`**——**ループとソケットとクライアント、launchd の仕事、`settings.json` への登録は、すべて建てられ、このホストに設置されている。**

✅ **機体への道は、もう欠けた部分が無い:** LED にはドライバが、画面には 0.19.12 からのレンダラが、スピーカーには 0.19.13 からの声があり、伝送路も選ばれている——すべてこのパッケージの下、`projects/stackchan-firmware/` に在る。**この層の出力は `Decision` であり、消費者は端末と、デーモンと、デーモンを通って枠ごとに1行を基板である。**

✅ **`projects/stackchan/daemon/` が、唯一の長命のプロセスである。** `room.py` は中核であり——依頼の形、部屋、次の期限——時計もソケットも環境も読まない。`__main__.py` は縁であり、ソケットを開き `time.monotonic()` を読む唯一のファイルである。

## 部屋から出るもの

✅ **`projects/stackchan/outbound.py` が `Decision` を `Frame` に変える**——顔（または `null`）、光、身振り（または `null`）、そして音（または `null`）。**純粋であり、時計を持たず、機体を1つも名指さない。**

- **枠は、機体の見せるものが変わったときに出す**——顔か光——**か、身振りが選ばれたとき、か、音が名指されたとき、か、そのプロセスの最初の決定であるとき。** ⛔ **音は事象であって状態ではない**: 光は覚えられて再び送られ、音は覚えられない。その欄の `null` は*この枠は黙る*を意味する。 ⛔ **最初の決定は必ず出す。その前の機体の状態が知られていないからである**; 決定が名指さなかった顔は、枠自身の状態から埋めるので、機体は自分が何を映していたかを憶えておかなくてよい。
