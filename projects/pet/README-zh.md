# projects/pet/ — 画面与运动

**住进 `projects/` 的第一件东西，也是 Pet 之中唯一已经存在的部分。**

**核心与画面，就一个状态而言，接上了。** `motions/greeting.json` 是一次会话写下的 `Motion Intent`，
**`motion.py` 准入它、算出轨迹、过门并送到 Mock**——**并在同一个循环的第一个刻点里画出脸。**
**那正是*脸与身体出自同一只时钟*，而且它被断言下来，不是被描述出来。**

⛔ **身体是 Mock 的，不是机器的。** 这里不打开任何端口；**串口层依然是机器唯一握着的部分。**

## 这里记录着两个决定

- **A —— 保留这张脸，并自称「猫」**（2026-09-28，作者）。`expressions.py` 中的五张脸，
  **是从概念文档 §5 逐字抄来的**——**一个字都没有改，连缩进也是。**
  变的是记录，不是图。**为什么「写下名字」本身就是决定，写在 `expressions.py` 里**
  ——**禁止动物形状的论据以「这个 ASCII 是抽象的」为前提，而 `/\_/\` 就是猫的耳朵。**
- **C —— Pet 住在这个仓库内部，`projects/` 之下**（2026-09-28，作者）。
  ⚠️ **这一个是在违背推荐的情况下决定的。** 当时给出的代价是对 `CLAUDE.md` 中一条固定方针的附注，
  **而那条附注还没有付**——**它与 `projects/` 之下第一个调用 LLM 的文件落在同一个提交里。**
  **这个目录里没有那样的文件。**

## 五张脸

| 状态 | 脸 | 概念文档为它配的运动 |
|---|---|---|
| `happy` | `( ^.^ )` | small bounce → small bounce → settle |
| `sleepy` | `( -.- )` ＋第四行 `z` | slow downward movement → small sway → still |
| `angry` | `( >.< )` | quick tilt → hold → small corrective movement |
| `curious` | `( o.o )` | small left tilt → center → small right tilt |
| `greeting` | `( ^.^ )` | small forward tilt → return |

⚠️ **最后一行不是笔误：`happy` 与 `greeting` 是同一张脸。**
**它们不是同一个表情**——**把两者区分开的只有运动，别的什么都没有。**
**这是实测，不是主张**（`tests/test_pet_expressions.py`）。
⇒ **去掉身体，这两个状态就变成一个。** **「脸与身体出自同一只时钟」不是样式偏好
——它是从这五张图里出来的。** **而第一个做出来的运动之所以是 `greeting`，原因就在这里。**

## 那一个运动

`motions/greeting.json`——意图，也是唯一存在的那一个:

| 词语 | 自由度 | 量 | 时间 | 组 |
|---|---|---|---|---|
| `small forward tilt` | `pitch` | `+40` 计数（512 → 552） | 600 ms | 0 |
| `return` | `pitch` | 512 | 600 ms | 1 |

⚠️ **词语不在文件里。** `schemas/motion-intent.schema.json` 设了 `additionalProperties: false`，
**所以没有栏位可以放它们**——**因此它们的住处是 `motion.py`。** ⛔ **这不是不便：`Intent` 已经是计数，
它说不出「为什么是这个数」。** **把词语与数字配成对的那一行，在 `references/README.md` 里。**

⛔ **词语来自概念文档 §5。数字不来自任何地方**——`demo_rig()` 把它提供的每一个数都列了出来，
**并写明各自不是什么。** ⚠️ **尤其是，它一个速度上限都没有提供**，所以落差检查不会响——
**这一趟里真正在起作用的是包络（190〜833），而那是唯一的实测值。** **不要把一次绿色的运行读成「安全」。**

## 运行

从仓库根目录:

```
python3 -m projects.pet                # 依次轮转五张，直到 Ctrl-C
python3 -m projects.pet --state sleepy # 只画一张，然后退出
python3 -m projects.pet --sync         # 使用同步更新
python3 -m projects.pet --motion greeting  # 跑运动，并从同一个时钟画出脸
```

⚠️ **`--sync` 默认为关闭，这是有意的。**
**你面前的终端是否实现 `CSI ? 2026 h`/`l`，本工房这一侧尚未测量。**
**未经测量的假设，不该成为唯一触碰你终端的那个地方的默认值。**

⚠️ **`--motion` 的收件人是 Mock，而最后一行会这么说**——**同时说明因此有哪几项检查没有响。**
**打印出四个零的一趟，是「没有任何东西被拒绝」的一趟。它不是「关于机器有任何东西被验证了」的一趟。**

## 被检查的内容

**`tests/` 对这个目录主张七件事**——四个文件，与其余测试一起运行:

- **一帧就是一次 write**——**而这是安全问题，不是速度问题。**
  `frame()` 把同步更新的开始与结束**放在同一个字符串里**返回，
  因此只写一次的调用方不可能把这一对留在打开状态。
  **`close()` 发出的第二个 `SYNC_END` 是对 write 被截断时的救助，它是幂等的。**
- **帧的形状不随状态改变**——五个状态的箱子都是 8 列 × 4 行，
  所以重画时不会残留上一帧的行。
- **没有比一列更宽的字符**——**本工房的文档是 CJK。**
  脸里混进一个全角字符，**屏幕上图会移位，而 `len()` 什么都不会说。**
- **`projects/` 不 import 任何会变化的东西**——与 `engine/` 相同的禁止清单，
  取自 `tools/purity.py`。⛔ **`__main__.py` 被排除清单点名，而排除本身也被检查**
  ——**入口是这个仓库唯一可以 import `time` 的地方，
  因为循环从调用方接收它的时钟。**
- **脸与身体出自同一个刻点**——`Take.drawn_at` 等于 `ticks[0].started`。
  ⛔ **脸是在第一个刻点之内画出的，绝不在循环之前**——**画在外面，*同一只时钟*就只是描述而不是主张，
  也就没有任何东西可以断言。**
- **Pet 回到意图第二组所说的位置**——**并且两组之间的交界处什么都不跳。**
  ⚠️ **后半句是 2026-09-28 补上的，在它本可以抓住的那个缺陷之后**：
  **表演结束时，组被退回最后一组，但 *offset* 没有退回去**——
  **因此结束之后的刻点送出的，是最后一组的*第一个*采样。** **见 `HISTORY.md` 的 0.5.0。**
- ⛔ **从一个意图没有为它写过的起始位置跑起来，Pet 会离开那里。**
  **这一条记录的是类型的限界，不是缺陷。** `target` 是绝对计数，
  **所以意图不知道机器在哪里**——把为 512 写的意图从 400 跑起来，
  **Pet 会去 512，而不是它原来所在的地方**——**而门一个也不拒绝，因为每一帧都是合法的。**
  **错的是意义。** **确定性的核心不知道那些数字是否有意义。**

⚠️ **最后一条并不能让这个目录和 `engine/` 一样强。** 它看的只是 import
——**而且上面的主张都是关于 Mock 的。**

## 这里没有的东西

- **没有串口层。** Mock 是一个假装成控制箱的 Python 对象，**帧走不到它之外。**
  ⛔ **机器唯一握着的就是这一层**——**而它也正是 Mock 与实机分歧最大的地方。**
- **只有一个运动，五个动词里只用了一个。** ⚠️ **语汇的五个动词里有三个指向这台机器没有的平移**
  ——**所以还没有一个响过 D-12 加在 `references/` 上的那一栏。**
- **没有 LLM。** 何时何地改变，见上面的决定 C。
- **没有反馈。** 起始位置是手填的——**`demo_rig()` 写着那个数是哪一个，以及它不是测量。**
  **机器不会报告它做了什么。**
