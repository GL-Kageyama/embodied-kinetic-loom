# projects/stackchan-firmware/ — 电线的机体一端

⛔ **只有源码。没有构建。没有烧写。** 本仓库从未向机器2写入一个字节，而这个目录不会改变这一点。

**这里有的:** 一个命令帧的解析器，以及一个拒绝所有身势的 `apply_command`。**这里没有的:** 角度。⛔ **把 `perk` 变成舵机位置的数字，不在任何记录里**——所以诚实的固件没有它，只接收符号，不移动。

⚠️ **这个拒绝不是某个被忘记写下的行的占位符。** 在手边的个体被测量之前，**它就是那一行**（`docs/first-contact-stackchan.md`）。**猜出来的角度在源码里与测量出来的角度无法区分**——所以一个也不写。

## 帧携带什么

**每条命令一行 JSON**，而命令在机体该显示的东西发生变化时到达——阶段、脸、光或选中的身势；这不是流。⚠️ **脖子只在阶段转换时动**: 身势只在那里被选中。契约是 `schemas/stackchan-command.schema.json`，两端都读它。

| 栏 | 值 | 含义 |
|---|---|---|
| `face` | Pet 的五张脸，或 `null` | 显示这个表情。`null` = 不改变 |
| `light` | `off` / `dim` / `breathe` / `warm` / `alert` / `error` | 始终存在，永不为 `null` |
| `gesture` | `perk` / `nod` / `turn` / `settle` / `flinch`，或 `null` | 动脖子。`null` = 不动 |

⛔ **没有 `sound` 栏。** 扬声器是一个还不存在的通道。

## 这份源码故意不决定的事

- **角度表** — 没有记录，没有测量，就没有行;
- **LED 映射** — 十二个像素及其颜色顺序，这台个体没有记录;
- **显示渲染器** — 在这里脸是意义，不是像素;
- **传输路径** — 这个文件读一行。这一行如何到达板子，是电线的成帧问题，而手边的个体是厂商云的客户端，不是 LAN 上的服务器。

## 第一次写入之前必须发生的事

✅ **写入路径已经走通了; 它之后的启动还没有。** 2026-10-18，在手边的个体上: 原厂镜像被写入并逐位读回，然后当前快照被写在它上面，也同样读回。⛔ **仍然开着的是本节所点名的步骤的后半——*然后读回版本*: 恢复之后的启动，一次也没有被看到。** `docs/first-contact-stackchan.md` 持有那个文件、它的哈希、测到的差，以及这次作业证明什么、不证明什么。

⚠️ **这个目录里什么都不会响。** 这里没有 C++ 测试，也没有构建。`tests/test_stackchan_wire.py` 读取这些字面量，并在它们与契约不一致的那天变红——那是唯一的检查，**而它检查的是副本，不是机体。**
