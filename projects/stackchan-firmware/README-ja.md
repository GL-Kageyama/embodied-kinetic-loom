# projects/stackchan-firmware/ — 電線の機体側

✅ **ビルドし、焼き、頭が回った——2026-10-18。** このディレクトリは `build/stackchan-vessel.bin` を作り、`0x510000` に書き、ハッシュで照合し、走らせた: アプリは `ready.` を印字し、両方のサーボが ping に答え、`bench move 5` が頭を回した。⛔ **下の断りは変わっていない**——どの身振りにも角度は無く、それを運ぶ枠は今も断られる。**記録は `records/2026-10-18-first-arrival.md` であり、観察がその背骨である。**

**ここに在るもの:** 1つのコマンド枠の読み手と、すべての身振りを断る `apply_command`。**ここに無いもの:** 角度。⛔ **`perk` をサーボ位置に変える数は、どの記録にも無い**——ベンダーのソースが持つのは度とカウントの間の**スケール**であり、それは**どの**角度が `perk` かという数とは別の数である。

⚠️ **この断りは、誰かが書き忘れた行の代わりではない。** 手元の個体が測られるまで、**これがその行である**（`docs/first-contact-stackchan.md`）。**当て推量の角度は、ソースの中では測定された角度と見分けがつかない**——だから1つも書かない。

## 枠が運ぶもの

**1コマンドにつき JSON 1行**、そしてコマンドは、機体の見せるものが変わったときだけ届く——段階・顔・光・選ばれた身振りのどれかであり、流れではない。⚠️ **首が動くのは遷移のときだけである**: 身振りはそこでだけ選ばれる。契約は `schemas/stackchan-command.schema.json` であり、両端がそれを読む。

| 欄 | 値 | 意味 |
|---|---|---|
| `face` | Pet の5つの顔、または `null` | この表情を出す。`null` = 変えない |
| `light` | `off` / `dim` / `breathe` / `warm` / `alert` / `error` | 常に在り、`null` にならない |
| `gesture` | `perk` / `nod` / `turn` / `settle` / `flinch`、または `null` | 首を動かす。`null` = 動かさない |

⛔ **`sound` の欄は無い。** スピーカーはまだ存在しないチャンネルである。

## ベンダーのソースが記録していること

✅ **2026-10-18 から、これらは記録に在る**——`m5stack/StackChan`、ブランチ `firmware-dev`、MIT。手元の個体に入っているファームである。⚠️ **これはベンダーの数であり、コードから読んだものであって、ここで測ったものではない。** このリポジトリはそれを読むが、所有はしない。

| 何 | ベンダーの記録 |
|---|---|
| サーボバス | UART1、1,000,000 baud、TX GPIO 6、RX GPIO 7。Feetech SCSCL |
| スケール | `raw = zero + angle × 16 / 5 / 10`、`angle` は 0.1° ⇒ **1カウントは 0.3125°**。逆は `(raw − zero) × 5 × 10 / 16` |
| yaw（ID 1） | 既定のゼロ 460、範囲 ±1280（0.1°）= **±128.0°**、raw 0–1000 |
| pitch（ID 2） | 既定のゼロ 620、範囲 30–870（0.1°）= **+3.0°〜+87.0°**、raw 0–1000、ストール保護あり |
| ゼロ点 | NVS、名前空間 `servo`、キー `zero_pos_1` / `zero_pos_2`——⚠️ **この個体の実測ゼロ点はここに在る** |
| LED | 12個。PY32 IO エキスパンダ（I²C `0x6F`、SDA GPIO 12、SCL GPIO 11）の先。同じエキスパンダが **サーボ電源** をピン0で切る |

⛔ **いまもどの記録にも無いのは、このディレクトリが発明することを拒んでいる表である: `perk` がどの角度か。** スケールは角度の**送り方**を教える。**どの**角度かを教えはしない。

## このソースが、わざと決めないこと

- **身振りの表** — `perk` がどの角度か: 記録も測定も無いので、行も無い。✅ **度とカウントのスケールはもうこの一覧に無い**——ベンダーのソースが上に持っている;
- **LED の色** — ✅ **順序はエキスパンダの先の RGB565 だと分かった**。欠けているのは色の選択であり、それは測定ではなく選択である;
- **画面の描画器** — ここで顔は意味であり、画素ではない;
- **伝送路** — このファイルは1行を読む。その行がどう盤に届くかは電線のフレーミングの問題であり、手元の個体は LAN のサーバではなく、ベンダーのクラウドのクライアントである。

## 最初の書き込み — 2026-10-18

✅ **復元は書かれ、読み戻され、起動するのを見られた。** 2026-10-18、手元の個体で: 純正のイメージが書かれ、ビット単位で読み戻され、**起動した——自身の USB ログが、ランチャーが開き、すべてのアプリが作られるのを示した**。次に現在のスナップショットが書き戻され、同じように読み戻され、**それも起動した。** `docs/first-contact-stackchan.md` が、ファイルとハッシュと、測った差分と、起動の観測そのものを持っている。

✅ **次に、このディレクトリが作るイメージがビルドされ、書かれた。** `build/stackchan-vessel.bin`、272,976 バイト、`0x510000` に、ハッシュを照合して。アプリは `ready.` に達し、ベンチが頭を回した。⚠️ **同じ日の後のビルドは 273,808 バイトで、`bench timed` を足し、同じ手順で書かれた**——ここのサイズはそのビルドのものであって、定数ではない。⛔ **閉じなかったのは、このページの冒頭の門である:** 枠に入った身振りは今もすべて断られる——角度は1つも測られていないからだ。**あの移動はベンチのコマンドだった——`Motion Intent` も、軌道も、ゲートも無い**（`records/2026-10-18-first-arrival.md`）。

⚠️ **それでもこのディレクトリでは何も鳴らない。** ここに C++ の試験は無く、**このリポジトリの中でそれをビルドするものも無い**——`idf.py build` はその日に手で走らせたもので、繰り返す検査は無い。`tests/test_stackchan_wire.py` がこれらのリテラルを読み、契約と食い違った日に赤くなる——それが唯一の検査であり、**それは写しを検査していて、機体を検査していない。**

## サーボの time フィールドが答えたこと — 2026-10-18

✅ **`bench timed <yaw_deg> <time> [speed]` をベンチに足し、同じ日に焼いた。** これは**1回だけ**目標を書く——time フィールドと speed フィールドを伴って——`bench move` が1秒ごとに目標を書き直すのとは違う——**そのあと200 ms ごとに、最大70秒、yaw の軸を読む。**

⛔ **この機体では、time フィールドは移動時間を決めなかった。決めたのは speed フィールドである。** 2回の試行: `time=5000, speed=0` は5カウント動いて止まり、`time=500, speed=100` は32カウント（10°）を約0.3〜0.4秒で、約127カウント/秒で動いた。**どちらも目標のちょうど6カウント手前で止まった**——見たところ固定のずれであり、バックラッシュとも読み戻しそのものとも、まだ分けていない。

⇒ **エンジンにとっての意味を1行で: この機体では、滑らかさをサーボに任せることはできない。** 段差のない首は、**ホストが補間した目標を書き続ける**ことを要る——`engine/trajectory/` はそのために在り、**そしてそれはこの機体では一度も走っていない。** ⚠️ **数字は `records/2026-10-18-first-arrival.md` にあり、そこでは数字が伴っていた観察が背骨である。**
