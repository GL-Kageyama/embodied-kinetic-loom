# 自分の網を見つけられなかった体 — 2026-10-21

⛔ **この頁は、生きていたのに届かなかった体と、届くまでに要ったものの記録である。** その終わりに、1文が回線を渡り、**著者がそれを聞いた**——この頁で耳はその1つだけであり、それは著者のものである。

**数えたもの。** 機体1台、Mac1台、コンソール1本（`/dev/cu.usbmodem101`）、回線1本（`192.168.0.103:3333` への TCP）。**数えなかったもの:** パケットキャプチャ、起動時の断の理由（コンソールを開いた時にはもう流れていた）、アクセスポイント側のログ、そして⛔ **ケーブルを挿したあと画面が点いたかどうか——誰も見ていないし、そう言ってもいない。**

## 著者が最初に言ったこと

**画面は暗かった**——「くらい」。⛔ **そして、その同じ瞬間に体は生きていた**: コンソールは `alive` を出し続け、`bench pos` は `yaw raw 492, angle 10.0 deg` と `pitch raw 773, angle 47.8 deg` を返し、`servo strikes=0 rail=0` だった。⇒ **暗い画面は、死んだ体ではなかった。** 最初に試した説明——電池切れ——は外れていた。

## 板が自分について言ったこと

```
$ bench wifi
wifi: credentials "BFW6K-G-48420", not associated, no ip

$ bench dial
dial: 192.168.0.103:3333, down — 18 dial(s), 0 connect(s)

$ bench wifi scan
wifi: 1 access point(s)
wifi:   "BFW6K-G-48420_EXT" ch 6 rssi -58 auth 3
```

- ⛔ **板が覚えていた SSID は、板が見えるものの中に無かった。** 電波の届く範囲にアクセスポイントは1つだけあり、それは別の名前だった。
- **dial 18回、接続0回**——dial の任務は回っていて、dial する先が無かった。⚠️ **その再試行は1〜10秒で、止まらない**（`main/dial.cpp`）⇒ **dial が来ないことは、ネットワークについての証拠であって、任務についての証拠ではない。**

## 要ったもの

**コンソールに1行**——`bench wifi join BFW6K-G-48420_EXT …`——それだけで板は associated になり（WPA2-PSK、ch 6、rssi −57）、**`192.168.0.100`** を取り、自分の判定を出した:

```
dial: connected to 192.168.0.103:3333
```

デーモンのログは、同じ瞬間のもう片側を持っている:

```json
{"link": "the board dialled in", "peer": "192.168.0.100:63142"}
```

⛔ **鍵はこの頁に書かない。** SSID は書く。パスフレーズは書かないし、板の `bench wifi` もそれを出さない。

## 最初の1文

口に1文を頼んだ。3.4秒の声である。

| 何 | 値 | どこから |
|---|---|---|
| 道具の返事 | `queued`、終了0、**0.055秒** | `python3 -m projects.stackchan_next.mouth` |
| デーモンの行 | `{"voice": "spoke", "blocks": 41, "bytes": 164294}` | `/tmp/ekl-stackchan-next.log` |
| 板の受領 | **41塊・164,294バイト・`not played` 0** | 板上の `bench dial` |
| 板が鳴らした時間 | **3,330 ms** | `bench dial` |
| 渡ったもの | `link read 164,744` バイト、**頭41** | `bench dial` |

**余分の450バイトは頭である**——41 × 11——これは0.19.69 の実測（36 × 11 = 396）と同じ算術だ。⛔ **`not played: 0` は、受け取った塊を全部鳴らしたという板の言葉である**。音が良かったという言葉ではない。

**そして著者が聞いた**——「聞こえた」。⛔ **それで閉じた問いは1つで、開いたものは無い**: 声が明瞭か、大きさが適切か、役回りに合うか、とは言っていない。**このリポジトリの耳は、数を返せる問いをまだ1つも立てられていない。**

## 源が言うこと、言わないこと

- ⛔ **`main/wifi.cpp` は、切れたアクセスポイントに繋ぎ直さない。** `WIFI_EVENT_STA_DISCONNECTED` の枝は理由を出して戻る。`esp_wifi_connect()` を呼ぶのは `WIFI_EVENT_STA_START` からの1回だけである。⚠️ **これは源の読みであって、この故障の実測ではない**——ただし、「電源は入っていて、生きていて、届かない」という状態に、この体がいつまでも座っていられる形を作っているのはこれだ。
- ⚠️ **dial の行き先は NVS から来ていて、変わらなかった**: 前も後も `192.168.0.103`。**変わったのは板自身のアドレス**で、`192.168.0.19` から `192.168.0.100` になった。デーモンはそれを追えた——**板のほうから dial するからである。2026-10-21 に証明された向きが、この日を救った向きである。**

## 分かっていないこと

- ⛔ **`BFW6K-G-48420` が電波を止めたのか、チャンネルを移ったのか、単に届かなくなったのか。** 板の居る場所からは1つだけ見え、もう1つは無かった。**アクセスポイントの側は読んでいない。**
- ⛔ **起動時の接続がなぜ失敗したか**——理由の番号は、コンソールを開く前に流れていて、取れていない。
- ⛔ **暗い画面が、表示のせいだったのか、バックライトのせいだったのか。** 体は、画面が暗いまま、聞かれたことすべてに答えた。
- ⛔ **`_EXT` が何なのか**——中継機か、別の帯か、別の無線か。ここでは分かっていない。⚠️ **板はもうその名前を NVS に覚えた**ので、次の起動ではそれを求める。
