# 要一个圆的眼睛 — 2026-10-24

⛔ **这一页是关于这具身体的脸的、作者的两句话——判定一个圆的、以及要一道眉的——和一件从未打响的器具的记录。** 0.19.80 给身体装上了三张新脸——`focused`、`watching`、`startled`——而**没有一双眼睛判定过其中任何一张**。**两句话同一天到来，各自产生了一处改动**：处理中的那张脸，眼睛变成了一个朴素的圆；书写的那张脸长出了一道眉。⚠️ **标题保留第一句，只指名它**——记录以造就它的那件事命名，而第二句是在写它的过程中到来的。**眼睛看见的才是脊梁，守护进程的行只是被引在里面的证据。**

**数了什么。** 一台机体、一台 Mac、一个会话、一双眼睛、被问到的两张脸（`focused`、`watching`）。**没数什么：** 某一秒里那双眼睛是否在这台身体前面——**没有日志记录人**；眼睛看到的光的颜色；以及⛔ **某张脸被画在玻璃上的次数**——基板对一个帧只回一行受理，对面板一言不发。

## 器具，以及两次什么也没有改变的发送

⛔ **USB 控制台不在了**——`/dev/cu.usb*` 不存在——所以打不了 `bench face <word> [light]`。⇒ 仓库外的一次性脚本 `/tmp/eye_face.py`，向 `/tmp/ekl-stackchan-next-501.sock` 发一个层事件，并读守护进程的回答。

✅ **章开着的时候，它有效。** 冒烟试验打印 `focused: face=focused light=writing`，守护进程在 `at 3727.0` 写下 `{"face":"focused","gesture":null,"light":"writing","sound":null}`，`sent: true, accepted: true`。

⛔ **作者一次也没有运行它。** 日志里没有它的行——没有一行 `PostToolUseFailure`，也没有一条带着 `write` 或 `run` 的 `PreToolUse` 落在本会话自身工具调用之外。**器具被递了出去，没有被使用**，这一页照实写，而不写一次没有发生的运行。

⛔ **然后器具从这里被驱动，驱动失败了。** 两次发送被排在回合结束之后——`focused` 在 +7 秒，`watching` 在 +32 秒——而守护进程把两次都记成 **`reason: "observed", face: null, light: "breathe"`**，并且**一帧也没有写**。行是 `at 3988.5` 的 `PreToolUse work=write` 与 `at 4013.6` 的 `PreToolUse work=run`，紧跟在 `Stop`（acted、`happy`/`warm`）和一行 `settled`（`curious`/`breathe`）之后。⇒ **一章关闭之后，被人手送来的 `PreToolUse` 什么也不动**——⚠️ **为什么如此，这里没有查明**。而**那句告诉作者“7 秒后是 `focused`”的话，在写下时就是错的**。

## 改变了什么

`main/face_bitmap.cpp`——`kWatching` 从 `{88, 0, 132, 6}` 变成 `{100, 0, 132, 6}`。**眼睛现在是 `curious` 戴着的同一个圆盘**（权重 100，作者 2026-10-20 的数字），而**这张脸说的只有嘴的宽度**。⛔ **88 是“稍微眯起”，而眯起是 `focused` 的活儿**（权重 55）——一张稍微眯起的脸，是一张说着两个词中间话的脸。⚠️ **同一天内订正**：那个括注没撑过一个小时——`focused` 也戴上了圆盘，**这具身体加的三张脸一张也不收窄眼睛**（见「样本与第二个判定」）。⛔ **88 之所以错，不依赖那一条**：处在两个词中间的眼睑，无论谁在用，说的都是两个词中间的话。**一个检查按住它**——`test_the_watching_face_also_wears_the_disc`，在 `tests/test_stackchan_face.py` 里，把眼睛的栏与 `curious` 逐像素比较。

## 同一个会所要来的眉

⛔ **第二句话是要求，不是判定**——它被说出的时候，玻璃上没有任何东西被读作 `focused`，而这一页不会把它升格成裁决。

**这是 `face_bitmap.cpp` 里 vendor 从未画过的唯一一个形状。** vendor 的皮肤是两个圆盘、两片眼皮和一根棒；`StyleFor` 的其他每一行都只是移动 vendor 写下的数。眉必须被造出来（`DrawBrow`）。而**它的四个数是选定的，不是量出来的**：长 24px、粗 3px、外端比内端高 6px、离眼睛上沿 5px——斜率 `atan(6/24) ≈ 14°`，**比作者画的 `＼` 那个字形更缓**，因为字形是按字格能容纳的斜率画的，而眉是按能被读作眉的斜率画的。⚠️ **这一页说不出作者指的是哪一个斜率**——去问它的地方是 `bench face focused`。

**眉不参与眨眼。** 眼皮画在眼睛上，眉画在 `render_blink` 移动的那一个整数之外——所以眨眼时眉仍然立着。⇒ **眨眼会让 `focused` 的眉出现在两只闭上的眼睛上方**，而**那张画也没有被任何眼睛看过。**

**一项检查按住它**——`test_only_the_focused_face_wears_a_brow`：只有一张脸戴眉，两侧的倾斜都是外高内低，两条眉在同一高度。⚠️ **镜像检查不得不加上一行**（76 → 92），而**器具不得不学会一个眉的框**——在那之前，**它把眉当成嘴的一部分来测量**，和那天的缺陷是同一种形状：整整一行亮着的像素落在检查认识的每一个框外面。

## 样本与第二个判定

⚠️ **第二个判定来的时候，玻璃依然不可用。** 作者写了「さした」——线被重新插过——而 Mac 的清单什么也没有变：`/dev/cu.*` 与 `/dev/tty.*` 里只有蓝牙口和 debug console，`ioreg -p IOUSB` 显出三个集线器，下面挂着 LAN 适配器、REALFORCE 键盘和蓝牙适配器——**没有 ESP32，也没有串口芯片**。⛔ **身体一直是活的**：守护进程的 3333 端口与 `192.168.0.100:63327` 保持着 `ESTABLISHED`。板子在跑，自己拨了进来，**跑的是这一天改动之前的镜像**。

**于是会所在主机上把脸画了出来。** 用 `clang++` 把 `face_bitmap.cpp` 和 `command_frame.cpp` 与一个小导出程序一起编译，对八个词各调用一次 `render()`，把每张 320 × 240 的灰度缓冲写成 PNG；打开了一张 4×2 的样本，下面放着 `focused` 眼睛的 3 倍裁切。⛔ **这不是面板的照片**：它是固件调用的同一个绘制函数被打印进文件——转成 RGB565 的部分和面板的粗糙都不在里面，**关于玻璃，它什么也没有量。**

**作者的两句话：**

| 话 | 它做了什么 |
|---|---|
| 「この見え方でOK」 | 眉，照画出来的斜率——长 24px、粗 3px、外端高 6px、间距 5px |
| 「眉毛ある時も丸目がいいな」 | `focused` 的眼睛：权重 55 → **100**，`curious` 与 `watching` 戴着的圆盘 |

⚠️ **第一句话没有指名任何形状。** 它跟在一段以眉的四个数、以及「这形状是否读作*在写*由作者决定」为主题的发言之后，而会所把它读作对所画的眉的认可——⛔ **那个读法并不在句子里**，而这一页把句子和读法分开放。⚠️ **它也不是 2026-10-20 那个判定的重复**——「● が見える」关上的是*看得见一个圆*，而这一句关上的是*这道眉、照这样画，正是想要的*。

**改变了什么：** `main/face_bitmap.cpp`——`kFocused` 从 `{55, 0, 60, 6, true}` 变成 `{100, 0, 60, 6, true}`。**眉留着，嘴没有动**；离开这张脸的是收窄的眼睑。⇒ **这具身体加的三个词，如今一个也不收窄眼睛**，而 0.19.81 写下的那句话——*收窄是 `focused` 的活儿*——从这一刻起为假；⛔ **它被写下时是真的，而写下它的那一页会说出它曾经说什么。**

**一项检查按住它**——`test_the_focused_face_wears_the_disc_under_its_brow`：眼睛与 `curious` 的圆盘逐栏相同，眉的计数仍然大于零，嘴仍然是宽 60。⛔ **第二项检查是被改写而不是被保留的**：`test_the_watching_face_also_wears_the_disc` 保住了自己那一行，而它的 docstring 如今带着它曾经主张的那句话，和推翻它的那一个小时。

## 线，第二次

✅ **作者写了「もう一回さしなおした」，而这一次 Mac 动了**：`/dev/cu.usbmodem1101`、`/dev/tty.usbmodem1101`，以及 `ioreg` 里的 `USB JTAG/serial debug unit@01100000`。⚠️ **第一次重插什么也没有改变，第二次改变了**——⛔ **那是线、是口、还是芯片 USB 的回来方式，这里没有分开**，而**一次没回来，不等于一具回不来的身体。**

**在槽位确定之前，什么也没有写。** `0xd000` 的 `otadata` 读出 **`ota_seq = 1`、`state = 0x2`**，⇒ `ota_0` = **`0x20000`**；`0x20020` 的描述符**在写入之前**被读过，指名 **`7f27191-dirty`、`Oct 24 2026 05:16:43`**——0.19.80 的镜像，身体那一整天跑着的那一个。

| 步骤 | 数 |
|---|---|
| 写入 | **937,712 字节**（压缩后 577,384），写到 `0x20000`，5.2 秒 |
| esptool | **`Hash of data verified.`** |
| 之后的描述符 | **`2a5c49e-dirty`、`Oct 24 2026 06:05:06`** |
| 控制台 | `bench: face focused drawn — the eye says whether it reads as that word` |

⛔ **`--verify` 不是引导检查**——0.19.53 把一张验证过的镜像写进了没有东西会引导的槽位，屏幕没有变——所以描述符要在写入的两侧各读一次。⚠️ **启动横幅没有采到**；正在跑的是哪张镜像，是用描述符确认的，不是基板印出来的某一行。

⛔ **而玻璃还没有回答。** `bench face focused` 把画放上面板；**圆盘和它上面那道眉是否读作「在写」，是作者眼睛的问题，沉默不是受理。**
