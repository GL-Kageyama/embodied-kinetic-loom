# 基板が外へ dial する — 2026-10-21

⛔ **このファイルの背骨は観察である。プログラムの数は、その内側に証拠として引用される。** 受ける側が受け付けた行は、頭を動かした行ではない。

**数えたもの。** 1台、1つの Mac、1つのアクセスポイント、**その間ずっと挿さったままの USB ケーブル1本**、そしてソケット1つ。**数えていないもの:** **USB ケーブルが抜かれていた区間は一つも無い**——**以下の測定はどれも、コンソールが消えた状態では取られていない**——そして2本目の接続、本物の切断、パケットキャプチャも無い。以下の行はすべて、基板が自分で開いたリンクを戻ってきた; その間もケーブルは在った。

## 何を問われたか

「最終的には、usb接続なしで動くようになるよね？」 — 最後には USB ケーブル無しで動くのか。

⚠️ **その問いには「はい」ではなく、形で答えた。** 前の頁は向きを1つだけ開けて残した: Mac は決して先に喋れず、基板が開いた接続は両方向を運んだ。⇒ **だから基板が dial する。** これが、それが初めて起きたビルドである。

## 見えたもの

**基板は、起動時に、自分から dial した——「ready」と言う前に。** 誰も何も打っていない: 住所は NVS にあり、`bench dial` が一度だけ書いたものである。

```
dial: pointed at 192.168.0.103:3333
waypoint: dial
dial: connected to 192.168.0.103:3333
ready. type `help`.
```

**頭の位置は、そのリンクを戻ってきた。** Mac は、自分が待ち受けているソケットへ `bench pos` を書いた:

```
sent b'bench pos\n'
recv bench: yaw=ok pitch=ok
recv bench: yaw raw 478, angle 5.6 deg (zero 460)
recv bench: pitch raw 777, angle 49.0 deg (zero 620)
```

**枠が降りてきて、基板は同じソケットで答えた。** 書いてから `0.159 秒` 後、証拠は基板自身の受理の行——デーモンが 0.19.41 から USB のコンソールで読んでいる行である:

```
sent b'{"face":"curious","gesture":null,"light":"writing","sound":null}\n'
recv frame: light=writing face=curious gesture=none sound=none
```

**pose が降りてきて、頭が動いた。**

```
sent b'pose 100 491*26\n'
recv pose: stream started — goals on the present positions (yaw 478, pitch 777), torque on
recv pose: stream lost after 500 ms — torque released
recv pose: 1 applied, 0 refused, 0 clamped
```

⚠️ **yaw を 10.0° 頼んで、頭は 6 カウント——1.9°——動き、次の `bench pos` は `yaw raw 484`、7.5°、目標に8カウント届かなかった。** ⛔ **その損失は 0.19.36 がこの機体ですでに測ったものである: サーボのものであり、スケジュールのものではない——そして線がケーブルを渡ろうとソケットを渡ろうと、同じ大きさである。** ここに書くのは、**同じもの**が動いたことの確認としてであって、新しい発見としてではない。

**そしてリンクは、「この基板へどう届くか」を変える命令を拒む。** 下の綴りは `HandleBench` が本当に受理する形である——先頭の空白を読み飛ばすので、空白2つは誤記ではなく本物の命令である:

```
sent b'bench  wifi\n'
recv dial: refused — that command is the console's
```

⛔ **その拒否は、機体に届く前に自分の中の穴を見つけた。** この規則は `bench <verb>` に厳密に一致するように書かれ、`bench  wifi`——空白2つ——を素通りさせた。`HandleBench` が読み飛ばすのと同じ空白を、読み飛ばしていなかったからである。`tests/test_stackchan_dial_policy.py` が先に書かれ、その行で落ちた; **直したのはソースであり、行ではない。**

## 言っていないこと

- ⛔ **ケーブルは一度も抜かれていない。** 上の行はどれも、USB を抜いた状態では取られていない。**この頁が測っているのは、体の会話を丸ごと運ぶリンクである; ケーブル無しで体が生き延びることを測ってはいない。** その二つは別の主張であり、ここでしているのは1つ目だけである。
- ⛔ **デーモンはこのリンクを使っていない。** 今も枠ごとに、身振りごとに `/dev/cu.usbmodem101` を開く。上のすべての測定でリンクの向こうに居たのは、そのために書かれた探針——`/tmp/ekl-dial-listen.py`——であり、⚠️ **探針は輸送ではない**。
- ⛔ **0.159 秒はリンクの値段ではない。** その区間で基板は顔を描き、12個の LED を書いている。ソケットと基板自身の仕事を分けたものは、ここには何も無い。
- ⛔ **接続は1本、1回だけ。** 本物の切断後の再接続、Mac の住所が変わったときの挙動、2本同時が安全かどうかは、すべて未測定である。⚠️ **基板は backoff を付けて再試行するが、それが動くところは一度も見ていない。**
- ⚠️ **住所は1つの DHCP リースである。** `192.168.0.103` はその晩に Mac が居た場所である。Mac が動いたときにそれを見つけるものはここに何も無く、⛔ **ケーブルが抜かれていれば、新しい住所を打ち込むコンソールも無い。**
- ⛔ **この機械に対して、二人目の書き手は一度も走らせていない。** コンソールは今も体を持っており、リンクは同じ扉（`RunLine`）を通してそれを求める——ミューテックス1つ、一度に1つ。**それで足りるというのはソースの読みであって、測定ではない。**
