# 找不到自己网络的身体 — 2026-10-21

⛔ **这一页记录的是一具活着却联系不上的身体，以及连上它所需的东西。** 在它的末尾，有一句话穿过了链路，**作者听见了它**——这一页里只有这一只耳朵，而且是作者的。

**数了什么。** 一台机体、一台 Mac、一个控制台（`/dev/cu.usbmodem101`）、一条链路（到 `192.168.0.103:3333` 的 TCP）。**没有数的：** 任何抓包、开机时断开的原因（打开控制台时已经滚过去了）、接入点一侧的日志，以及 ⛔ **插上电缆之后屏幕有没有亮——没有人看，也没有人这样说。**

## 作者最先说的话

**屏幕是暗的**——「くらい」。⛔ **而就在同一时刻，身体是活着的**：控制台一直在打印 `alive`，`bench pos` 回答 `yaw raw 492, angle 10.0 deg` 与 `pitch raw 773, angle 47.8 deg`，`servo strikes=0 rail=0`。⇒ **暗屏不等于死掉的身体**，最初试的那个解释——电池耗尽——是错的。

## 主板如何说明自己

```
$ bench wifi
wifi: credentials "BFW6K-G-48420", not associated, no ip

$ bench dial
dial: 192.168.0.103:3333, down — 18 dial(s), 0 connect(s)

$ bench wifi scan
wifi: 1 access point(s)
wifi:   "BFW6K-G-48420_EXT" ch 6 rssi -58 auth 3
```

- ⛔ **主板记住的 SSID 不在它能看见的列表里。** 信号范围内只有一个接入点，而它是另一个名字。
- **dial 18 次、连接 0 次**——dial 任务还在跑，只是没有可拨的方向。⚠️ **它的重试是 1–10 秒，永不停止**（`main/dial.cpp`）⇒ **没有 dial 是关于网络的证据，不是关于任务的证据。**

## 所需的东西

**控制台上的一行**——`bench wifi join BFW6K-G-48420_EXT …`——主板就关联上了（WPA2-PSK、ch 6、rssi −57），取得了 **`192.168.0.100`**，并打印出自己的判定：

```
dial: connected to 192.168.0.103:3333
```

守护进程的日志带着同一时刻的另一侧：

```json
{"link": "the board dialled in", "peer": "192.168.0.100:63142"}
```

⛔ **这一页不写密钥。** SSID 写，口令不写；主板的 `bench wifi` 也不打印它。

## 第一句话

向嘴要了一句话，3.4 秒的声音。

| 什么 | 值 | 从哪里来 |
|---|---|---|
| 工具的回复 | `queued`、退出 0、**0.055 秒** | `python3 -m projects.stackchan_next.mouth` |
| 守护进程的行 | `{"voice": "spoke", "blocks": 41, "bytes": 164294}` | `/tmp/ekl-stackchan-next.log` |
| 主板的回执 | **41 块、164,294 字节、`not played` 0** | 主板上的 `bench dial` |
| 主板播放了多久 | **3,330 ms** | `bench dial` |
| 穿过了什么 | `link read 164,744` 字节、**41 个头** | `bench dial` |

**多出的 450 字节是头**——41 × 11——与 0.19.69 的实测（36 × 11 = 396）是同一算术。⛔ **`not played: 0` 是主板说它把收到的每一块都播放了**，不是说声音好听。

**而作者听见了**——「聞こえた」。⛔ **那句话关掉了一个问题，没有打开任何东西**：它没有说声音清晰、音量合适、或符合角色。**这个仓库的耳朵，还没有被问过一个它能用数字回答的问题。**

## 源码说了什么，没说什么

- ⛔ **`main/wifi.cpp` 不会重新连上掉线的接入点。** `WIFI_EVENT_STA_DISCONNECTED` 的分支打印原因就返回；`esp_wifi_connect()` 只被调用一次，来自 `WIFI_EVENT_STA_START`。⚠️ **这是对源码的阅读，不是对这次故障的实测**——但让「有电、活着、联系不上」成为一种可以无限停留的状态的，正是这个形状。
- ⚠️ **dial 的目标来自 NVS，没有变过**：前后都是 `192.168.0.103`。**变的是主板自己的地址**，从 `192.168.0.19` 变成 `192.168.0.100`，而守护进程跟得上——**因为拨号的是主板。2026-10-21 被证明的那个方向，正是这天救了它的方向。**

## 尚未确定的事

- ⛔ **`BFW6K-G-48420` 是停止广播了、换了频道，还是仅仅超出了范围。** 主板所在处只看到一个接入点，另一个不在。**接入点那一侧没有读。**
- ⛔ **开机时的关联为什么失败**——原因编号在打开控制台之前就滚过去了，没有抓到。
- ⛔ **暗屏是显示屏的问题还是背光的问题。** 屏幕一直暗着，身体却回答了问它的每一件事。
- ⛔ **`_EXT` 是什么**——中继器、另一个频段、另一个电台：这里没有确定。⚠️ **主板已经把那个名字记进 NVS**，下次开机就会去找它。
