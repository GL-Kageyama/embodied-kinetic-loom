# 声 — 2026-10-18

⛔ **このファイルの背骨は観測である。プログラムの数は、その周りではなく、その中に証拠として引用される。** 基板が印字したものだけを持つログは、この記録が何のためにあるか——1つの語が聞こえたかどうか——に答えられない。そして `done` と印字する基板は、証拠でないものを証拠のように読ませる。

**数えたもの。** 1台の基板、1つの夕方、1対の耳。**数えなかったもの：** デシベルで表した大きさ、スピーカーから実際に出た周波数、2人目の聴き手が4つの語を同じように名付けたかどうか、そして同じ基板のマイクが聞いたはずのもの——ここでは何もそれを読んでいない。

## 聞こえたもの

⚠️ **ワイヤの4番目の欄は、契約が書かれてからずっと黙っていた。** 在るのに一度も鳴らない欄は、チャンネルではない。**日本時間19:00**——**21:00の静かな時間の線より前**、つまりこの時刻は意図して選ばれた——に4つの語を1つずつ鳴らし、基板はそのたびに答え、著者には何が届いたかを尋ねた。

| # | 著者に届いたもの | そのとき基板が言ったこと |
|---|---|---|
| 1 | **4つの語とも聞こえた** | `bench: playing` … `bench: done`、語ごとに1回 |
| 2 | — | 続いて同じ4つの語を枠が運び、基板はその欄を印字した |

⛔ **この答えは引用ではなく、このファイルはそれを引用の形に着飾らない。** 問いは4つの語が聞こえたかであり、答えは4つとも、であった。⚠️ **それで足りる主張は1つだけで、他の何にも足りない：** スピーカーが語ごとに音を出した。**どの語が心地よいか、大きすぎないか、その遷移にふさわしい音かは、何も言っていない**——それは問われておらず、判定されていない。

## ワイヤが運んだもの

コンソールはデーモンが開くのと同じやり方で開いた——`os.open` と素の `termios`、セッション全体で1回だけ開き、`pyserial` は使わない——同じ基板が同じ日に2度、DTR と RTS を立てる読み手に固まらされたからである（records/2026-10-18-the-lights-ja.md）。**このセッションは基板をリセットせず、固まらせもしなかった。**

```
  5.40 bench: playing hello
  5.58 bench: hello done
  8.39 bench: playing pip
  8.41 bench: pip done
 11.61 bench: playing chime
 11.85 bench: chime done
 14.80 bench: playing fall
 15.11 bench: fall done
```

⚠️ **`playing` と `done` の間は、音の長さではないし、そう読んではならない。** `i2s_channel_write` はサンプルが DMA バッファに収まったときに戻るのであって、スピーカーが鳴り終えたときに戻るのではない。`pip` は20 msで閉じ、`fall` は310 msで閉じるが、**そのどれもこの記録が主張できる長さではない。**

続いて、それぞれ1語を運ぶ4つの枠と、2つの拒否：

```
frame: light=warm face=happy gesture=look_up sound=pip
frame: light=dim face=sleepy gesture=none sound=chime
frame: light=dim face=none gesture=none sound=none
frame: refused (missing key)
frame: refused (unknown value)
```

- ⚠️ **`chime` の行は、書かれてから4秒後に印字された。** その前の枠が `look_up` を運び、身振りのモーターが首の動くあいだコンソールを塞ぐからである。**身振りの後ろにいる語は、遅れて届く語である**——ここで測られたことであり、論じられたことではない。
- ⛔ **`sound` の欄を持たない枠は拒否され**（`missing key`）、`"sound":"horn"` の枠も拒否された（`unknown value`）。**欄は必須で、その語は閉じている**——Python のデコーダが主張するのと同じ規則を、反対側の端が喋った。
- ✅ **`"sound":null` は受け入れられ、何も鳴らさなかった。** `null` は*この枠は黙る*という意味であり、*最後のものを保て*という意味ではない。

## アンプ——ベンダーの数のまま

⛔ **以下のレジスタ値は、1つもこの個体で発見されていない。** それらはドライバのものであり（ベンダーのスタックが持つ esp_codec_dev の AW88298 の表）、この日に読まれ、このリポジトリが変えた数だけが名指しされる：

| レジスタ | 値 | 何をするか |
|---|---|---|
| `0x00` | `0x55AA` | ソフトウェアリセット、その後50 ms |
| `0x04` | `0x4040` | I2S 有効、アンプをパワーダウンから起こす |
| `0x05` | `0x0008` | SYSCTRL2、ベンダーの初期値 |
| `0x06` | `0x3CC5` | Philips I2S、16ビットフレーム、**レートコード5＝24,000 Hz** |
| `0x0C` | `0x3064` | 音量**−18 dB**——`0x30` がその欄、`0x64` はベンダーがそう置く別の欄 |
| `0x61` | `0x0673` | ベンダーの初期値、用途は読んでいない |

⚠️ **初期化表自身の `0x06` は `0x3CC8` であり、その下位ニブルは48,000 Hzのレートコードである。** **この基板は24,000で駆動され、コードは手で `0x5` に置き換えられた**——レートコードとサンプルレートが食い違うのは、黙って音程の狂ったチャンネルであり、この基板の何もそれを報告しなかっただろう。

⚠️ **リセット線はアンプのレジスタではない。** それは AW9523 の P0.2——ディスプレイがすでに所有するエキスパンダ——であり、だから `display::pulse_amplifier_reset()` がそのパルスを持ち、`sound` がそこへ呼び戻す。**1本のバス、1人の持ち主。**

## 4つの語

⛔ **これらは選択であり、測定ではない**——12個の LED の色と同じ立場である。この表のどの音も測られず、基準と照合されず、別のものと比べて判定されていない。**残ったものは、耳が受け入れたものである。**

| 語 | 音 | 形 |
|---|---|---|
| `hello` | 659 Hz 90 ms → 880 Hz 150 ms | 上がる |
| `pip` | 1319 Hz 70 ms | 短い1点 |
| `chime` | 880 Hz 90 ms → 1319 Hz 200 ms | 上がり、長く響く |
| `fall` | 659 Hz 110 ms → 440 Hz 260 ms | 下がる |

⚠️ **どの遷移がどの語を運ぶかはホストの規則であり、この基板のものではない：** `SessionStart` に `hello`、`PermissionRequest` に `pip`、`Stop` に `chime`、`StopFailure` に `fall`、そして `UserPromptSubmit` と `SessionEnd` は黙る。⛔ **基板は4つの語を知っていて、いつが正しいかは何も知らない**——枠が名指したものを鳴らす。

⚠️ **音は、デーモンのスイッチが入れるまで切れている**（`--sound on|off`、既定は off）——著者の決定であり、これを入れたことで機体が頼まれずに喋り出さないようにするためである。

## この記録が確かめないこと

- **音が良いことは確かめない。** 4つの語は聞こえた。**1つも別のものと比べて判定されていない**し、この工房に基準音は無い。
- **スピーカーから出た周波数や大きさは確かめない。** 何も測っていない。耳が言ったのは*音*であって、*880 Hz* ではない。
- **エンジンが走ったことは確かめない。** `Motion Intent` は読まれず、軌道は計算されていない。**スピーカーは語に答える。動きを計算しない。**
- **ペットがそこにいることは確かめない。** ⛔ **それはゴールであり、この工房では検証できない。** 事象に従う語は仕組みであって、存在ではない。
