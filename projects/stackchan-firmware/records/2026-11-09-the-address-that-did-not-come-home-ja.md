# 家に帰らなかった住所 — 2026-11-09

✅ **著者は体を家へ連れて帰り、繋がっているかと訊いた。** ⛔ **繋がっていなかった——そして網が理由ではなかった。** 体は自宅の網に入り、その上の住所を持っていた。そして**dial の向き先は、まだ会場のままだった**: `dial: pointed at 10.5.0.114:3333`、**3 dial(s), 0 connect(s)**、**56 address(es) swept, 0 found by the sweep**、**58 connect attempt(s) failed**。✅ **向き先を手で Mac に向け直すと、次の起動は住所を得てから2秒以内に繋がった**——そしてガラスに顔が出た: 「顔の表示が出た」。

**何を数えたか。** 1台の体、1台の Mac、3回開いたシリアルコンソール、そして3回の起動。以下の数はボード自身の行（`bench wifi`、`bench dial`、`bench net call`、`bench pos`）と Mac の行（`lsof`、`arp`、`ping`、`nc`、`ifconfig`、`socketfilterfw`）から来ており、どの数もどちらかを名指ししている。**数えなかったこと:** 体がいつ電源に入ったか——⛔ **家に着いたあとの起動を見た者はいない**し、最初のコンソールの行はこのセッションが起こした起動である; **Mac がどの SSID に居たか**——`system_profiler` は名前を伏せ、`networksetup` は*associated ではない*と答えたので、**同じサブネットに居ることだけ**が確かである; **ICMP が返らない原因が Mac の側にあるか**——パケットは1つも採っていない。

## 体が持っていたもの、そして向いていた先

✅ **網は正しかった。** 無線は `BFW6K-G-48420_EXT`、チャンネル1、bssid `dc:62:79:d0:ad:2e`、rssi **−45** で立ち上がり、station は **`192.168.0.100`** を得た。`bench wifi` は4件のうち2件を名指しし、`*` は自宅の行にあった:

```
wifi: credentials "BFW6K-G-48420_EXT", associated, 192.168.0.100
wifi: list 2 of 4 — `*` is the row the radio is on
wifi:   * "BFW6K-G-48420_EXT"
wifi:     "Cokoga-5F"
wifi:   ch 1 rssi -44
wifi:   sys_evt stack, 1600 bytes never used
```

⛔ **dial は正しくなかった。** 向き先は、2日前に会場の Mac が持っていた住所のまま——`bench dial` が NVS に書き、**それ以来あらゆる再起動をまたいで残っていた**:

```
dial: pointed at 10.5.0.114:3333
dial: 10.5.0.114:3333 gave nothing in 3002 ms (errno -1)
dial: 10.5.0.114:3333, down — 3 dial(s), 0 connect(s)
dial: 56 address(es) swept, 0 found by the sweep
dial: 58 connect attempt(s) failed (last -1), 0 opened without a greeting
```

⇒ **Mac から見ると同じに見えて、同じでない2つの事実**: Mac に届かない体と、どこか別の場所に届いている体。⛔ **デーモンのログはその2つを区別できない**——300秒で `{"link": "nobody dialled in", "for": 300.1}` と書いたが、それは真実で、原因を名指ししない。**その2つを分けるのはコンソールであり、そこに印字される住所が区別そのものである。**

## コンソールが言ったこと

✅ **向け直しは1行で、しかも再起動をまたぐと言う**:

```
bench: dial -> 192.168.0.106:3333, kept across a reboot
```

⛔ **そして同じ起動では繋がらなかった。** 20秒後:

```
dial: 192.168.0.106:3333, down — 3 dial(s), 0 connect(s)
dial: 84 address(es) swept, 0 found by the sweep
dial: 86 connect attempt(s) failed (last -1), 0 opened without a greeting
```

⚠️ **理由は分けていない。** 掃き出しが前の住所の `/24` を抱えたままだった可能性がある——**それはソースの読みであって測定ではない**——し、カウンタは RAM なので起動ごとに0から始まり、**2つの報告は同じ算術ではない**。

✅ **次の起動は繋がった。そして順序がこの頁の発見である**:

```
dial: pointed at 192.168.0.106:3333
dial: 192.168.0.106:3333 gave nothing in 0 ms (errno 118)
dial: no route yet — 192.168.0.106:3333 is not being looked for
wifi: connected ip=192.168.0.100
dial: connected to 192.168.0.106:3333
```

⚠️ **最初の3行は、まだ経路が無いとボードが言っている行である**——`errno 118` が **0 ms**、そのあと経路なしで掃かないという断り。✅ **住所は `I (2079)` で到着し、connect は `I (3996)` より前に印字された** ⇒ **住所を得てから2秒以内、起動から4秒未満。**

## Mac が見たこと

✅ **TCP が1本、保持されている**:

```
TCP 192.168.0.106:3333->192.168.0.100:51251 (ESTABLISHED)
```

✅ **そしてデーモン側には4行、接続ごとに1行**——接続が取られるか切られるたび、ボードはまた dial する:

```
{"link": "the board dialled in", "peer": "192.168.0.100:50763"}
{"link": "the board dialled in", "peer": "192.168.0.100:51249"}
{"link": "the board dialled in", "peer": "192.168.0.100:51250"}
{"link": "the board dialled in", "peer": "192.168.0.100:51251"}
```

✅ **そのあと枠が来て、受領はボード自身の行から読んだ**:

```
{"frame": "{\"face\":\"focused\",\"gesture\":null,\"light\":\"writing\",\"sound\":null}", "sent": true, "accepted": true, "err": null, "at": 662.790517791}
{"frame": "{\"face\":\"watching\",\"gesture\":null,\"light\":\"busy\",\"sound\":null}", "sent": true, "accepted": true, "err": null, "at": 700.936800416}
```

⚠️ **デーモンは、手で打った探りとボードを区別できない。** このセッション自身の `nc -z 192.168.0.106 3333`——Mac が自分自身に繋いだ——がこう書かせた:

```
{"link": "the board dialled in", "peer": "192.168.0.106:49501"}
{"link": "the board let go", "peer": "192.168.0.106:49501"}
```

⛔ **手掛かりは peer の住所だけで、この行の peer は Mac 自身である。** ⇒ **港が開いているかを見るために港を開く検査は、体が来たと言う行を書く。**

⛔ **`ping` は返らない。そしてこの記録は、理由を知っているふりをしない**: `sendto: No route to host` が3回、100% 損失——一方で `arp -n 192.168.0.100` は `80:45:6b:54:6d:b0 on en0` を保持し、上の TCP は ESTABLISHED である。⚠️ **原因は分けていない**: ICMP がこのアクセスポイントを渡らないのかもしれず、隣接の項目が古いのかもしれない。⛔ **確かなのはこれだけである: この網で、`ping` はこの機械の探りにならない。** Mac のファイアウォールは**切れていた**（`State = 0`）し、`192.168.0.106:3333` への自己接続は成功した。

## 目が見たこと

✅ **著者の観察がこの頁の背骨であり、それは1文である**: 「顔の表示が出た」——**顔が出た**、上の枠が受け取られたあとに。⛔ **それが言うのはガラスに絵があることであり、どの顔かではない。** 語は判定されず、色は名指しされず、光はパネルと比べられていない。

⚠️ **その前の2つの観察は、同じことではない**: 「LEDはついている。」——体は起きて灯っていた、⛔ **それは繋がっていたという意味ではない**——そして「USB繋ぐ？」→「繋いだ」。

⚠️ **コンソールを開くとボードはリセットされる。** 3回開いて、3回の起動バナー。⇒ **コンソールはただの覗き窓ではない**——この頁のすべての行はこのセッションが起こした起動のものであり、⛔ **家に着いてから最初に開くまでの体の状態は観測されていない。**

## この記録が言わないこと

- ⛔ **コンソールを開く前に体が繋がっていた、ということ。** ここにある限りでは繋がっていなかった——だがコンソールの最初の仕事はリセットであり、**到着したときの状態はもう無い**。
- ⛔ **向け直した同じ起動では繋がらず、次の起動で繋がった理由。** ソースは読みを差し出すが、測ったものは無い。
- ⛔ **`ping` がこの網でこの機械について何かを言う、ということ。** 言わない。そして原因は名指しされていない。
- ⛔ **パネルの絵が判定された、ということ。** 顔が出た。どれかはここに書かれていない。
- ⛔ **体がどこでも Mac を見つけられる、ということ。** 掃き出しが覆うのは**名指しされた住所の `/24`** である——だから自宅のようにリースが `192.168.0.0/24` の中で動く場所では、挨拶がホストを見つけられる。**別のサブネットの網では見つけられない**: 2026-11-08 のような移動にはコンソールでの `bench dial` が要り、⛔ **`bench dial` はリンクの上では断られる。**
- ⛔ **何かが直った、ということ。** コードは動かず、テストも動いていない。**4件の表は自宅で働いた**——1行目で associated になった——そして**この体の自宅での1日がどんなものかは、まだ書かれていない。**
