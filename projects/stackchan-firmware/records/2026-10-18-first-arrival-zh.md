# 最初的到达 — 2026-10-18

⛔ **这份记录的脊梁是观察。程序的数字被引在它内侧作为证据**——而不是围在外侧。**一份只能装下程序所印之物的记录，装不进这份记录的目的本身**——究竟有没有东西动过——**而且它会读起来像证据，实际却不是。**

**数过的东西。** 一条命令，一次，一台机器，一天。**没有数的东西：** 那个结果是否活着；以及关于这套引擎轨迹的任何事——这里一条都没有跑过。

## 看见的东西

**作者在看这台机器。** 用作者的话说：头本来朝右，然后**转成了朝向正面**。它不是滑过去的。动一点，停一下，再动一点，再停一下——听得见小小的「ジジジ」在重复，**而那些停顿，是看得见的停顿。**

⚠️ **没有任何仪器记录下这件事。** 那是一双看着桌面的眼睛，**而这份文件里唯一能说机器动过的，就是那双眼睛。**

## 打进去的东西

一行，打进应用的控制台，走的是把固件送进来的同一根 USB 线：

```
bench move 5
```

⛔ **这是台架命令，不是引擎。** 它不读 `Motion Intent`，不做插值、缓动、平滑、限幅。**它每秒写一个新的目标位置，让舵机一步一步走过去**——设计如此，因为这次最初到达要弄清的是「有没有东西到达」，而不是「动得好不好」。

## 程序说了什么

```
bench: yaw=ok pitch=ok
bench: yaw raw 604, angle 45.0 deg (zero 460)
bench: pitch raw 894, angle 85.6 deg (zero 620)
bench: yaw 604 -> 476 (raw), one step per second
bench: yaw -> raw 601
bench: yaw -> raw 598
bench: yaw -> raw 595
   … one line per second, three counts each …
bench: yaw -> raw 478
```

**数字说的：** yaw 舵机（ID 1）在动之前被**读过**，是 604——那次读就是台架印出来的。目标是原始值 476。**每秒一行是写下去的命令，不是回读**——最后写下的是 478，离目标还差两个计数。**动过之后只回读过一次**，来自下一次启动，yaw 484。**刻度是厂商的**——一个计数是 0.3125°——所以头被要求走 128 个计数（40°），**而在离起点 120 个计数的地方被找到。**

**数字说不出的：** 头有没有动。⛔ **被告知了一个新位置的舵机不是证人；证人只有事后那一次回读，而它说轴停在了别处。** 那个 484 是测量。**头转过去了，是作者的眼睛。** 两者相差六个计数以内（约 1.9°）——**那是扭矩松开之后，一颗无力的头的下垂，而它本身没有被测过。**

⚠️ **这次移动是被中断的，不是走完的。** 目标的最后两个计数从未写下：**回读打开了串口，芯片重启，启动在轴当时所在的位置松开了扭矩。** **我打开的控制台窗口比这次移动还短**——43 秒的命令，只有 40 秒。**这是我的错。** 写在这里，是因为后来的人会看见 478 和 476 而疑惑。

## 为什么走走停停

⚠️ **那些停顿是命令，不是故障。** `bench move` 先算出目标，然后**每秒把目标往近处改写几个计数**（`kStepIntervalMs` 1000、`kStepCounts` 3）。写完的一瞬间舵机是静止的——**所以机器每一秒里的大半时间并没有在动。** **测到的只有控制台每秒那一行；平滑度一点也没有测。**

⇒ **看得见的那个结果，正是这个仓库为了消除它而存在的。** 轨迹族、缓动、平滑，把一串停顿变成一条路径。**2026-10-18，它们一个也没有在这台机器上跑过。** 跑的是台架。

## 在此之前挡住的、两个缺陷

⚠️ **在这一天之前，什么也没有动过，而两个理由都不在硬件上。**

| 错在哪里 | 看起来像什么 | 实际是什么 |
|---|---|---|
| ping 的校验和加了**四个**字节，应当三个 | `ping yaw=0/3 pitch=0/3`，可同一个 id 的 `read` 却有回答 | ping 不带参数，校验和覆盖 ID + LEN + INST 就结束；第四个字节是还没写下的校验和本身 |
| 两个字节的字段**低位在前**地写、也这样读 | 604 以 `0x02, 0x5C` 到达，被解析成 **23554** | 厂商的 SCSCL 驱动以 `End = 1` 构造，它的 `Host2SCS`／`SCS2Host` 把**高位放在前面** |

⛔ **第二条不只是读错了。** 写目标时用的也是同一个顺序：**下令 604 会以 23554 到达舵机**——一个它到不了的值，而且是一个**会让它朝那里追过去**的值。**在写下任何一个目标之前就修好了。** 第一步之所以发生在这一天，原因全在这里。

## 之后发生了什么

⚠️ **在回读的过程中应用重启了，控制台没来得及收住整段移动。** 原因没有确定，而两个候选并不是同样可能：

- **回读打开了串口**，在这颗芯片上，主机的控制线可能敲到复位脚——**这是通常的解释，而且它发生在读的时候，不是动的时候。**
- **供电跌落**，因为两个舵机在电池上压着扭矩将近四十秒——⚠️ **若是这一条，它应当发生在移动中途，而控制台显示移动一直继续到最后写下的那一步。这一条更不合。**

⛔ **这份文件不在两者之间选。** 重新打开控制台的时候，运动已经发生过了。**重启不能撤回这个观察，也不能解释它。**

## 同一天的第二个命令

**作者看着这台机器。** 用作者的话说：「ジジっと、2回少し動いた」——*它轻轻地动了，两次，带着咭咭的声音。*

打了一行：

```
bench move 0
```

⛔ **这个命令的程序输出不在本文件里。** 捕获只留下了一条流的最后三十行，而那条流每三秒被心跳填一次——**活下来的是三十行 `alive`，别的什么都没有。** **本文件不重构它们。** 它有的，是事后取到的一个数，和一双眼睛。

**那个数**由 `bench pos` 经过下一次启动读出：yaw 原始值 **468**，距零点 460 为 2.5°；pitch 原始值 **894**，85.6°，没有变化。

| | 第一个命令 | 第二个命令 |
|---|---|---|
| 打的是 | `bench move 5` | `bench move 0` |
| 它之前最后的记录 | 604（45.0°） | 484（7.5°）——上一次的回读 |
| 它之后的回读 | 484（7.5°） | 468（2.5°） |
| 作者看到的 | 头转过来，朝向正面 | 头轻轻地动了两次 |

⚠️ **468 说了什么，没说什么。** 目标是零点本身，460，而 `MoveAxis` 每秒三个计数地走到它，分毫不差——**所以最后写下的目标是 460。而轴是在离它八个计数的地方被找到的**——2.5°，与第一次回读所见的六个计数下垂同一量级，**而这一次，没有人中断这段移动。** ⚠️ **这个命令究竟走了多少计数，并不知道**：两个命令之间头是松的，没有取过读，**所以 484 是最后「被记录」的值，不一定是这个命令的出发点。** 轴在比 484 更靠近零点的位置结束，这是测量；**头动了，仍然只是作者的眼睛。**

⚠️ **丢失的行是台架工具的过失，不是固件的。** 那个工具在两秒的沉默后结束读取，而这个固件每三秒印一次 `alive`——**于是沉默从未到来，它从不提前停止，一直握到自己的期限。** **那个工具在本仓库之外，没有任何检查覆盖它。**

## 这份记录没有确立的事

- **没有确立引擎能工作。** 没有读 `Motion Intent`，没有计算轨迹，没有通过闸门。**引擎至今没有在任何机器上跑过。**
- **没有确立这台机器是安全的。** 一次缓慢的 yaw 40°，扭矩开启之前把两个目标都设成当前位置，最后松开扭矩——**那是一次移动，不是对失效模式的检验。**
- **没有确立宠物在那里。** ⛔ **那是目标，而这个工作坊无法验证它。** 到达的是一个值，不是一个存在。
- **没有为任何手势命名角度。** `command_frame.cpp` 里的拒绝没有变：`perk` 仍然不是一个数。
