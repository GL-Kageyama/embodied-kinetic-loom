# 渡る行 — 2026-10-21

⛔ **この頁は、読取りの記録であり、動きの記録ではない。** 誰も首を見ていないし、この間ずっと首は動いていない（`look_up` は2回とも `skipped: "no motion"` を返した）。見たのは**1つの沈黙を、2つの側から**である——基板のコンソールと、ホストのログ——そして2つは一致している。

**数えたもの。** 機体1台、Mac 1台、ソケット1本。**下の行のうち2つは、USB ケーブルが1本も無い状態で取った**: `/dev/cu.usb*` は存在せず、`ls` がそう言った。**数えなかったもの:** 目が見たもの、パケットキャプチャ、Wi-Fi の切断やアクセスポイントの再起動。そして⛔ **2つの沈黙は、機械が起こした故障ではない——私が `bench power off` と打ち、手を離した。**

## 何を尋ねられたか

0.19.61 の記録は、借金でもある一文で終わっていた:

> ⛔ **基板の独白はリンクを渡らない。** 渡るのは `Say()` を通る行だけである。`servo: silent for 3 checks…` は `printf` であり、**ケーブルの外では、もう誰も読まない。** ⇒ **このホストは、サーボのバスが黙ったことを、もう知ることができない**——それは 0.19.34 が答えとして建てられた故障である。

⛔ **そしてその借金は、リンクを唯一の経路にした同じ版が作った**——**縁の隙間ではなく、機械が自分の線を失った瞬間に感覚を1つ失ったということである。** 0.19.62 はそれを1行で払う: **基板は監視犬の2つの数を、問いへの答えに載せる。** 0.19.61 を生き延びた規則がそれだからである——*問いに答える行は渡り、体が自ら語る行は渡らない。*

## 何が見えたか

**基板が、コンソールの上で、仕事をしている:**

```
bench: servo power OFF — the expander took the write; the head is limp
servo: no answer (1 of 3 before the rail is cycled)
servo: no answer (2 of 3 before the rail is cycled)
servo: silent for 3 checks — cycling the rail (1 since this boot)
servo: rail cycled — ping yaw=0/3 pitch=3/3
servo: present yaw=491 pitch=779; goals set; torque off
```

⛔ **この6行はどれも `printf` であり、0.19.61 では1行もホストへ届かなかった。**

**同じ午後を、ホストが読んだとおりに——探針の10行、順に:**

```
{"strikes": 0, "rail": 0}
{"strikes": 0, "rail": 0}
{"strikes": 0, "rail": 0}
{"strikes": 0, "rail": 0}
{"strikes": 0, "rail": 1}
{"strikes": 0, "rail": 1}
{"strikes": 2, "rail": 1}
{"strikes": 0, "rail": 2}
{"strikes": 0, "rail": 2}
{"strikes": 0, "rail": 2}
```

⚠️ **7行目が肝である。** その行の全体は:

```
{"position": null, "heard": true, "servo": {"strikes": 2, "rail": 1},
 "read": "bench: servo strikes=2 rail=1\nbench: yaw=no answer pitch=no answer\n", "at": 11671.812024583}
```

**コンソールは答え、サーボは答えず、基板はどちらなのかを言った**——2回続けて答えず、レールは既に1回落ちている。**2026-10-19 の故障が、誰にも読めない一文ではなく、数としてホストに届いている。** ⚠️ **`strikes` は予告であり、`rail` は出来事である**——そしてこの行は両方を同時に示す: **沈黙はまだ続いており、回復は既に1度起きている。**

**最後の行は、ケーブルを抜いた状態で取った:**

```
{"position": [96, 496], "heard": true, "servo": {"strikes": 0, "rail": 2},
 "read": "bench: servo strikes=0 rail=2\nbench: yaw=ok pitch=ok\nbench: yaw raw 491, angle 9.6 deg (zero 460)\nbench: pitch raw 779, angle 49.6 deg (zero 620)\n", "at": 11738.901884791}
```

⛔ **その行が書かれたとき、`/dev/cu.usb*` は存在しなかった。** 監視犬が `printf` で印字していた数——0.19.61 が奪ったもの——が、いま `Say()` に載って届く。そして**姿勢の行より先に届く**、なぜならホストは姿勢が読めた瞬間に窓を閉じるからである。⚠️ **その順序は前提ではなく、検査されている**: 試験は `main.cpp` から2つの literal を読み、その位置を比べる。

**一日の計器は、教えられずにそれを数える。** 同じログの上で: `servo reports 10`、`seen silent 1`、`rail cycles 2`、`rail resets 0`。⚠️ **`rail cycles` は、あのファイルで唯一、数え上げでない数である**——`rail` は基板の*起動から*の回数なので、回数とは**増えた分**であり、減るのは基板の再起動で、その前の回数は観測できない（`rail resets`）。⛔ **その例外は源に書かれ、行を逆順に渡して「どの欄が動くか」を見せる試験に支えられている。**

**最初の `bench power off` は届かなかった。** 行を書いてすぐポートを閉じた; 次の探針はサーボが答えていることと `strikes: 0` を示した——**書き込みは返り、行は届いていなかった。** 2度目はポートを2秒開いたままにし、基板は従った。⛔ **返った書き込みは、届いた行ではない**——このリポジトリが `sent: true` について既に書いたのと同じ文が、1層下にある。

## 直さなかったもの、途中で見つけたもの

**再起動したデーモンは、体を孤児にする。** `launchctl kickstart -k` のあと、新しいソケットは待ち受けていたが、基板は戻らなかった: 古い接続は**1分以上 `FIN_WAIT_1` のまま ACK が無く**、`ping -c 2 192.168.0.19` は **2送信・0受信**を返し、`arp -an` は基板の MAC を保持していた。⇒ **0.19.59 の向きは変わっていない**——Mac から先には話せない——そして基板は、二度と話さないソケットの `select()` に座っており、`DialTask` に読み取りの期限は無い。

⛔ **戻したのはリセットだけだった**——`esptool` の hard reset で、ケーブルを挿したまま。**ケーブルが無ければ、その回復は存在しない**——体は手で電源を入れ直すしかない。

⚠️ **主張しないこと: これが必ず起きるとは言っていない。** 2026-10-21 の待ち受けの入れ替え4回は、0.3〜4秒で自分から戻った。**これはその故障の1回の観察であり、頻度ではない。**

## 何を言っていないか

- ⛔ **首は1つも動いていない。** この頁は読取りであり、引いている姿勢は前も後も同じである。
- ⛔ **2つの沈黙は、こちらが起こした。** コンソールから打った `bench power off` は命令であり、それへの監視犬の答えは**機械が働いたこと**である——**故障が自然に起きたことではない。** 2026-10-19 の自発的な沈黙（22.8分、何も尋ねていない）は、まだ説明されていない。
- ⛔ **数の勘定は起動ごとである。** 基板が再起動すれば `rail` は 0 に戻り、その前の回数をホストは見られない。
- ⚠️ **`strikes` は 0 と 2 で読まれ、1 では読まれていない**——そして、自ら訪れた沈黙のあいだに読まれたことは一度もない。
- ⚠️ **リンクはまだ認証されていない**、そして `bench power off` がそれを渡った。**3333番に届くものは、いま首をダルにできる**——姿勢と枠については既にそうだった; この頁が足すのは、**bench も届く**ということだけである。
- ⚠️ **画面も、光も、首も、この間ずっと目の前には無かった。**
