# 身振り — 2026-10-18

⛔ **観察がこのファイルの背骨である。プログラムの数は、その周りではなく、その内側に証拠として引用される。** 目の無い角度の表は、測定の衣を着た推測である。

**数えたもの。** 5つの身振り、1台、1対の目、1日。**数えていないもの:** これが*最良の*角度かどうか、第二の人が同じ姿勢を同じ語で呼ぶかどうか、そしてその背後に何かが在るかどうか。

## 見たもの

**5つの姿勢をベンチ命令で置き、1つずつ尋ねた。** 著者は首を見ていて、置くたびに答えた。⚠️ **これを記録した計器は無い。机の上の目であり、このファイルで「その姿勢がその語の意味である」と言える唯一のものである。**

| # | 置いたもの | 著者の言葉 | 残ったもの |
|---|---|---|---|
| 1 | `bench set 8 50 80` | 「これで perk」 | yaw **+8.0°**、pitch **50.0°** |
| 2 | `bench set 20 50 80` | 「もっと大きく」 | `turn` には足りない |
| 3 | `bench set 35 50 80` | 「これで turn」 | yaw **+35.0°**、pitch **50.0°** |
| 4 | `bench set 0 30 80` | 「もっと下げる」 | `settle` には足りない |
| 5 | `bench set 0 10 80` | 「もっと下げる」 | まだ足りない |
| 6 | `bench set 0 3 80` | 「これで settle」 | yaw **0.0°**、pitch **3.0°** |
| 7 | `bench set 8 10 80` | 「もっと深く」 | `nod` には深さが足りない |
| 8 | `bench set 8 3 80` | 「これで nod」 | 下ろし先: yaw **+8.0°**、pitch **3.0°** |
| 9 | `bench set -8 70 80` | 「これで flinch」 | yaw **−8.0°**、pitch **70.0°** |

⛔ **5つのうち2つは、著者の選択ではなく機体の限界である。** `settle` と `nod` の下ろし先はどちらも **pitch 3.0°**、ベンダーの下限（`kPitchAngleMinTenths`）に座っている。著者は `settle` について「もっと下げる」と2度言い、3度目の配置が首の行ける最も低いところで、そこで受け入れられた。**もっと下げたい語は、この機体では下げられない**——それはこの機体が覆えない差であり、均して消さずにここに書く。

⚠️ **ベンチの封筒は測定の途中で動いた。** 最初の2つの姿勢を置いたときは ±20.0° で、`turn` はそもそも見せられなかった: `bench set 20` がクランプそのものである。配置3の**前に** ±45.0° へ上げた——それでもベンチの境界であり、ベンダーの ±128.0° の3分の1であり、身振りの限界ではない。動いた理由は数と並べて `main/board.h` に在る。

## 各姿勢をどう置いたか

`bench set <yaw> <pitch> [speed]` はこの測定のために同じ日に足したベンチ命令である。両方の位置を読み、現在位置の上に両方のゴールを書き、トルクを入れ、測定が使ったのと同じ速さで各軸に1つずつゴールを書き、**トルクを入れたまま**首が止まるまで問い続ける。⛔ **軌道ではない**: 動かすのはサーボ自身の速さの欄であり、上流では何も補間しない。

⚠️ **命令の名前は `set` であって `pose` ではない。** 振り分けは `pos` を先に試し、その比較は3文字幅なので、`pos` で始まる語はすべて `bench pos` として読まれる。その衝突は振り分けの場所に、ソースの中に書いてある。

## 数

⚠️ **送った角度と、サーボが落ち着いた位置は同じ数ではない。** 両方をここに置く。

| 身振り | yaw (0.1°) | pitch (0.1°) | 書いた raw | 保持した raw（ベンチ） | 保持した raw（枠から） |
|---|---|---|---|---|---|
| `look_up` | `+80` | `+500` | 485 / 780 | 491 / 778 | 477 / 781 |
| `look_side` | `+350` | `+500` | 572 / 780 | 566 / 778 | 564 / 781 |
| `rest` | `0` | `+30` | 460 / 629 | 466 / 630 | 467 / 629 |
| `nod`（下ろし先） | `+80` | `+30` | 485 / 629 | 478 / 630 | 別には読んでいない |
| `recoil` | `−80` | `+700` | 435 / 844 | 442 / 842 | 442 / 842 |

⚠️ **ゼロはこの個体のもので、NVS から来る: yaw 460、pitch 620。** 変換はベンダーのものである: `raw = zero + tenths × 16 / 50`、切り捨て。

**ずれは実在し、一定ではない。** `look_up` は書いた yaw より **6カウント上**に落ち着き、`look_side` は **8下**、`recoil` は **7上**、pitch 軸は配置を通して両方向に2〜5カウントずれた。⛔ **補正は入れていない。** 固定のずれは、バックラッシュとも読み戻しともサーボ自身の整定とも切り分けていない——だから何も仮定しない。

## 枠が語を動かす

✅ **表をファームに書いた後、5つの身振りを電線から演じた。** 一度に1枠ずつ、JSONの行を基板のコンソールへ書いて。どれも首を測定した姿勢へ動かし、基板はどこで終わったかを印字した。⛔ **これはまだエンジンではない**: `Motion Intent` を読んだものは無く、補間したものは無く、デーモンはこれらの行を送っていない——セッションが手で送った。

`nod` だけは単一の姿勢ではない。**下ろし先と、戻る先**として測られ、戻る先は測ったときの姿勢——`look_up` のものである。⇒ **`nod` は pitch 3.0° まで下ろし、pitch 50.0° へ戻る。**

## 名前と、硬さ

⛔ **著者は、プロトコルが0.19.0から運んでいた5語を退けた**: 「そもそも、英語の動作名前が、わかりづらい」。候補は `perk`・`nod`・`turn`・`settle`・`flinch` で、セッションで選ばれ、どこからも借りておらず、とりわけ `perk` は*顔を上げる*とは読めなかった。**著者は読める英語を選び、語はこうなった:**

| 古い語 | 新しい語 | 何を言うか |
|---|---|---|
| `perk` | `look_up` | 顔が上がる |
| `turn` | `look_side` | 顔が横へ向く |
| `nod` | `nod` | 変わらない |
| `settle` | `rest` | 顔が下がり、そこに居る |
| `flinch` | `recoil` | 顔が引いて上を向く |

⚠️ **角度は名前と一緒には動かなかった。** 改名はスキーマ、コーデック、デーモンの層、解析器、ファームの表、テストに触れた; 首がすることは上の表である。

⛔ **そして著者の第二の判断は名前についてではなかった**: 改名した身振りを枠から演じた後、**「動きが硬い」**。**動きは硬い**——各身振りは1つの速さの1回の移動で、そのあと停止である。それは表の欠陥ではなく、電線がまだできないことである: サーボの速さの欄は線形で、**離れる姿勢と取る姿勢の間で何も補間しない**。⚠️ **補間するはずのエンジンは、この機体で一度も走っていない。** それが次の決定であり、この記録はそれを決めない。

## この記録が言わないこと

- **動きが良いとは。** 著者は硬いと言い、それがこのファイルの最後の言葉である。
- **これらの角度が他人にとっても正しいとは。** 1つの目、1台、1日。第二の人は `look_side` をもっと別のところに置くだろう。
- **エンジンが走ったとは。** `Motion Intent` も、軌道も、門も、姿勢の流れも無い。基板は5つの姿勢の表を演じた。
- **`rest` が休みであるとも、`recoil` がのけぞりであるとも。** 語は読めるように選ばれ、姿勢がそれを運ぶかどうかは著者の判断であり、上に引用した。
- **ペットがそこに居るとは。** ⛔ **それは目標であり、この工房では検証できない。** 語に従う首は機構である。
