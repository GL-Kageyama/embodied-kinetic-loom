# 声音 — 2026-10-18

⛔ **观察是这份文件的脊骨。程序的数字是作为证据引用在它之中，而不是围绕在它周围。** 一份只装着电路板印出的东西的日志，回答不了这份记录所为何在——一个词是否被听见；而印着 `done` 的板子，会让并非证据的东西读起来像证据。

**数了什么。** 一块板、一个傍晚、一对耳朵。**没数什么：** 以分贝计的响度、扬声器实际发出的频率、第二位听者会不会用同样的方式命名这四个词，以及同一块板上的麦克风本该听见的东西——这里没有任何东西读过它。

## 被听见的

⚠️ **线路的第四个字段，自契约写下的那天起一直是沉默的。** 存在却从未发声的字段不是通道。在**日本时间19:00**——**在21:00静默线之前**，也就是这个时刻是刻意选的——四个词被逐个播放，板子每一次都作答，然后问作者：什么到了你那里。

| # | 到达作者的 | 那一刻板子所说的 |
|---|---|---|
| 1 | **四个词都听见了** | `bench: playing` … `bench: done`，每个词一次 |
| 2 | — | 随后同样的四个词由帧携带，板子印出了那个字段 |

⛔ **这个回答不是引语，这份文件也不把它打扮成引语。** 问的是四个词是否被听见，答的是四个都听见了。⚠️ **这足以支撑一个主张，不足以支撑任何别的：** 扬声器为每个词发出了声音。**至于哪一个好听、是否太响、是否适合它所在的迁移，什么也没说**——那没有被问，也没有被判定。

## 导线携带的

控制台是以守护进程开启它的方式打开的——`os.open` 与原始的 `termios`，整场只开一次，绝不使用 `pyserial`——因为同一块板在同一天被一个升起 DTR 与 RTS 的读取者卡死过两次（records/2026-10-18-the-lights-zh.md）。**这一次既没有复位它，也没有卡死它。**

```
  5.40 bench: playing hello
  5.58 bench: hello done
  8.39 bench: playing pip
  8.41 bench: pip done
 11.61 bench: playing chime
 11.85 bench: chime done
 14.80 bench: playing fall
 15.11 bench: fall done
```

⚠️ **`playing` 到 `done` 之间的间隔不是音的长度，也不能被读成音的长度。** `i2s_channel_write` 是在采样装进 DMA 缓冲时返回的，不是在扬声器把音放完时返回的：`pip` 20 ms 就闭合，`fall` 310 ms，**这些数字没有一个能作为这份记录可以主张的时长。**

随后是四个各载一个词的帧，和两次拒绝：

```
frame: light=warm face=happy gesture=look_up sound=pip
frame: light=dim face=sleepy gesture=none sound=chime
frame: light=dim face=none gesture=none sound=none
frame: refused (missing key)
frame: refused (unknown value)
```

- ⚠️ **`chime` 那一行在写下四秒之后才印出**，因为它前一个帧载着 `look_up`，而手势的马达在头转动时把控制台堵住了。**排在手势后面的词，是迟到的词**——这是在这里测到的，不是论出来的；
- ⛔ **没有 `sound` 字段的帧被拒绝了**（`missing key`），`"sound":"horn"` 的帧也被拒绝了（`unknown value`）。**字段是必需的，它的词是封闭的**——Python 解码器所主张的同一条规则，由另一端说了出来；
- ✅ **`"sound":null` 被接受**，并且什么也没播放。`null` 的意思是*这一帧是静默的*，而不是*保持上一个*。

## 放大器——照厂商的数字

⛔ **下面没有一个寄存器值是在这台机器上发现的。** 它们是驱动的（厂商栈里的 esp_codec_dev 的 AW88298 表），在这一天被读过；本仓库改动的那一个数被点名：

| 寄存器 | 值 | 做什么 |
|---|---|---|
| `0x00` | `0x55AA` | 软件复位，然后 50 ms |
| `0x04` | `0x4040` | 使能 I2S，把放大器从掉电中唤醒 |
| `0x05` | `0x0008` | SYSCTRL2，厂商的初值 |
| `0x06` | `0x3CC5` | Philips I2S，16 位帧，**速率码 5 = 24,000 Hz** |
| `0x0C` | `0x3064` | 音量 **−18 dB**——`0x30` 是那个字段，`0x64` 是厂商就这么放着的另一个字段 |
| `0x61` | `0x0673` | 厂商的初值，用途未读 |

⚠️ **初始化表自身的 `0x06` 是 `0x3CC8`**，它的低半字节是 48,000 Hz 的速率码。**这块板以 24,000 驱动，那个码被手工换成 `0x5`**——速率码与采样率不一致，是一条沉默而音高错误的通道，而这板上的任何东西都不会报告它。

⚠️ **复位线不是放大器上的寄存器。** 它是 AW9523 的 P0.2——显示器已经拥有的那块扩展器——所以 `display::pulse_amplifier_reset()` 持有那次脉冲，`sound` 回调进去。**一条总线，一个所有者。**

## 四个词

⛔ **这些是选择，不是测量**——与十二颗 LED 的颜色同一地位。这张表里没有一个音被测量过、与基准比对过、或与别的判定过。**留下来的是耳朵接受的那一个。**

| 词 | 音 | 形状 |
|---|---|---|
| `hello` | 659 Hz 90 ms → 880 Hz 150 ms | 上行 |
| `pip` | 1319 Hz 70 ms | 一个亮点 |
| `chime` | 880 Hz 90 ms → 1319 Hz 200 ms | 上行，且响得更久 |
| `fall` | 659 Hz 110 ms → 440 Hz 260 ms | 下行 |

⚠️ **哪个迁移携带哪个词是主机的规则，不是这块板的：** `SessionStart` 是 `hello`，`PermissionRequest` 是 `pip`，`Stop` 是 `chime`，`StopFailure` 是 `fall`，而 `UserPromptSubmit` 与 `SessionEnd` 是静默的。⛔ **板子知道这四个词，对何时正确一无所知**——它播放帧所命名的。

⚠️ **声音在守护进程的开关打开之前是关着的**（`--sound on|off`，默认 off）——作者的决定，好让装好之后机器不会不经要求就开口。

## 这份记录不确立什么

- **不确立这些音好听。** 四个词被听见了；**没有一个与另一个比对判定过**，这个工房里也没有基准音。
- **不确立离开扬声器的频率或响度。** 没有东西测量它们；耳朵说的是*声音*，不是*880 Hz*。
- **不确立引擎运行过。** 没有读 `Motion Intent`，没有计算轨迹。**扬声器回答词语；它不计算运动。**
- **不确立宠物在那里。** ⛔ **那是目标，在这个工房里无法验证。** 跟随事件的词是机制，不是存在。
