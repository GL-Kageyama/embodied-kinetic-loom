# 身势 — 2026-10-18

⛔ **观察是这份文件的脊梁。程序的数字被引用在它的内部作为证据，而不是在它的周围。** 一张没有眼睛在背后的角度表，是穿着测量外衣的猜测。

**数了什么。** 五个身势、一台个体、一双眼睛、一天。**没数什么：** 这些是不是*最好*的角度、第二个人会不会用同一个词称呼同一个姿态，以及它们背后有没有什么东西是活的。

## 看见了什么

**五个姿态是用台架命令摆出来的，一个一个地问。** 作者看着头部，每一次摆放都回答了。⚠️ **没有仪器记录这件事。这是桌上的一双眼睛，是这份文件里唯一能说「这个姿态就是那个词的意思」的东西。**

| # | 摆出的姿势 | 作者的话 | 留下的 |
|---|---|---|---|
| 1 | `bench set 8 50 80` | 「これで perk」 | yaw **+8.0°**、pitch **50.0°** |
| 2 | `bench set 20 50 80` | 「もっと大きく」 | 对 `turn` 来说不够 |
| 3 | `bench set 35 50 80` | 「これで turn」 | yaw **+35.0°**、pitch **50.0°** |
| 4 | `bench set 0 30 80` | 「もっと下げる」 | 对 `settle` 来说不够 |
| 5 | `bench set 0 10 80` | 「もっと下げる」 | 仍然不够 |
| 6 | `bench set 0 3 80` | 「これで settle」 | yaw **0.0°**、pitch **3.0°** |
| 7 | `bench set 8 10 80` | 「もっと深く」 | 对 `nod` 来说不够深 |
| 8 | `bench set 8 3 80` | 「これで nod」 | 下放点：yaw **+8.0°**、pitch **3.0°** |
| 9 | `bench set -8 70 80` | 「これで flinch」 | yaw **−8.0°**、pitch **70.0°** |

⛔ **五次摆放里有两次不是作者的选择，而是这台个体的极限。** `settle` 和 `nod` 的下放点都坐在 **pitch 3.0°**，厂商的下限（`kPitchAngleMinTenths`）上。作者为 `settle` 说了两次「もっと下げる」；第三次摆放是脖子能到的最低处，就在那里被接受了。**想更低的一个词，在这台机器上低不下去**——这是机器覆盖不了的差，写在这里，而不是被抹平。

⚠️ **台架的包络在测量途中动过。** 摆前两个姿态时是 ±20.0°，`turn` 根本没法展示：`bench set 20` 就是那个夹取本身。在第三次摆放**之前**提到了 ±45.0°——仍然是台架的边界、厂商 ±128.0° 的三分之一，不是身势的极限。它为什么动，和那个数一起写在 `main/board.h` 里。

## 每个姿态是怎么摆的

`bench set <yaw> <pitch> [speed]` 是同一天为这次测量加上的台架命令。它读两个位置，把两个目标写在当前位置上，打开扭矩，用测量所用的同一个速度给每个轴写一个目标，并**保持扭矩打开**，同时轮询到头部停止移动。⛔ **它不是轨迹**: 移动的是舵机自己的速度栏，上游什么也不插值。

⚠️ **命令的名字是 `set`，不是 `pose`。** 分派先试 `pos`，而它的比较是三字符宽，所以任何以 `pos` 开头的词都会被读成 `bench pos`。那个冲突写在源码里分派的地方。

## 数字

⚠️ **送出去的角度和舵机安定下来的位置不是同一个数。** 两个都在这里。

| 身势 | yaw (0.1°) | pitch (0.1°) | 写出的 raw | 保持的 raw（台架） | 保持的 raw（来自帧） |
|---|---|---|---|---|---|
| `look_up` | `+80` | `+500` | 485 / 780 | 491 / 778 | 477 / 781 |
| `look_side` | `+350` | `+500` | 572 / 780 | 566 / 778 | 564 / 781 |
| `rest` | `0` | `+30` | 460 / 629 | 466 / 630 | 467 / 629 |
| `nod`（下放点） | `+80` | `+30` | 485 / 629 | 478 / 630 | 没有单独读 |
| `recoil` | `−80` | `+700` | 435 / 844 | 442 / 842 | 442 / 842 |

⚠️ **零点属于这个个体，来自 NVS: yaw 460、pitch 620。** 换算是厂商的: `raw = zero + tenths × 16 / 50`，截断。

**偏差是真实的，而且不是常数。** `look_up` 停在写出的 yaw **上方 6 个计数**，`look_side` **下方 8 个**，`recoil` **上方 7 个**，pitch 轴在整次测量中两个方向偏 2〜5 个计数。⛔ **没有施加任何修正。** 一个固定的偏移没有被从齿轮间隙、从读回、从舵机自身的安定中分离出来——所以什么也不假设。

## 帧让词动起来

✅ **把表写进固件之后，五个身势是从电线上演出来的。** 一次一帧，把一行 JSON 写进板子的控制台。每一个都把头部移到测量出的姿态，板子印出了它停在哪里。⛔ **这仍然不是引擎**: 没有东西读 `Motion Intent`，没有东西插值，守护进程也没有发这些行——是会话用手写的。

`nod` 是唯一一个不是单一姿态的身势。它是作为**下放点和回来的地方**被测量的，而回来的地方就是它被测量时所在的姿态——`look_up` 的。⇒ **`nod` 下到 pitch 3.0°，再回到 pitch 50.0°。**

## 名字，和硬

⛔ **作者否定了协议从 0.19.0 起一直携带的五个词**: 「そもそも、英語の動作名前が、わかりづらい」。候选是 `perk`・`nod`・`turn`・`settle`・`flinch`——在会话里选的、不从任何地方借来的，尤其是 `perk` 读不出*把脸抬起来*。**作者选择了可读的英语，词变成了:**

| 旧词 | 新词 | 它说什么 |
|---|---|---|
| `perk` | `look_up` | 脸抬起来 |
| `turn` | `look_side` | 脸转向一侧 |
| `nod` | `nod` | 不变 |
| `settle` | `rest` | 脸低下去，留在那里 |
| `flinch` | `recoil` | 脸缩回去并抬起 |

⚠️ **角度没有跟着名字动。** 改名触及了 schema、编解码器、守护进程的层、解析器、固件的表和测试；头部做的事是上面那张表。

⛔ **而作者的第二个判断不是关于名字的**: 改名后的身势从帧里演完之后，**「動きが硬い」**。**运动是硬的**——每个身势都是一次一个速度的移动，然后停住。那不是表的缺陷，是电线还做不到的事: 舵机的速度栏是线性的，**在离开的姿态和到达的姿态之间什么都不插值**。⚠️ **那个会插值的引擎，在这台机器上从未跑过。** 那是下一个决定，这份记录不决定它。

## 这份记录不说什么

- **不说运动是好的。** 作者说它硬，那就是这份文件里的最后一句话。
- **不说这些角度对别人也正确。** 一双眼睛、一台个体、一天。第二个人会把 `look_side` 放在别处。
- **不说引擎跑过。** 没有 `Motion Intent`、没有轨迹、没有门、没有姿态流。板子演了一张五个姿态的表。
- **不说 `rest` 是在休息、`recoil` 是在退缩。** 词是为了可读而选的；姿态是否承载它们，是作者的判断，已在上面引用。
- **不说宠物在那里。** ⛔ **那是目标，在这个工房里无法验证。** 跟随词语的头部是机构。
