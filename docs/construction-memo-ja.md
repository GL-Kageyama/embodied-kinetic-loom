# リポジトリ構築メモ — どう作られ、いまどこに立っているか

⛔ **このリポジトリで、意図的に他の頁を写している唯一の頁である。** メモは要約であり、要約は2つ目の写しである——**そして2つ目の写しは、このリポジトリが既に欠陥と呼んでいる形である**: **一覧を2つ書けば、片方だけが直る**（`tools/purity.py`、そして同じ文が語彙の規則の下にも座っている）。

⚠️ **だから、この重複は隠していない。宣言し、そして規則を1つ連れている。**

- ⛔ **以下の行はすべて、どこかから導ける。ここにあるものは、1つも出典ではない。**
- ⚠️ **つまり——出典が変わったとき、間違っているのはこの頁である。** **地図として読み、記録としては決して読まない。**
- ⛔ **そして、鳴るものが何も無い。** **検算器を持たない3枚目の頁である**——**そして3枚の中で代価がいちばん高い。この頁のために書かれた検査は、出典ではなく写しを検査することになり、それは「違うものに鳴る検査」だからである。**

## 2台の機体

| | **機体1**——DOF Reality の制御箱 | **機体2**——スタックチャン |

| 何を動かすか | 人が座るプラットフォーム | 机の上の首 |
| 自由度 | **3つ**——`pitch` / `roll` / `yaw` | **2つ**——yaw と pitch。⛔ **roll は無い** |
| 数 | **10bit のカウント**——中立 `512`、枠 `190–833` | ⛔ **入りは度、出はサーボ自身のカウント。** ⚠️ **両者の換算は、どの記録にも無い** |
| ホスト → 機体 | ベンダーのプロトコル（シリアルまたは HID） | ⛔ **手元の個体には無い** |
| その数がコードのどこに住むか | `engine/backend/protocol.py`——`DofRealityWire`、`DOF_REALITY_ENVELOPE` | ⛔ **どこにも無い。モジュールが存在しない** |
| このリポジトリが持っているもの | 電線と Mock | 電線の上の層——事象から顔へ。⛔ **数は無く、運動も無い** |
| 手順表 | `docs/first-contact.md` | `docs/first-contact-stackchan.md` |
| このリポジトリから値が届いたことがあるか | ⛔ **無い** | ⛔ **無い** |
| 動いたことがあるか | ここでは分からない | ✅ **ある**——ベンダーの SETUP ウィザードがホームへ動かし、著者が見た（2026-10-15） |

⚠️ **そして機体2は2個体であり、それ自体が罠である。** 2026-10-04 には、借り物の個体が**実際にホストから駆動された**——`/dev/cu.usbmodem1101` のテキストシェル、`head <pan> <tilt>`。⛔ **手元の個体は、その個体ではない。** **その経路が1本も無い**——UART コンソールは無効、ポート 1〜65535 は走査してすべて閉、そしてこの機体は LAN 上のサーバではなく**ベンダーのクラウドのクライアント**である。⇒ **2026-10-04 日付の「動いた」は、すべて別の、ここに無い機体のものである。**

## 踏んだ罠

⚠️ **溶かした時間の順である。どれも、もう一度払い済みである。**

| 罠 | どう見えるか | 何であるか |
|---|---|---|
| ⛔ **Fresco Logic の USB ハブ** | デバイスは列挙され、文字列も MAC も正しく読める——**そしてシリアルが死んでいる** | esptool が全リセットモードで `No serial data received`、pyserial が**全ボーレートで 0 バイト**、一部のレートで `OSError: [Errno 83]`。**「基板が死んだ」と診断される。** Mac 本体に直挿しする——`Mac14,10` には USB-A が無いので、**データ対応の USB-C ↔ USB-C ケーブル**が要る |
| ⛔ **ポート名は身元ではない** | ハブを外したら `/dev/cu.usbmodem1401` が `1101` になった | ⚠️ **そして 10/04 の記録同士が、`101` と `1101` のどちらがスタックチャンだったかで食い違っている。** **MAC で識別すること** |
| ⛔ **`MOVE_SETTLE = 1.0`** | サーボが動き切る前に送った指令がストールさせ、電源レールを落とし、**両軸を落とす** | **このエンジンは 15〜20 ms ごとに目標を送る。** ⚠️ **それがここで耐えられるかは未測定**——そして唯一の点は逆を指している（`head 90 135` は `yaw=-1 pitch=-1` で終わった） |
| ⛔ **`flush()`（`tcdrain`）** | 戻ってこない | **macOS の pty で無限にブロックすることが実測されている。** ⇒ **理由を docstring に残すこと**——**残さなければ、次の誰かが「念のため」で足す** |
| ⛔ **macOS の CDC デバイスに対する pyserial** | `TIOCSDTR` / `TIOCSRTS` が **ENOTTY** を返す | ⇒ **ホストは DTR/RTS でボードをリセットできない**——ゆえにシリアル層は `termios` を直に使う |
| ⛔ **部分書き込み** | `vmen on` が `vmen o` で届き、シェルが何も返さない | **10/04 の記録が「サーボが無応答」と呼んでいた現象の、最も有力な原因である。** ⇒ **部分書き込みは `select` で待って埋め合わせること** |
| ⚠️ **このリポジトリの記録自体が誤りうる** | `HISTORY.md` の 0.15.0 が「利用者に見えるものは1つも変わらない」で始まっていた | ⛔ **同じ項が、`pet_report.caveat`——3言語すべての利用者可視の文字列——が変わったことを書いている。** **あの項は、書かれた日から偽であった。** ✅ **2026-10-15、それが属する見出しの下で訂正した——旧い文は残したままである**——**自分の主題を消す訂正は、訂正ではない**（0.14.1 が作った形） |
