# 登攀——通往编程智能体身体的进度表

⛔ **这一页是地图，不是记录。** 它的每一行都能从仓库的某个源推出——**源变了，错的是这一页。** **读它，是为了看登攀站在哪里，而不是为了知道发生过什么。**

**在造什么——以及不在造什么。** ⛔ **智能体不是在这里造的。** 智能体是 Claude Code，运行在一个会话里；**这个仓库造的是它穿的身体**——一张脸、一个声音、十二盏灯，以及一条脖子。⛔ **这里的代码不调用 LLM**，`Motion Intent` 由 Claude 在会话里、按技能的引导写下。⇒ **这里能检验的是身体的机制，不是智能体的判断。**

## 登攀的现在位置

**八个当中六个是 ✅，一个是 ⚠️，一个是 ⛔——2026-10-19 测得。** ⛔ **这不是「编程智能体的八分之六」**: 行是问题，不是权重；而表下面的那个问题，一个仪器也没有。

**第 5 级在 2026-10-19 闭合，而仪器是一只耳朵。** ✅ **耳朵做的是拿一个词去和别的词比**，不是拿音去和什么比：作者在厂商的 −18 dB 下听完四个，说「少し小さい」；在 `bench volume 90`——−10 dB——下说四个里有一个偏小，并把它指了出来：**`fall`，唯一以 440 Hz 收尾、整组里最低的那个词**。⇒ **启动音量现在是 −10 dB，而只有 `fall` 的振幅是 0.34（另外三个仍是 0.22）**，作者再听一次，说了「OK」。⚠️ **那是关于响度平衡的判断，也正是这一行在等的判断**——⛔ **四个形状仍然是选择，其中任何一个后面都没有测量。**

**第七阶造好了，它停在机体那里。** ✅ **代码这一侧已经合上**: 守护进程在每个身势的瞬间，在它将要流出的 fd 上向板子询问位置，并在 `PORT_WAIT = 0.5` 之内读回答案——这正是这张表所要的那次有界读取（`projects/stackchan/neck/readback.py`，十个测试）。✅ **2026-10-19 在机体上测得**: 查询被写下，控制台回答了——但答案是 `yaw=no answer pitch=no answer`，而 `bench scan` 在 `bench power on` 之前和之后都是 **0 id(s)**。⛔ **而当同一个问题被转向固件一侧时，回答比主机更早**: 启动日志读出 `servo: ping yaw=0/3 pitch=0/3` 和 `servo: a position did not read — nothing will move`——**总线在主机写下一行之前就沉默着。** ✅ **而 `bench power on` 不再是一句打印，而成了一个问句**: 命令检查扩展器的回答，探针读出引脚0背后的六个寄存器——`M_L`/`O_L`/`PU_L` 立着，`DRV_L` = `0xFE`（推挽），`I_L` = `0x00`。⛔ **`I_L = 0x00` 的含义尚未确定**: 扩展器的输入寄存器可能只在引脚为输入时映出焊盘，所以它**与线被拉低**和**寄存器不读输出**两者都相容。✅ **同一天又来了两个答案**: PMIC 把电池读为 **4,624 mV、充电中**，而 `bench level` 把引脚0的焊盘读为 LOW，即使输出在驱动高电平。⇒ **供电在电池那里；电源轨的电压仍未测量**——人下一步能试的是电源开关，其余由万用表合上。⇒ **路径被测量了；位置没有，而这里的代码造不出它。** ✅ **然后电源轨回答了，这一行动了，却没有合上**: `bench power off`、三秒、`bench power on` 让两个 id 都回来了，而 `bench state` 返回了舵机自己的 **5.1 V**、31〜32 °C、负载 0——**电源轨、开关、配线、扩展器，都不是原因。** ⛔ **沉默是舵机跨过这块芯片的复位所抱有的状态，而唯一能清除它的开关是电源轨**；自 0.19.31 起，启动自己投下它。✅ **而且一个位置回来了**: 在 `SessionStart` 上得到 `[28, 487]`，`look_up` 从那里流出。⛔ **这一行仍是 ⚠️，因为一个答案不是这一级**: 八次读回中有四次带着位置，一次有界动作之后总线又沉默了，而 `heard: false` 的机制之一是共享的控制台——问句被粘到一帧上，以 `frame: refused (malformed)` 被拒收。

**第 8 行要的是时间，不是代码——但它身上唯一长着代码形状的那一块，在 2026-10-19 落地了。** ⚠️ **直到 0.19.25，保住夜晚安静的唯一办法是 `--sound off`**，而那也把白天关掉了；⇒ **时刻如今是一条规则**（`projects/stackchan/quiet.py`，三十三项测试）：21:00–05:00 只关闭声音字段。✅ **而同一个早晨的 05:27，安装好的作业被切换到了 `--sound on`**——白天有声音，夜晚仍然没有。⛔ **这一行仍是 ⛔，因为没有人写下过一天**——**门开了。日子不在。** ✅ **自 0.19.28 起，那一天至少可以被数出来**: `projects/stackchan/day/` 读守护进程自己的日志——十七项测试、一个纯粹的核心、一个打开一个路径的边缘——而它的第一次读取数出了 **3,852 行、启动 11 次、判定 3,599 次、帧 124（全部 `sent: true`）、流 48、读回 24（其中带回位置的 0）**。⛔ **数是给记录用的证据，不是记录**: 它不说身体是对了、错了，还是没被注意到——而且 ⛔ **日志里没有一次重启说得出理由。**
