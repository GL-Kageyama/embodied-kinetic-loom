# 仓库构建备忘 — 它是怎么做出来的，现在站在哪里

⛔ **这是本仓库里唯一一页有意抄写其他页面的页。** 备忘是摘要，而摘要是第二份副本——**而第二份副本，正是本仓库已经称之为缺陷的形状**: **把一份清单写两遍，就只有其中一份会被修**（`tools/purity.py`，同一句话也坐在语汇规则的下面）。

⚠️ **所以这份重复没有藏起来。它是被声明出来的，并且带着一条规则。**

- ⛔ **下面的每一行都可以从别处推出来。这里没有一样东西是出处。**
- ⚠️ **也就是说——当出处变了，错的是本页。** **把它当地图读，绝不当记录读。**
- ⛔ **而且什么都不会让它响。** **这是本仓库第三页没有检查器的页面**——**而三页之中它的代价最高: 为这一页写检查器，检查的会是副本而不是出处，那是一个「对着错的东西响」的检查。**

## 两台机体

| | **机器1**——DOF Reality 的控制箱 | **机器2**——Stack-chan |
|---|---|---|
| 它动的是什么 | 人坐上去的平台 | 桌上的一个头 |
| 自由度 | **三个**——`pitch` / `roll` / `yaw` | **两个**——yaw 和 pitch。⛔ **没有 roll** |
| 数 | **10bit 的计数**——中立 `512`、包络 `190–833` | ⛔ **进的是度，出的是舵机自己的计数。** ⚠️ **两者的换算，任何记录里都没有** |

| 本仓库为它持有的东西 | 电线与 Mock | 电线之上的层——从事件到脸——**第二种运数的行（0.19.6，基板自 0.19.7 起读它）**、**流出它的主机（0.19.10）**、**在自有循环里流出它的守护进程（0.19.14）**、**控制台的读者（0.19.23）**、**基板判定的读者（0.19.38）**、**安静的时间（0.19.25）**、**一天的仪器（0.19.28）**、**以及拥有自己守护进程的第二层（0.19.46–0.19.50）** |

⚠️ **而机器2是两台个体，这本身就是个陷阱。** 2026-10-04，一台借来的个体**确实**被主机驱动过——`/dev/cu.usbmodem1101` 上的文本 shell，`head <pan> <tilt>`。⛔ **手边这台不是那一台。** **它一条这样的通路都没有**: UART 控制台是关的，端口 1〜65535 全部扫过、全部关着，而这台机子是**厂商云的客户端**，不是 LAN 上的服务器。⇒ **所有写着 2026-10-04 的「它能用」，都属于另一台不在这里的机子。**

## 踩过的陷阱

⚠️ **按耗掉的时间排序。每一条都已经付过一次了。**

| 陷阱 | 看起来像什么 | 它是什么 |
|---|---|---|
| ⛔ **Fresco Logic 的 USB 集线器** | 设备枚举出来了，字符串和 MAC 都读得对——**而串口死了** | esptool 在所有复位模式下都是 `No serial data received`，pyserial 在**所有波特率下读到 0 字节**，某些波特率抛 `OSError: [Errno 83]`。**它会被诊断成「板子死了」。** 直插 Mac 本体——`Mac14,10` 没有 USB-A，所以需要一根**支持数据的 USB-C ↔ USB-C 线** |
| ⛔ **端口名不是身份** | 拔掉集线器后，`/dev/cu.usbmodem1401` 变成了 `1101` | ⚠️ **而 10/04 的几份记录彼此矛盾: `101` 和 `1101` 里哪个才是 Stack-chan。** **用 MAC 识别。** ⛔ **2026-10-18: 一块板子在一次插拔后从 `1101` 变成 `101`**——**相隔十六分钟**——而写到不再存在的路径的帧是 `sent: false`，**安全，而且沉默** |
| ⛔ **`MOVE_SETTLE = 1.0`** | 在舵机走完之前送出的指令让它堵转、拉垮电源轨、**把两个轴一起带下去** | **本引擎每 15〜20 ms 送一次目标。** ⚠️ **那在这里撑不撑得住，没有测过**——而唯一的那个点指向反面（`head 90 135` 以 `yaw=-1 pitch=-1` 收场） |
| ⛔ **`flush()`（`tcdrain`）** | 它不返回 | **在 macOS 的 pty 上实测会无限阻塞。** ⇒ **理由要留在 docstring 里**——**不留在那里，下一个读的人就会「以防万一」把它加回来** |
| ⛔ **macOS CDC 设备上的 pyserial** | `TIOCSDTR` / `TIOCSRTS` 抛 **ENOTTY** | ⇒ **主机没法用 DTR/RTS 复位板子**——所以串口层直接使用 `termios` |
| ⛔ **部分写入** | `vmen on` 变成 `vmen o` 到达，shell 什么都不回 | **这就是 10/04 记录一直称作「舵机没有响应」的那个现象，最可能的原因。** ⇒ **部分写入必须在 `select` 等待之后补完** |
| ⚠️ **本仓库自己的记录也会错** | `HISTORY.md` 的 0.15.0 曾以「用户能看到的东西一点都没变」开头 | ⛔ **而同一条目里写着，`pet_report.caveat`——三种语言里的用户可见字符串——变了。** **那一条目，在写下的那天就是假的。** ✅ **2026-10-15 已在它所属的标题下订正——旧句子留着没删**——**抹掉自己主题的订正，不是订正**（0.14.1 立下的形状） |
