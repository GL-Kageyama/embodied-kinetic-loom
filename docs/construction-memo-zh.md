# 仓库构建备忘 — 它是怎么做出来的，现在站在哪里

⛔ **这是本仓库里唯一一页有意抄写其他页面的页。** 备忘是摘要，而摘要是第二份副本——**而第二份副本，正是本仓库已经称之为缺陷的形状**: **把一份清单写两遍，就只有其中一份会被修**（`tools/purity.py`，同一句话也坐在语汇规则的下面）。

⚠️ **所以这份重复没有藏起来。它是被声明出来的，并且带着一条规则。**

- ⛔ **下面的每一行都可以从别处推出来。这里没有一样东西是出处。**
- ⚠️ **也就是说——当出处变了，错的是本页。** **把它当地图读，绝不当记录读。**
- ⛔ **而且什么都不会让它响。** **这是本仓库第三页没有检查器的页面**——**而三页之中它的代价最高: 为这一页写检查器，检查的会是副本而不是出处，那是一个「对着错的东西响」的检查。**

## 两台机体

| | **机器1**——DOF Reality 的控制箱 | **机器2**——Stack-chan |
|---|---|---|
| 它动的是什么 | 人坐上去的平台 | 桌上的一个头 |
| 自由度 | **三个**——`pitch` / `roll` / `yaw` | **两个**——yaw 和 pitch。⛔ **没有 roll** |
| 数 | **10bit 的计数**——中立 `512`、包络 `190–833` | ⛔ **进的是度，出的是舵机自己的计数。** ⚠️ **两者的换算，任何记录里都没有** |
| 主机 → 机体 | 厂商的协议（串口或 HID） | ⛔ **手边这台上没有** |
| 它的数住在代码的哪里 | `engine/backend/protocol.py`——`DofRealityWire`、`DOF_REALITY_ENVELOPE` | ⛔ **哪里都没有。模块不存在** |
| 本仓库为它持有的东西 | 电线与 Mock | 电线之上的层——从事件到脸。⛔ **没有数字，也没有运动** |
| 它的清单 | `docs/first-contact.md` | `docs/first-contact-stackchan.md` |
| 从本仓库送出的值到达过吗 | ⛔ **没有** | ⛔ **没有** |
| 它动过吗 | 在这里不知道 | ✅ **动过**——厂商的 SETUP 向导把它驱回原位，作者看见了（2026-10-15） |

⚠️ **而机器2是两台个体，这本身就是个陷阱。** 2026-10-04，一台借来的个体**确实**被主机驱动过——`/dev/cu.usbmodem1101` 上的文本 shell，`head <pan> <tilt>`。⛔ **手边这台不是那一台。** **它一条这样的通路都没有**: UART 控制台是关的，端口 1〜65535 全部扫过、全部关着，而这台机子是**厂商云的客户端**，不是 LAN 上的服务器。⇒ **所有写着 2026-10-04 的「它能用」，都属于另一台不在这里的机子。**

**六级。一级 = 一个提交 = 一个版本。** **每一级只由它前面那一级来证成，而梯子可以在任何一级停下**——**这样切成六级，目的就在这里。**

| **0.16.0** | 语汇报出机体 | ✅ 已落地。`references/` ×3、`COLUMNS` 6→7、V4 与 V5 扩展、自检 14→16 |

⛔ **而路线现在站在哪里，诚实的总结是: 没有打开。** ⚠️ **四级造的是插座，不是第二个插头。** `engine/backend/` 里只有 `axis_map.py`、`cycle.py`、`gate.py`、`mock.py`、`protocol.py`、`transmit.py`、`wire.py`——**机器1的电线而已。** ⛔ **本仓库直到 2026-10-18 一毫米也动不了 Stack-chan，而在那一天它动了 40°**——靠的是打入固件控制台的一条台架命令，**那是机构在动，不是电线在抵达**（`projects/stackchan-firmware/records/2026-10-18-first-arrival.md`）。

⚠️ **而梯子已经比计划长了。** 0.17.0 定下的是要求而不是形状，所以**决定记录形状的那一级，在这条梯子上还没有位置**——**它排在 0.20.0 后面，而不在计划里。** ⛔ **一份把六级排得整整齐齐的摘要，正在用省略撒谎。** ✅ **取而代之的是，2026-10-18 方策按写下的样子生效了: 形状在有了可以放进去的东西的那天被定下**——`projects/stackchan-firmware/records/2026-10-18-first-arrival.md`，**观察在先，程序的数字被引用在其中。**

⚠️ **2026-10-18: 一个不在这条梯子上的层。** `projects/stackchan/` 把 Claude Code 的钩子事件映射到六个阶段、Pet 的五张脸、六种光与五个候选身势——⛔ **没有机器2的数字，所以什么也不发送（`sent` 是 `False`）。当两个以上窗口同时运行时，脖子也只用在一个窗口上。** 它在 0.19.0 之前到来，**但它不是一级**: 梯子的顺序没有变，**变的是上面那张表的一行——本仓库现在为机器2持有东西，而它不是电线。** ⚠️ **2026-10-18 它接到了钩子上，而桥的两端都在:** `projects/stackchan/daemon/` 就是保住状态的那个进程——纯核心（`room.py`）与套接字边缘（`__main__.py`），二十六项测试——而 `projects/stackchan/hook/` 是钩子运行的客户端: 一个事件一个进程，沉默地以 0 退出，二十一项测试。✅ **launchd 用户代理在登录时启动守护进程，全部三十三个事件都调用客户端**，所以钩子能够到达房间。⛔ **但它到达不了机体。** **安装不是仓库的性质，而是一台主机上的一个位置**——plist 副本在 `projects/stackchan/launchd/`，记录与卸载路径在 `docs/stackchan-daemon.md`。✅ **而自 0.19.0 起，本仓库也为那一层持有一根电线**——帧、它的契约，以及机体那一端的源码——⛔ **所以「它不是电线」在那天为真，如今不再为真。如今仍然为真的是: 传输路径未选定。而「我们自己的东西什么也没有被烧写」也不再为真了——0.19.4 时它被烧写了，并且转动了头。**

⚠️ **2026-10-18，又有一个点版本，它同样不是一级。** 0.19.1 坐在 0.19.0 与 0.20.0 之间，**没有级别编号**: `projects/stackchan/outbound.py` 把可见状态差分成一个 `Frame`，守护进程把它本该送出的帧写成一行——`{"frame": …, "sent": false}`。⛔ **那一行不是电线**，而 ⛔ **它也不是运动的记录**——帧是程序本该发出的东西，而记录的要求说，它本身不能成为记录。**传输路径仍未选定，0.20.0 仍未开始。**

⚠️ **2026-10-18，还有 0.19.2，它同样不是一级——第一次写入，而其中没有一行是本仓库的代码。** 手边的个体以 MAC 被识别，经由 esptool 把原厂镜像写入并逐位读回，然后把它写在上面、同一天取下的快照也同样写入并读回。⛔ **那第一次恢复之后的启动没有被看到**，所以那一轮证明了网能承住一次写入，还没有证明能承住一台机器。✅ **同一天的 0.19.3 关上了后半**: 从它自己的 USB 日志看到原厂镜像启动——启动器打开、每个应用被创建——写回的快照也一样。⇒ **级别没有变。变的是一个文件的主张**——`docs/first-contact-stackchan.md`。⛔ **传输路径没有选定，`sent` 依然是 `False`。**

⚠️ **2026-10-18，还有 0.19.4，它也不是一级——第一次抵达，而且它是本仓库的东西第一次真正到达机体。** `projects/stackchan-firmware/` 被构建（`build/stackchan-vessel.bin`，272,976 字节），写在 `0x510000`，核对哈希后运行；一条打入其控制台的命令把头的 40°，缓缓地、一格一格地转了过去。⛔ **它不是通过一个帧抵达的**——引擎没有跑，没有读 `Motion Intent`，每一个身势仍然被拒绝。✅ **记录在 `projects/stackchan-firmware/records/2026-10-18-first-arrival.md`，它是 0.17.0 时还空着的容器的第一条。** ⛔ **0.20.0 没有开始，传输路径仍然没有选定。**

## 踩过的陷阱

⚠️ **按耗掉的时间排序。每一条都已经付过一次了。**

| 陷阱 | 看起来像什么 | 它是什么 |
|---|---|---|
| ⛔ **Fresco Logic 的 USB 集线器** | 设备枚举出来了，字符串和 MAC 都读得对——**而串口死了** | esptool 在所有复位模式下都是 `No serial data received`，pyserial 在**所有波特率下读到 0 字节**，某些波特率抛 `OSError: [Errno 83]`。**它会被诊断成「板子死了」。** 直插 Mac 本体——`Mac14,10` 没有 USB-A，所以需要一根**支持数据的 USB-C ↔ USB-C 线** |
| ⛔ **端口名不是身份** | 拔掉集线器后，`/dev/cu.usbmodem1401` 变成了 `1101` | ⚠️ **而 10/04 的几份记录彼此矛盾: `101` 和 `1101` 里哪个才是 Stack-chan。** **用 MAC 识别** |
| ⛔ **`MOVE_SETTLE = 1.0`** | 在舵机走完之前送出的指令让它堵转、拉垮电源轨、**把两个轴一起带下去** | **本引擎每 15〜20 ms 送一次目标。** ⚠️ **那在这里撑不撑得住，没有测过**——而唯一的那个点指向反面（`head 90 135` 以 `yaw=-1 pitch=-1` 收场） |
| ⛔ **`flush()`（`tcdrain`）** | 它不返回 | **在 macOS 的 pty 上实测会无限阻塞。** ⇒ **理由要留在 docstring 里**——**不留在那里，下一个读的人就会「以防万一」把它加回来** |
| ⛔ **macOS CDC 设备上的 pyserial** | `TIOCSDTR` / `TIOCSRTS` 抛 **ENOTTY** | ⇒ **主机没法用 DTR/RTS 复位板子**——所以串口层直接使用 `termios` |
| ⛔ **部分写入** | `vmen on` 变成 `vmen o` 到达，shell 什么都不回 | **这就是 10/04 记录一直称作「舵机没有响应」的那个现象，最可能的原因。** ⇒ **部分写入必须在 `select` 等待之后补完** |
| ⚠️ **本仓库自己的记录也会错** | `HISTORY.md` 的 0.15.0 曾以「用户能看到的东西一点都没变」开头 | ⛔ **而同一条目里写着，`pet_report.caveat`——三种语言里的用户可见字符串——变了。** **那一条目，在写下的那天就是假的。** ✅ **2026-10-15 已在它所属的标题下订正——旧句子留着没删**——**抹掉自己主题的订正，不是订正**（0.14.1 立下的形状） |

## 作法——以及每一条实际写在哪里

⚠️ **这里不重写。** **所有规则的典章是 `CLAUDE.md`**，而第二份副本**恰恰就是本页开头指名揭出的那个缺陷**。下面只有**散落的部分**，或者**哪里都没写的部分**。

**五项检查——按每一级跑它们的顺序。** ⚠️ **这个顺序，本仓库里没有任何地方写着:**

```
python3 -m pytest tests/
python3 tools/check_vocabulary.py --self-test
python3 tools/check_vocabulary.py
python3 tools/check_i18n.py
claude plugin validate --strict .
```

⚠️ **`tests/README.md` 列出了这些检查，但不是这个顺序，也没有说要把它们一起跑。**

| 什么 | 写在哪里 |
|---|---|
| 文档规则、语汇规则、记录规则、安全一节、git 规则 | `CLAUDE.md` |
| 五项检查，以及每项看到什么 | `tests/README.md` |
| 带日期的经过，以及全部实测值 | `HISTORY.md` |
| 版本台帐——两份 manifest 与 `HISTORY.md` 最上面的标题 | `.claude-plugin/*.json`，由 `tests/test_versions.py` 核对 |
| ⛔ **被禁的 import 清单** | `tools/purity.py`——**一份清单，两个扫描器**（`tests/test_purity.py`、`tests/test_pet_purity.py`） |

⚠️ **还有两个数是测出来的，不是固定的**——**每一级都必须重数所有带着它们的文档**: **测试数与文件数**（`CLAUDE.md` 的 Tests、`README.md`、`tests/README.md`），以及**典章的本数**（`tools/check_i18n.py` 会打印）。**从上一版抄下来的数，就是错的数。**

## 本页不做什么

- ⛔ **它不是出处。** **本页与出处冲突时，对的是出处**——**而能发现这件事，正是第一节要讲「本页会怎么错」的理由本身。**
- ⛔ **它不重写规则。** **唯一重写的是运行顺序，而理由也写在那里**——**因为没有别的东西守着它。**
- ⛔ **什么都不会让它响。** ⚠️ **而和两份清单不同，在这里放一个检查器比没有更糟**——**它会把副本认证成真的。**
- ⚠️ **它不是记录之器，也不是 `HISTORY.md`。** **本页说「现在站在哪里」，`HISTORY.md` 说「某一天发生了什么」。** ⛔ **写了其中之一却把另一个的名字叫出来，正是两页都在警告的那个错误。**
