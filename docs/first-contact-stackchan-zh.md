# 第一次接触机器2的那一天 — 而本页从另一端开始

⚠️ **本页是清单，与 `docs/first-contact.md` 一样，不是安全论证**——**可以命令马达做什么，写在 `CLAUDE.md` 的 § Safety，本页不重复它。** 这里只放**若不从本仓库之外留下的记录里重读、就得在那台机子面前重新拼出来的东西**。

⛔ **而它从另一端开始。** 机器1那一页上，**条目一条都还没有做过**——因为没有机体。**这里，大部分已经做过了**：**手边这台在 2026-10-15 被放到计算机面前，另一台在 2026-10-04 被驱动过**——**而两者不是同一台机子。**

⇒ **本页的警告，是那一页警告的反面。** 在那边，一份过于齐整的清单会读起来像是**已经了结**——**尽管一件都没有。** **在这边，一份齐整的清单会读起来像是「答案属于你手边那台」——而大多数并不是。** ⚠️ **下面每一条事实都报出自己是在哪一台上测的。** **一台机子上的事实，不是另一台上的事实。**

## (a) 首先，是哪一台 Stack-chan

| | 被驱动过的那台 | 手边这台 |
|---|---|---|
| 测量日 | 2026-10-04 | 2026-10-15 |
| MAC | `68:ee:8f:d8:55:60` | `80:45:6B:54:6D:B0` |
| 固件 | `shi3z` "Stack-chan Web Server"——Arduino / M5Unified / M5GFX | M5Stack 原厂 **v1.5.1**（2026-07-31 构建）、ESP-IDF v5.5.4 |
| 主机 → 马达 | ✅ **有**——`/dev/cu.usbmodem1101` 上的文本 shell，`head <pan> <tilt>` | ⛔ **没有** |
| 舵机零点 | 没有记录 | yaw（ID 1）**460** / pitch（ID 2）**620**——⚠️ **这是 2026-10-15 由 SETUP 向导写入的值** |
| SKU / UUID | — | `m5stack-stack-chan` / `05fc3176-7236-46ac-8f33-0dfb43d46d55` |

⛔ **手边这台上不存在那条通路。而这正是决定了整条路线形状的发现。** **它不是被关掉的——它一开始就没有:**

- **UART 控制台是关的。** `help`、`?`、单独一个换行，什么都不回。
- **没有本地 API。** **端口 1〜65535 全部扫过，全部关着。**
- **这台机子不是服务器。** 它**作为客户端**去连 `ws://47.113.125.164:12800`——所以 MCP 的那些工具（`self.robot.set_head_angles` 等等）**只能经厂商的云到达，从 LAN 到不了。**
- 启动器上的应用——Launcher / AI.AGENT / AVATAR / ESPNOW.REMOTE / APP.CENTER / EZDATA / DANCE / SETUP——**没有一条通往主机的路。**

⇒ **自己写固件，在这里不是偏好。面对「手边这台上一条通路都没有」这个事实，它是唯一的方法。**

⚠️ **而这台上的「动了」是观察，不是测量。** 2026-10-15，SETUP 向导的 "Move To Home" 让脖子动了，**作者看见了。** 由此可以确认的是 **舵机本体、SCS 总线、舵机电源、扭矩控制全都正常**——⛔ **而这对本仓库什么都没说，因为从本仓库送到这台机子上的值，一个都没有。**

## 烧固件前唯一的一道门

**能不能把原厂镜像写回去。** 先把这件事做掉——因为 ⛔ **烧录是本页上唯一一个、事后无论再送什么都无法撤回的动作。**

安全网在，而且已经验证过:

| | |
|---|---|
| 文件 | `backup/stackchan-stock.bin`——⚠️ **在桌面上，不在本仓库里** |
| 长度 | **16,777,216 字节** |
| SHA256 | `012fe9d0b3c6075f78dd5426d5da7ed451c96c77ff685b1540c33a1f7594b466` |
| MD5 | `57de1620c3d1d4653927382abc7528d5` |
| 读回 | ✅ esptool 的 `verify-flash` 报告**与设备逐位一致** |
| 恢复 | `esptool --port /dev/cu.usbmodemXXXX write-flash 0 backup/stackchan-stock.bin` |

eFuse 实测: **`SECURE_BOOT_EN` False**、**`SPI_BOOT_CRYPT_CNT` Disable**、**`DIS_DOWNLOAD_MODE` False**、**`DIS_USB_SERIAL_JTAG` False**，而 `SOFT_DIS_JTAG` / `DIS_PAD_JTAG` 未被禁用。⇒ **一把锁都没上，可以自由烧入自制镜像。**

⛔ **而安全网没有覆盖的部分，就在这里。** ⚠️ **记录里一次写入都没有。** 镜像是**读**闪存做出来的，又**读了一遍**确认的。⇒ **写入的通路——线、芯片、驱动、偏移——在这台主机上一次都没有走过。** **读的验证证明的是「镜像是这台设备的」。它不证明「镜像能放回去」。**

⇒ **在第一次烧自制固件之前，先做一次恢复。** 把原厂镜像写进去，让它启动，把版本读回来。**那时候才知道网是承得住的。** ⛔ **一张从未张开的网，是文件，不是网。**

⚠️ **而在按下任何东西之前，有一件事要先定下来——舵机零点住在 NVS 里。** **整镜像恢复会把它们退回 455 / 603**——⚠️ **不会退回 2026-10-15 向导写下的 460 / 620。** ⛔ **只恢复分区，则会退回到又一个别的东西。** ⇒ **要知道自己选的是三者中的哪一个。并且把这个选择写在烧录之前——不是之后。**

## ⛔ 一个会耗掉一小时的陷阱——而它看起来像板子坏了

**端口名不是身份，也不稳定。**

- 经过 **Fresco Logic 的 USB 集线器**（带 Realtek 网口的底座），**枚举一切正常，串口却完全死掉。** `/dev/cu.usbmodem*` 会出现，USB 字符串和 MAC 都读得对——**然后就:** esptool 在所有复位模式下都是 `No serial data received`，pyserial 在**所有波特率下读到 0 字节**，某些波特率抛 `OSError: [Errno 83] Device error`，**启动日志一行都不出。**
  ⛔ **这正是会被误诊成「板子死了」的形状。** 解法是**直插 Mac 本体**——而 `Mac14,10` 没有 USB-A，所以需要一根**支持数据的 USB-C ↔ USB-C 线**。
- **名字会动。** 拔掉集线器后，这台从 `/dev/cu.usbmodem1401` 变成了 `/dev/cu.usbmodem1101`。⚠️ **而 10/04 的几份记录彼此矛盾：`/dev/cu.usbmodem101` 和 `1101` 里，哪个才是 Stack-chan。**

⇒ **用 MAC 识别机子，绝不用端口名。** ⚠️ **出现的通路，不是通得掉的通路**——**而「枚举出来了」，恰恰就是你会相信它的那种情形。**

## 机器2已经回答了什么——以及回答的是哪一台

⚠️ **这些是机器1那一页至今仍列为「未知」的问题。这里已经有答案——混着 10/04 那台的，和手边这台的。**

- **有几个轴。** **两个**——yaw（舵机 ID 1）和 pitch（ID 2）。⛔ **没有 roll。** `Motion Intent` 的三个名字不变——**只是这台机子不持有其中一个**——**而把它记下来的地方，是词表里「差」的那一栏。**
- **数的单位。** **进的是度，出的是舵机计数。** ⛔ **而两者的换算，任何记录里都没有。** 记录里有的是**零点**，**不是标度。**
- **数做什么。** 在 10/04 那台上: `head 45 90` → yaw 322、`head 90 90` → 454、`head 135 90` → 597、`head center` → 454；`head 90 45` → pitch 637、`head 90 90` → 762。✅ **一个轴上三个点，而且间距均匀**——⚠️ **那是那台的事。** ⛔ **不要搬到手边这台上:** 手边这台的零点被向导改成了 460 / 620，**而零点不是标度。**
- **传输层。** **两台都是** ESP32-S3 的 **native USB Serial/JTAG**——VID `0x303A` / PID `0x1001`。⛔ **没有 CP210x，也没有 CH9102**——所以线路设置和自动复位的行为，是 ESP32-S3 的，不是 USB-UART 桥的。
- **能对 shell 说什么。** `head nod|shake|center|<pan> <tilt>`、`vmen on|off`、`track on|off|mirror`、`follow`、`search`、`say` / `greet` / `tts`、`brain <url>`、`wifi` / `scan` / `target` / `gw`、`rover`、`i2cint` / `camtest`、`status` / `ping` / `clear` / `reboot`。⚠️ **那是 10/04 那台的 shell，是跟着另一份固件来的。** ⛔ **手边这台上没有 shell。**
- **闪存布局**（10/04 那台）: nvs 20 KB、otadata 8 KB、app0 3072 KB、app1 3072 KB、ffat 10112 KB、coredump 64 KB。⚠️ **布局相同不等于固件相同**——手边这台从 `0x510000` 的 `ota_1` 槽启动。

## ⛔ 有一条实测，与本引擎正面冲突

⚠️ **这是在你按周期送任何东西之前，应该拦住你的那一行。**

摘自针对 10/04 那台写的示例游戏:

> 如果在舵机走完之前就送下一条指令，舵机会堵转，电源轨会掉，**两轴都变得没有响应。** 带移动的指令之间，必须至少隔 1 秒。（`MOVE_SETTLE = 1.0`）

⛔ **而这个引擎，是按每 15〜20 ms 送一次目标来造的。** **那在这台机子上撑不撑得住，没有测过**——而记录里唯一的一个点，指向反面: `head 90 135` **让舵机堵转、电源轨掉下来、两轴都报 `yaw=-1 pitch=-1`。** 恢复靠 `vmen off` → `vmen on`，**3 次里成了 3 次。**

⇒ **这条通路的周期、速度上限、可动范围，全部未测量，不带任何默认值**——和机器1的 `Envelope` 同一条规则: **没人测过的数不是默认值，它是穿着默认值衣服的猜测。** ⚠️ **而唯一能回答它的是门**——门之所以能挡下「太快的那一帧」，靠的是 `velocity`。**没有那个数，门什么也守不住。**

⚠️ **而在做任何事之前，先送 `track off`。** 摄像头的追脸会拿 `cam_hal: EV-VSYNC-OVF` 把流刷满，**让 shell 失去响应。** **这该算固件的问题还是摄像头的问题，记录里没有**——**但在 10/04 那台上，关掉追踪之前，shell 一直看起来是坏的。**

## 在这里，「停」是什么

⛔ **这台机子上，同样没有停下的命令。**

| 命令 | 它实际做什么 |
|---|---|
| `vmen off` | 关掉**舵机电源**——⚠️ **而没有电的舵机，哪个位置都不保持** |
| `reboot` | ⚠️ **重启不是停下**——电源轨会回来，舵机回到最后被告知的值 |
| 「原地别动」 | **没有这样的命令** |
| 拔线 | ⛔ **和机器1同一个陷阱**——**机器不会因为主机离开了就停下** |

⚠️ **而这里比机器1更糟，不是更好。** 那边，失效模式是扭矩衰减到四分之一。**这边记录下来的失效模式，是电源轨本身掉下去**——⛔ **也就是说，你没在命令的那个轴，会跟着你在命令的那个一起掉。**

⇒ **你实际会用的停止，是电源开关，或者电池。** **在打开端口之前，要知道它在哪**——**而在这台上，就是在插 USB-C 线之前。在 10/04 那台上，活着的是「烧录」那条路。**

## ⛔ 不容误读的结局

⚠️ **在这台机子上，绿日志的结局比机器1更容易到达。而这正是它更危险的原因。**

**固件会回话。** `ping` 回 `yaw(id1)=ok pitch(id2)=ok`；`status` 打印 `raw pos yaw=266 pitch=753`。⇒ **你可以做出一份满是机器回话的日志，却仍然不知道有没有东西动过。** ⛔ **而舵机自己的回话也不是证据。** 记录说得一字不差:

> `[ScsServo] id: 1 get zero pos: 455 from settings` 只是从 NVS 读的，**不是总线通信的证据。** 动了的证据，**只有「脖子真的动了」。**

⇒ **那边如此，这边也如此: 绿日志装得下的，是主机发出去的东西，和从线上回来的东西。这两样都不是「它动了」。**

**写什么，写去哪。** ⚠️ **两件不同的东西，去两个不同的地方**——**和机器1那一页同一条规则。**

| 什么 | 哪里 |
|---|---|
| **按顺序，发生过的一切**——哪个 MAC、哪个端口名、烧了什么，**以及有没有东西动过。** | **`projects/`**——记录之器。⛔ **它是空的，而它的形状是有意未定的**（见 `CLAUDE.md`）。 |
| **知见——那些改变「文档现在怎么说」的东西。** | ⚠️ **送回现在写着「未知」的那些文档**——`CLAUDE.md` 的 § Safety、机器1那一页，以及本页。**不送回去的知见，会让文档继续撒谎。** |

⛔ **而 `examples/` 不存在。** **`projects/` 是工作与记录唯一的地方。**

## 这里没有的东西

- ⛔ **本页的条目，一条也不会让检查响。** ⚠️ **理由与代价都和机器1那一页相同**: 这些是在机子面前、只做一次、用手做的确认，**而一个去检查「一串字符串被打了字」的检查，是长着检查形状的噪声。** **本页会变旧，而什么都不会说。**
- ⛔ **本页不是记录之器。** **这里没有一件东西是本仓库观察到的。**
- ⚠️ **而本页是从本仓库之外留下的记录写成的**——桌面上的两个目录，**以及一份已经不在的、厂商源码的一次性检出**。**来自记录、而非来自本仓库自身测量的行，会报出这件事。**
