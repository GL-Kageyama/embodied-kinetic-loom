# embodied-kinetic-loom — Motion Intent を書く

**このスキルは、このエンジンが据えられている唯一の値を書く。** その値より上流はすべて自由でよい——判断でも、会話でも、部屋に居る人でも。**その値より下流はすべて関数である。****このスキルは、その上流の端である。**

⚠️ **これは文書であって、プログラムではない。** セッションに指示する。 ⛔ **このリポジトリのコードはモデルを呼ばない**——書くのはセッションの Claude であり、**このファイルがその導きである。** それが決定 D-03 であり、**その下の軌道を厳密に検査できる理由である。**

## このスキルが何であるか

- **これが唯一の書き手である。** ⛔ **「このリポジトリの書き手」ではない——書き手である。** セッションが無く Pet が入っているとき、**アプリの中の AI が意図を書く**（決定 C）。**そしてそれは、このファイルに従って書く。** 仕様は1つ、呼ぶ側は2つ。**1本で足りるのは、そういう理由である。**
- **成果物は `Motion Intent` である**——機体の3つの自由度の上での、カウントとミリ秒の小さな JSON。
- **語の出どころは `references/README.md` である**——語彙。**何かを書く前に、これを読む。**

## ⛔ 最初の運動の前に、これを読む

**出力はファイルではない。** ファイルは焼き直せて、切り直せて、消せる。**運動は部屋の中で1度起き、取り消せない。**

- **機体は、受け取った値を検査しない。** 値域へのクランプはホストの仕事である——**ベンダーの参照コード自身がそう書いている。**
- **プロトコルに停止コマンドが無い。** `[mo0]` は*報告をやめる*、`[sav]` は EEPROM への保存である。 ⛔ **どちらもモーターを止めない。**
- **上流ファームにソフトスタートもソフトストップも無い。** 段差指令は段差のまま入る。**エンジンの軌道はこれを避けるために在り、このスキルはそれを壊してはならない。**
- **機体を止めておけるのはホストだけである。** 送信をやめると、15秒でトルクが約 1/4 に落ちる——**そしてモーターは止まらない。**
- **3軸のうち1本が強制停止に入ると、他の2本も操作できなくなる。**

⚠️ **これらは、このスキルについての注意ではない。** 決定論的な核心が存在する理由である。**測定ごと `CLAUDE.md` に書いてある。**

## 手順

### 1. 語を引く

**`references/README.md` を読む。** その表が語彙である——語、機体が持つ自由度、量、時間、そして ⛔ **この機体が覆えない差の欄**。

**その運動が要する語を、名前で取る。** ⛔ **頭の中で数に直してから、数を書かない。** 数は行から来る——*ゆっくり* が何を意味するかについての感覚からではない。

### 2. 語が表に無いとき

⛔ **表に無い語は、語彙に無い。** **意図を書く時点で、語を作らない。**

**先に書くのは行のほうである**——`references/README.md` **と2本のミラーへ、同じコミットで**——そして**すべての欄を、差の欄も含めて埋める。** 語が機体の持たない自由度を名指すとき、**その隔たりを書くのがその欄であり、欄が在る理由である。**

**意図は後から書く。** ⚠️ **語彙が育つ道はこれだけであり、それは意図的である**——**1行は、正直に埋めねばならない欄を1つ要求する。**

### 3. 意図を書く

**形は `schemas/motion-intent.schema.json` が定める**——1つのオブジェクト、1つの鍵、運動の並び:

```json
{
  "moves": [
    { "dof": "pitch", "target": 552, "duration_ms": 600, "group": 0 },
    { "dof": "pitch", "target": 512, "duration_ms": 600, "group": 1 }
  ]
}
```

- **`dof` は `pitch` / `roll` / `yaw` のいずれかである。** ⚠️ **この3つの名前は我々のものであって、機体のものではない**——**制御箱は正準の軸対応を文書化しておらず、各軸の符号は配線に依存する。**
- **`target` はカウントであり**、プロトコル自身の単位である。 ⛔ **可到達な値域は、意図的に型に入れていない。** 既定ではホストは 190〜833 を指令でき、**箱のリミットはフィードバック駆動であって定数ではない。** **外殻は実行時に与えられる——意図に値域を書いて、それを信じてはならない。**
- **`duration_ms`** はその運動の所要時間である。**同じ `group` の運動は同時に走り**、1つの群の中のすべての運動は同じ長さでなければならず、**群は0から昇順に走る。**
- ⛔ **語は意図の中に書かれない。** スキーマは閉じており、**閉じているのが正しい。** **意図は既にカウントであり、なぜその数なのかを自分では言えない**——**その2つを1つに保つ場所は `references/README.md` だけである。**
- **`quality` は開けてある唯一の欄であり、エンジンは無視する。** そこに何を書いても、走るものは変わらない。**開けてあるのは、それを埋めるはずの写像の半分がまだ無いからである**——副詞。

**置き場は `projects/<作品>/motions/<名>.json` である。** `projects/` は、このリポジトリで作業と記録を置く唯一の場所である。

### 4. 走らせて、検査を走らせる

```bash
python3 -m projects.pet --motion <名>     # 顔と身体を、1つの時計から
python3 -m pytest tests/ -q               # 何が検査され、どこに在るかは tests/README.md
python3 tools/check_vocabulary.py         # 表——列・自由度・パス
python3 tools/check_i18n.py               # ミラー——いま足した行も含めて
claude plugin validate --strict .         # .claude-plugin/ に触ったときだけ
```

⛔ **`--motion` の送り先は Mock であって、機体ではない。** シリアル層は、機体が握っている唯一の部分であり、**まだ書かれていない。**

## このスキルがしてはならないこと

- ⛔ **語を作ること。** §2 を見よ。
- ⛔ **語を意図の中に書くこと。** スキーマが拒む。**そしてスキーマが正しい。**
- ⛔ **値域を書くこと。** 安全の外殻は実行時のホストのものである。
- ⛔ **送った後に、それに合わせて行を書くこと。** 行は意図的に、先に書かれる。
- ⛔ **機体へ届くこと。** このリポジトリの何も、ポートを開かない。

## このスキルにできないこと

**その運動が正しいかどうかを言うこと。** 機構は検査できる。**目標は検査できない。** ⚠️ **緑の検査は、機構が命じられたとおりに計算したことを意味する**——それ以上ではない。**その線が論じられているのは `docs/verification-boundary.md` である。**

⛔ **そして写像そのものに検査は無い。** `tools/check_vocabulary.py` が読むのは表の形であって、**表の真偽ではない。** **書き手の判断を通る往復だけが、検査を持たない段である。**
