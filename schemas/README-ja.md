# schemas/

**境界の型は、ここに住む。** いまは1本だけである。

```
motion-intent.schema.json     Motion Intent——D-06
```

## 型が、境界である

**上流は何をしてもよい。下流は関数でなければならない。** 人を1人含むセッションが、**Skill に導かれて、自然言語で意図を書く。** **コードがそれを読み、計算する。** **それが、軌道を検査可能にしているものである。**

**draft 2020-12、既定で閉じている。** **両方のオブジェクトに `additionalProperties: false`**——**知らない欄は、黙って無視されるのでなく誤りになる。** **これは設計ノートが記録している作法であり、2つの既定のうち安全なほうである**——**欄の名前の打ち間違いが、無視されずに大きく落ちる。**

## 開いたままの、ただ1つの欄

⛔ **`moves[].quality` は意図して開いてある。そして、それだけである。**

**値の型がまだ決まっていない欄を閉じれば、書けなくなる。** **だが、決まっていないのに決まったふりをして開けておくのは、もっと悪い**——**値が入り、誰も読まず、全員が何かが起きたと思う。**

**ゆえに境界は両側から押さえてあり、両側とも検査されている:**

| 側 | すること | 押さえている検査 |
|---|---|---|
| スキーマ | 欄を**受け取る**。値は任意のオブジェクト | `test_the_open_field_accepts_any_object` |
| コード | **持ち運ばない**——`engine/intent.py` は `Move` をこれ抜きで組む | `test_the_open_field_is_accepted_and_ignored` |

**型と語彙の衝突に、住所を与えたのがここである。** **消してはいない**——**欄が在るのは、それを埋めるはずの語彙が無いからである。** **止めているのは、機体の応答を要する決定と、セッションの無いときの Pet についての問いである**——**どちらも開いている。**

**語→値写像が入る日、表の2行目が変わる。** **スキーマは欄を持ち続け、コードがそれを読み始める。** **いま「コードは無視する」と主張している検査は、その日に消すのではなく書き換えなければならない形で書いてある。**

## 意図して型に入れていないもの

- ⛔ **`target` の許される範囲。** これはフィードバック駆動であり、プロトコルから読み出せる定数ではない。**そして、実行時にホストが渡す安全包絡に属する。** **同じ数を2箇所に持つと、そうやって食い違う。**
- ⛔ **速度・加速度・ジャークの上限。** 理由は同じで、もう1つある——**調査が見つけた唯一のジャークの数値は、それが引用された規格に帰属させられなかった。** **このリポジトリは、発明した定数をスキーマに入れない。**
- **軸とモーターの対応。** **3つの自由度の名前は我々のものである。** **制御箱は正準の対応を記録しておらず、各軸の符号は配線に依存する。** **このファイルの名前は名札である。**
- **時間についての一切。** **ホストがどれだけ待つか、周期はいくつか、ループが締め切りに乗っているか**——**どれも型には無い。** **そのうち2つは、意図ではなくホストの実測された性質である。**

## 手で検証する

```python
import json, jsonschema
jsonschema.validate(json.load(open("intent.json")),
                    json.load(open("schemas/motion-intent.schema.json")))
```

⚠️ **`jsonschema` が要るのは、型を読み込むときであって、軌道を計算するときではない。** **`engine/trajectory/` の中核は、算術以外の何でもない。**
