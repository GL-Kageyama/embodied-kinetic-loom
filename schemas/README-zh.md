# schemas/

**边界类型住在这里。** 目前只有一份。

```
motion-intent.schema.json     Motion Intent——D-06
```

## 类型就是边界

**它的上游可以任意变化；它的下游必须是函数。** **一个有人在场的会话，在 Skill 的引导下用自然语言写出意图。** **代码读取它并计算。** **这正是使轨迹可检验的东西。**

**draft 2020-12，默认关闭。** **两个对象上都写了 `additionalProperties: false`**——**未知的栏位是错误，而不是被默默忽略。** **这是设计笔记记录下来的作法，也是两种默认里较安全的一种**——**栏位名的笔误会大声失败，而不是被无视。**

## 唯一一个保持敞开的栏位

⛔ **`moves[].quality` 是有意敞开的。而且只有它。**

**关掉一个值类型尚未决定的栏位，就等于让人写不出来。** **但假装已经定下来、却把它敞着，更糟**——**值填了进去，没人读它，而所有人都以为它起了作用。**

**因此边界从两侧被按住，而且两侧都有测试:**

| 侧 | 做什么 | 由哪项测试按住 |
|---|---|---|
| 模式 | **接受**该栏位，值可以是任意对象 | `test_the_open_field_accepts_any_object` |
| 代码 | **不携带它**——`engine/intent.py` 构造 `Move` 时不含它 | `test_the_open_field_is_accepted_and_ignored` |

**类型与词汇表之间的冲突，就是在这里被给了地址。** **它并没有被抹掉**——**该栏位之所以存在，正是因为本该填满它的词汇表还不存在。** **挡住它的，是一个需要机体回应的决定，以及一个关于没有会话时 Pet 的问题**——**两者都还敞着。**

**词到值的映射落地的那一天，表格的第二行会改变。** **模式继续保有该栏位，代码开始读它。** **如今主张「代码忽略它」的那项测试，写成了在那一天必须被改写、而不是被删除的形式。**

## 有意不放进类型里的东西

- ⛔ **`target` 的容许范围。** 它由反馈驱动，不是能从协议里读出来的常数，**而且它属于运行时由主机提供的安全包络。** **把同一个数字放在两处，两者就是这样开始分歧的。**
- ⛔ **速度、加速度、加加速度的任何上限。** 理由相同，另有一条——**调研找到的唯一一个加加速度数值，无法归属于它被引用的那份标准。** **本仓库不把发明出来的常数放进模式。**
- **轴与马达的对应。** **三个自由度的名字是我们的。** **控制箱没有记录任何正准的对应，每个轴的符号取决于配线。** **这个文件里的名字是标签。**
- **关于时间的一切。** **主机等多久、周期是多少、循环是否踩在截止时刻上**——**都不在类型里。** **其中两项是主机的实测性质，不是意图的。**

## 手工验证

```python
import json, jsonschema
jsonschema.validate(json.load(open("intent.json")),
                    json.load(open("schemas/motion-intent.schema.json")))
```

⚠️ **需要 `jsonschema` 的是读入类型的时候，不是计算轨迹的时候。** **`engine/trajectory/` 里的核心，只是算术，别无其他。**
