**このファイルは、以前「1つも無い」と書いていた。** **最初のテストと同じコミットで変わった**——**`CLAUDE.md` のあの節が定め、このディレクトリが支えている規則が、それである。**

## 5つの検査と、それぞれの居場所

| # | 検査 | 居場所 | ⚠️ 同時に記録していること |
|---|---|---|---|
| **1** | 端——位置・速度・加速度が両端でゼロ | `test_profile.py`, `test_plan.py` | ⛔ **台形はこれに落ちる**——両端で加速度がゼロでない |
| **2** | 制限の非超過——軸ごと**と合成** | `test_limits.py` | ⛔ **台形はこれにも落ちる**——角でジャークが定義されない |
| **3** | 可到達性——消える区間 | `test_profile.py`, `test_admit.py` | **異物である: 正しい軌道が存在しない場合を扱う** |
| **4** | 決定論 | `test_plan.py`, `test_purity.py` | 2回走らせて比べるだけでは足りない——下を見よ |
| **5** | Safety が弾くべきものを弾く | `test_admit.py` | ⚠️ **計画時の側だけである。** 実行時の門はまだ無い |

**5つのうち2つは否定的な主張であり、そこが要点である。** **フォールバックはフォールバックとして書かれている。これらの検査は「それを選ぶことが検査を1つ外すこと」を記録する。** **無ければ、その1つは静かに消える。**

## 5つのうちに入らない検査

**`test_intent.py` は、境界を両側から押さえている。** **型の `quality` 欄は、スキーマが受け取り、コードが無視する**——**そして両方が主張されている。片側だけなら境界は崩れる。** **語彙が入る日、後半は消すのでなく書き換えられる。**

## なぜ決定論を静的に見るのか

**`test_purity.py` は `engine/` の全ファイルの import を読み、`random`・`time`・`os`・`socket`・LLM のクライアントのどれかがあれば落ちる。**

**同じ入力を2回走らせて比べても、証明にはならない。** **その2回が、たまたま一致しただけかもしれない。** **見るべきは import であり、AST はそれを、grep が docstring の中の語を見つける場所で見つける。**

## このディレクトリを支えている規則——**我々自身に適用する**

**`CLAUDE.md` の Tests 節は、テストファイルがディスクに在るのに「まだ何も無い」と書いていてはいけない。**

**それは仮定の話ではない**——**姉妹の1本が、いまそうなっている**——**7ファイル・54テストがディスクに在り、`CLAUDE.md` は今も「未整備」と書いている。** **ゆえにここで最初のテストが入ったとき、あの節は同じコミットで変わった。** **ディレクトリを読むのでなく説明している節は、そうやって生まれる。**
