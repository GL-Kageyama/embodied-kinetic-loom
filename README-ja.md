# embodied-kinetic-loom

**意図が運動になり、運動はファイルを出て行く。**

この工房の他の織機は、ファイルを書いて止まる。画像はディスクに書かれ、音声はディスクに書かれ、ショット表はディスクに書かれる——**そしてファイルは、焼き直せるし、切り直せるし、消せる。** **運動は、部屋の中で起きた出来事である。** それは一度だけ、そこに居合わせた者の前で起き、取り消せない。**取り消しも、2本目のテイクも、誰かが起きたことを書き残していない限り後からもう一度見る方法も無い。**

このリポジトリは、その一つの違いを中心に組まれている。

## 主張

**再現できるものと揺れてよいものの境界は、1つの型——`Motion Intent` に引かれ、それを機械が読む。**

その型より上流は自由である。揺れてよいし、判断であってよいし、人が居るセッションから出てきてもよい。**その型より下流は、関数でなければならない——同じ入力なら、毎回同じ出力である。** **補間・イージング・平滑化・制限がこのエンジンの核心であり、モデル呼び出しではない。**

これは有利な位置であり、はっきり書く値がある——**軌道は関数なので、軌道は厳密に検査できる。** この工房が作るもののうち、そう言えるものはほとんど無い。**検査できないのは、その結果が生きているかどうかである**——**そしてこのリポジトリは、そうでないふりをしない。** `CLAUDE.md` は最初のコミットでそう書いた——**検査が1つも緑になっていないうちに。**

## 今日あるもの

⚠️ **器と、その中の決定論的な核心——そして動くものは何も無い。**

このリポジトリが持っているのは、このエンジンが*何であるか*、これから動かす機体について決して前提にしてはならないこと、どの検査が存在するか、そして計算する部分である——**`Motion Intent` の型とそのスキーマと読み手、軌道の族、イージング、平滑化、計画、制限の包絡、そして受理。** **バックエンドも、Mock も、物理の機械を動かした1行も、持っていない。**

この最後の点は、主張ではなく実測である。この工房自身の Python 143本を `import hid`・`hidapi`・`pygame`・`joystick`・`evdev`・`pyserial`・`import serial`・`IOHID` で走査して、**0件**だった。

⚠️ **核心は緑である**——**8ファイル・80テスト、実測 2026-09-27**——**そして緑は、機構が「言われたとおりに計算した」ことを意味する。** **何かが「そこに居る」ことについては、何も意味しない。**

## 骨組み

```
.claude-plugin/     plugin.json と marketplace.json——1つの版を運ぶべき2つのファイル
docs/               文書。英語が正典で、-ja と -zh のミラーが隣に並ぶ
tools/              check_i18n.py——ミラーを読む検査
tests/              試験——8ファイル・80テスト
schemas/            motion-intent.schema.json——Motion Intent の型
engine/             決定論的な核心。⚠️ LLM を呼ばず、揺れるものを import しない
skills/             ⚠️ まだ無い——Skill 1本。止まっている
references/         ⚠️ まだ無い——運動の語彙。一部が止まっている
projects/           作品と記録。⚠️ まだ無い——記録は機体が来てから始まる
```

**作品と記録の置き場は `projects/` だけである。`examples/` は無い。** ⚠️ **単位は意図的に決めていない**——**1回の反応も、1日のセッションも、Pet の一生も、同じ器に入る。**

## まだ無いもの

- **バックエンドも Mock も無い。** 核心は軌道を計算する。**それを送るものは無い。** ⚠️ **そして制限の検査は計画時に走る——実際に出て行くものを門で見る段は、まだ無い。**
- **`skills/` が無い。** Skill 1本は決まった。**中身は、まだ開いている問い——*セッションが動いていないとき、誰が書くか*——で止まっている。**
- **`references/` が無い。** 運動の語彙は調査として存在する。**出発点の動詞5つ——傾く／倒れる／沈む／跳ねる／後退——のうち3つが、この機体に無い自由度を指している。ゆえに3つは、まだ書けない。**
- **`install.sh` が無い。** 姉妹リポジトリと同じ書き方をすると、その書き方は Skill の存在を事前に検証する——**ゆえに Skill より先には書けない。**
- **`assets/repo-hero.png` が無い。** 表紙の絵は「何のリポジトリか」を言う。**その1文は、このファイルができるまで存在しなかった。**

## 次

1. **送る側**——バックエンドと Mock、そして出て行く1フレームごとを門で見る段。⚠️ **これだけが機体待ちである**——制御箱には2世代あり、プロトコルがその間で違う。
2. **`skills/`**——Skill 1本は決まった。**中身は、まだ開いている問い——*セッションが動いていないとき、誰が書くか*——で止まっている。** **その問いは著者のものであり、このリポジトリのものではない。**
3. **`references/`**——運動の語彙。**出発点の動詞5つのうち3つが、この機体に無い自由度を指している。それをどう渡すかも、著者のものである。**

⚠️ **2と3は機体待ちではない。決定待ちである。機体が止めているのは1だけである。** **そして、どれを終えても「そこに何かがいるか」については何も主張できない。**

## 言語

**英語が正典で、`-ja` と `-zh` のミラーが同じディレクトリに並ぶ**（接尾辞方式——サブフォルダにはしない。**サブフォルダは深さを変え、深さが変わると文書の中の相対パスが全部ずれる**）。`tools/check_i18n.py` がこれを読む。

**この工房の作業言語は日本語である**——**ゆえに `HISTORY.md` とコミットメッセージは日本語で書く。** **それは文書の正典の言語とは、別の話である。**
