# embodied-kinetic-loom

<p align="center">
  <img src="assets/repo-hero.png" width="100%" alt="embodied-kinetic-loom">
</p>

**意図が運動になり、運動はファイルを出て行く。**

この工房の他の織機は、ファイルを書いて止まる。画像はディスクに書かれ、音声はディスクに書かれ、ショット表はディスクに書かれる——**そしてファイルは、焼き直せるし、切り直せるし、消せる。** **運動は、部屋の中で起きた出来事である。** それは一度だけ、そこに居合わせた者の前で起き、取り消せない。**取り消しも、2本目のテイクも、誰かが起きたことを書き残していない限り後からもう一度見る方法も無い。**

このリポジトリは、その一つの違いを中心に組まれている。

## 主張

**再現できるものと揺れてよいものの境界は、1つの型——`Motion Intent` に引かれ、それを機械が読む。**

その型より上流は自由である。揺れてよいし、判断であってよいし、人が居るセッションから出てきてもよい。**その型より下流は、関数でなければならない——同じ入力なら、毎回同じ出力である。** **補間・イージング・平滑化・制限がこのエンジンの核心であり、モデル呼び出しではない。**

これは有利な位置であり、はっきり書く値がある——**軌道は関数なので、軌道は厳密に検査できる。** この工房が作るもののうち、そう言えるものはほとんど無い。**検査できないのは、その結果が生きているかどうかである**——**そしてこのリポジトリは、そうでないふりをしない。** `CLAUDE.md` は最初のコミットでそう書いた——**検査が1つも緑になっていないうちに。**

## 今日あるもの

⚠️ **器と、決定論的な核心、送る側——ただしシリアルポートの手前まで——そして、唯一の書き手。**

このリポジトリが持っているのは、このエンジンが*何であるか*、これから動かす機体について決して前提にしてはならないこと、どの検査が存在するか、そして計算して送る部分である——**`Motion Intent` の型とそのスキーマと読み手、軌道の族、イージング、平滑化、計画、制限の包絡、受理**——**そして、出て行くものをフレームに組み、1フレームごとに経過時間で門を通し、制御箱の Mock を周期ループで走らせるバックエンド。**

**そして、運動が1つ、端から端まで走る。** `python3 -m projects.pet --motion greeting` は、**意図をディスクから読み、受理し、軌道を計算し、門を通し、Mock へ送る**——**そして、同じ時計の、同じ刻みから顔を描く。** ⚠️ **この1文が、この作業の全部である。そして、説明ではなく検査で押さえてある**: Pet の5つの顔のうち2つは同じ図なので、*顔と身体は1つの時計から*は好みではない——**2つの状態を分けている唯一のものである。**

⛔ **そのうち1バイトも、機体へは行っていない。** これは主張ではなく実測である。この工房自身の Python 143本を `import hid`・`hidapi`・`pygame`・`joystick`・`evdev`・`pyserial`・`import serial`・`IOHID` で走査して、**0件**だった。**バックエンドは、意図的に1層手前で止まっている**——下を見よ。

**そして、書き手が在る。** `skills/embodied-kinetic-loom/` が持つのは、その1本である——**`Motion Intent` を書く唯一のものである。** ⛔ **これは文書であって、プログラムではない。このリポジトリのコードはモデルを呼ばず、それこそが、その下の軌道を検査可能にしている。** 語の出どころは `references/README.md` であり、⚠️ **2026-09-28 現在、あのファイルは固定の表ではなく写像である**——**行として書かれ、名前で引かれ、使われることで育つ。それが育つ唯一の道である。** ⛔ **誰が引くかが、この問いの全部である——プログラムではなく Claude である**——**ゆえに正典の形は、読む者が読む表であり、機械専用の2つ目は作らない。読むものが無いからである。**

⚠️ **核心とバックエンドと Pet の画面と Pet の運動は緑である**——**22ファイル・267テスト、実測 2026-09-28**——**そして緑は、機構が「言われたとおりに計算した」ことを意味する。** **何かが「そこに居る」ことについては、何も意味しない。**

## 骨組み

```
.claude-plugin/     plugin.json と marketplace.json——1つの版を運ぶべき2つのファイル
docs/               文書。英語が正典で、-ja と -zh のミラーが隣に並ぶ
tools/              check_i18n.py——ミラー。check_vocabulary.py——語彙の表。purity.py——禁止輸入の一覧
tests/              試験——22ファイル・267テスト
schemas/            motion-intent.schema.json——Motion Intent の型
engine/             決定論的な核心。⚠️ LLM を呼ばず、揺れるものを import しない
engine/backend/     送る側——プロトコル、周期、門、軸の対応、送信、Mock
skills/             唯一の書き手——Motion Intent を書く Skill
references/         運動の語彙——行として書かれ、名前で引かれ、使われることで育つ
assets/             このリポジトリの顔（README の hero）
locales/            プログラム自身の言葉——en / ja / zh
projects/pet/       Pet——5つの顔、それを運ぶフレーム、そして走る運動
install.sh          Skill を入れる（--local は .claude/skills/ へ。それはコミットされる）
```

**作品と記録の置き場は `projects/` だけである。`examples/` は無い。** ⚠️ **単位は意図的に決めていない**——**1回の反応も、1日のセッションも、Pet の一生も、同じ器に入る。**

⚠️ **`projects/pet/` は、そこに住む最初のものである。** 5つの顔は概念文書から逐語で写してあり、**Pet が猫なのは既定ではなく決定である**——**その2つの決定は、あのディレクトリの README に記録してある。** **核心と画面は、いま繋がっている**: `motions/greeting.json` はセッションが書いた `Motion Intent` であり、**`motion.py` がそれを受理・門・Mock へ通しながら、顔を同じ刻みから描く。**

## まだ無いもの

- **シリアル層が無い。** バックエンドは組み、門を通し、送り出す——**だが、ポートを開くものは無い。** ⛔ **機体が握っているのは、この1層だけである**——制御箱には2世代あり、プロトコルがその間で違う——**そして、Mock と実機が最も食い違うのが、まさにそこである。**
- ⚠️ **語彙が持つのは1行であって、5行ではない。** **出発点の動詞5つ——傾く／倒れる／沈む／跳ねる／後退——のうち3つが、この機体に無い自由度を指している。** **そして写像は、差が何であるかを言う明示の欄を持つ。** ⛔ **欠けている4行は、使われなかったものである**——**いま書けば、1度も走っていないものを書くことになる。**
- ⚠️ **起きたことの記録が無い。** `--motion` は数を印字し、それは流れ去る。**記録の器は `projects/` である**（`CLAUDE.md` を見よ）——**それは空であり、空なのは、機体が唯一の観察を握っているからである。**

## 次

1. **シリアル層**——**針金へ届く唯一の段である。** ⛔ **機体待ち**: どの世代の制御箱が手元にあるかを確かめるまで、**このリポジトリのものを含め、どのプロトコル文書も信用しない。**
2. **2つ目の運動**——語彙は5つの動詞から始まる。⚠️ **そのうち3つは、この機体が持たない並進を指している——ゆえにまだ1行も、差の欄を渡っていない。** **その欄がどう振る舞うかは、1度も確かめられていない。**

⚠️ **機体が止めているのは1だけである。2は仕事待ちである。** **そして、どちらを終えても「そこに何かがいるか」については何も主張できない。**

## 言語

**英語が正典で、`-ja` と `-zh` のミラーが同じディレクトリに並ぶ**（接尾辞方式——サブフォルダにはしない。**サブフォルダは深さを変え、深さが変わると文書の中の相対パスが全部ずれる**）。`tools/check_i18n.py` がこれを読む。

⚠️ **プログラム自身も3言語を話す。** `--lang {en,ja,zh}`——または `EMBODIED_KINETIC_LOOM_LANG` 環境変数——が、Pet が印字するものの言語を決める。**既定は `en`。** 文字列は `locales/` に在り、**核はそこへ届かない**: 核はコードを返し、文にするのは縁である。

**この工房の作業言語は日本語である**——**ゆえに `HISTORY.md` とコミットメッセージは日本語で書く。** **それは文書の正典の言語とは、別の話である。**
