# embodied-kinetic-loom

**意图变成运动，而运动离开文件。**

本工房的其他织机写到文件为止。图像写入磁盘，音频写入磁盘，镜头表写入磁盘——**而文件可以重渲、可以重剪、可以删除。** **运动是房间里发生的事件。** 它只发生一次，就在场的人面前，而且无法撤回。**没有撤销，没有第二条，除非有人把发生的事写下来，否则事后也无从再看一次。**

本仓库正是围绕这一个差异搭建的。

## 主张

**可再现之物与可浮动之物的边界，划在一个类型上——`Motion Intent`——由机械读取它。**

该类型之上是自由的：可以浮动，可以是判断，也可以来自一个有人在其中的会话。**该类型之下必须是函数——同样的输入，每次同样的输出。** **插值、缓动、平滑、限幅才是这个引擎的核心，而不是模型调用。**

这是一个有利的位置，值得明说——**轨迹是函数，所以轨迹可以被严格检验。** 本工房所造之物中，能这样说的极少。**无法检验的，是那结果是否活着**——**而本仓库不假装不是这样。** `CLAUDE.md` 在第一次提交里就这样写了——**在任何一项检查变绿之前。**

## 今天有什么

⚠️ **容器、决定论的核心，以及送出的一侧——但停在串口之前。**

本仓库持有的是：这个引擎*是什么*、关于即将驱动的机体绝不可当作前提的事、存在哪些检查，以及那个负责计算并送出的部分——**`Motion Intent` 的类型及其模式与读取器、轨迹族、缓动、平滑、规划、限制包络、准入**——**以及一个后端：把要离开之物切成帧，对每一帧按实测算出的经过时间设门，并以周期循环驱动控制箱的 Mock。**

⛔ **其中没有任何一个字节到达过机体。** 最后这一点是实测，不是主张。用 `import hid`、`hidapi`、`pygame`、`joystick`、`evdev`、`pyserial`、`import serial`、`IOHID` 扫描本工房自写的 143 个 Python 文件，结果为 **0 件**。**后端有意在离导线一层之前停住**——见下文。

⚠️ **核心与后端是绿的**——**15 个文件、160 项测试，实测 2026-09-27**——**而绿意味着机构「按被吩咐的那样算了」。** **对于是否有东西「在那里」，它什么也不意味。**

## 骨架

```
.claude-plugin/     plugin.json 与 marketplace.json——必须承载同一个版本的两个文件
docs/               文档。英语为正典，-ja 与 -zh 镜像并列其旁
tools/              check_i18n.py——读取镜像的检查
tests/              测试——15 个文件、160 项测试
schemas/            motion-intent.schema.json——Motion Intent 的类型
engine/             决定论的核心。⚠️ 不调用 LLM，也不 import 任何会浮动之物
engine/backend/     送出的一侧——协议、周期、门、轴对应、发送器、Mock
skills/             ⚠️ 尚无——一个 Skill，处于停滞
references/         ⚠️ 尚无——运动的语汇，部分处于停滞
projects/           作品与记录。⚠️ 尚无——记录要等机体到来才开始
```

**作品与记录的存放处只有 `projects/`。没有 `examples/`。** ⚠️ **单位是有意不定的**——**一次反应、一天的会话、Pet 的一生，都进入同一个容器。**

## 还没有的东西

- **没有串口层。** 后端负责切帧、设门、送出——**但没有任何一处打开端口。** ⛔ **机体唯一握着的就是这一层**——控制箱有两个世代，协议在两者之间不同——**而 Mock 与实机分歧最大的地方，恰恰就在这里。**
- **没有 `skills/`。** 一个 Skill 已经定了；**内容停在一个仍然敞开的问题上——*会话没有运行时，谁来写*。**
- **没有 `references/`。** 运动的语汇作为调查存在。**出发点的五个动词——傾く／倒れる／沈む／跳ねる／後退——之中有三个指向本机体没有的自由度，因此有三个还写不出来。**
- **没有 `install.sh`。** 按姊妹仓库的写法，那种写法会预先验证 Skill 是否存在——**因此在 Skill 之前写不出来。**
- **没有 `assets/repo-hero.png`。** 封面图说的是「这是什么仓库」。**而那句话，在这个文件出现之前并不存在。**

## 接下来

1. **串口层**——**唯一触到导线的一步。** ⛔ **在等机体**：在确认手上是哪一代控制箱之前，**不要相信任何协议文档，包括本仓库的。**
2. **`skills/`**——一个 Skill 已经定了；**内容停在一个仍然敞开的问题上——*会话没有运行时，谁来写*。** **那个问题是作者的，不是本仓库的。**
3. **`references/`**——运动的语汇。**出发点的五个动词中有三个指向本机体没有的自由度，而如何把它们渡过去，同样属于作者。**

⚠️ **第 2、3 步不是在等机体，而是在等决定。机体卡住的只有第 1 步。** **而完成其中任何一步，都不能对「那里是否有某种存在」作出任何主张。**

## 语言

**英语为正典，`-ja` 与 `-zh` 镜像并列在同一目录**（接尾辞方式——不使用子文件夹。**子文件夹会改变深度，而深度一变，文档内所有相对路径都会错位**）。`tools/check_i18n.py` 读取它们。

**本工房的工作语言是日语**——**因此 `HISTORY.md` 与提交信息用日语书写。** **那是与文档正典语言不同的另一回事。**
