# embodied-kinetic-loom

<p align="center">
  <img src="assets/repo-hero.png" width="100%" alt="embodied-kinetic-loom">
</p>

**意图变成运动，而运动离开文件。**

本工房的其他织机写到文件为止。图像写入磁盘，音频写入磁盘，镜头表写入磁盘——**而文件可以重渲、可以重剪、可以删除。** **运动是房间里发生的事件。** 它只发生一次，就在场的人面前，而且无法撤回。**没有撤销，没有第二条，除非有人把发生的事写下来，否则事后也无从再看一次。**

本仓库正是围绕这一个差异搭建的。

## 主张

**可再现之物与可浮动之物的边界，划在一个类型上——`Motion Intent`——由机械读取它。**

该类型之上是自由的：可以浮动，可以是判断，也可以来自一个有人在其中的会话。**该类型之下必须是函数——同样的输入，每次同样的输出。** **插值、缓动、平滑、限幅才是这个引擎的核心，而不是模型调用。**

这是一个有利的位置，值得明说——**轨迹是函数，所以轨迹可以被严格检验。** 本工房所造之物中，能这样说的极少。**无法检验的，是那结果是否活着**——**而本仓库不假装不是这样。** `CLAUDE.md` 在第一次提交里就这样写了——**在任何一项检查变绿之前。**

## 今天有什么

⚠️ **容器、决定论的核心、送出的一侧——但停在串口之前——以及唯一的写者。**

本仓库持有的是：这个引擎*是什么*、关于即将驱动的机体绝不可当作前提的事、存在哪些检查，以及那个负责计算并送出的部分——**`Motion Intent` 的类型及其模式与读取器、轨迹族、缓动、平滑、规划、限制包络、准入**——**以及一个后端：把要离开之物切成帧，对每一帧按实测算出的经过时间设门，并以周期循环驱动控制箱的 Mock。**

**而如今，有一个动作从头到尾跑通了。** `python3 -m projects.pet --motion greeting` **从磁盘读出意图，准入它，算出轨迹，过门，送到 Mock**——**并从同一个时钟、同一个刻点，画出脸。** ⚠️ **这一句就是这件事的全部。而它是被断言下来的，不是被描述出来的**：Pet 的五张脸里有两张是同一幅画，所以*脸与身体出自同一个时钟*不是偏好——**它是把两个状态分开的唯一一样东西。**

⛔ **其中没有任何一个字节到达过机体。** 最后这一点是实测，不是主张。用 `import hid`、`hidapi`、`pygame`、`joystick`、`evdev`、`pyserial`、`import serial`、`IOHID` 扫描本工房自写的 277 个 Python 文件（已排除供应商的树），结果为 **0 件**。**后端有意在离导线一层之前停住**——见下文。

**而写者现在存在了。** `skills/embodied-kinetic-loom/` 持有那一本——**写出 `Motion Intent` 的唯一之物。** ⛔ **它是文档，不是程序：本仓库的代码不调用模型，而正是这一点让它下面的轨迹可以被检查。** 它的词的来源是 `references/README.md`，而 ⚠️ **截至 2026-09-28，那个文件是映射，不是固定的表**——**以行写出，以名字取用，在使用中生长，而这是它生长的唯一道路。** ⛔ **由谁来取，才是这个问题的全部——是 Claude，不是程序**——**所以正典的形式是读者读的表，而不会做第二个只有机器用的副本：没有东西会读它。**

✅ **而 2026-10-18，为了机器 2，电线之上多了一层。** `projects/stackchan/` 把 Claude Code 的钩子事件变成六个阶段、Pet 的五张脸、六种光和五个身势——⛔ **而它选择的每一个身势都是一个词，那台机器的数字一个也不在包里。** **当两个以上的窗口同时运行时，脖子也只用在一个窗口上。** 它是 Stack-chan 路线中，在烧写固件之前就能检查的部分。 ⚠️ **将要保住其状态的守护进程现在有了**——`projects/stackchan/daemon/`，一个纯核心和一个套接字边缘——**而钩子会运行的客户端也有了**——`projects/stackchan/hook/`，一个事件一个进程，沉默地以 0 退出。✅ **两者都在 2026-10-18 被安装**: launchd 用户代理在登录时启动守护进程，而 `~/.claude/settings.json` 的全部三十三个钩子事件都调用客户端。✅ **同一天，电线作为源码存在了**——`engine/backend/protocol_stackchan.py` 组装一行 ASCII，`schemas/stackchan-command.schema.json` 是两端共读的契约。✅ **传输路径选定了**——`--port`，每帧一次 `os.open`/`os.write`/`os.close`，安装的 plist 点名了板子的控制台——**而机体那一端会演出它收到的东西**：五个姿态是在这台个体上由作者的眼睛测得的，所以承载身势的帧会转动头部（`projects/stackchan-firmware/records/2026-10-18-the-gestures.md`）。⛔ **`sent: true` 说的是主机的 tty 收下了这行，不是板子收到了它**——送达只被证明过一次，靠板子自己的控制台把帧打印出来，而这里什么都不读回。⛔ **而电线仍然不运来自这一层的任何数字**——它运的是词，机体把词变成计数。✅ **2026-10-18 发生的事更窄，但它确实发生了**: `projects/stackchan-firmware/` 被构建，写在 `0x510000`，头转动了——**靠打入其控制台的一条台架命令**; 然后，来自本仓库之外一个工具的 `pose` 流让它转了 678 次，零拒绝; 然后十二颗 LED 跟随了一个词; 最后，五个身势从真实的帧里演出。**引擎本身在这台机器上仍然一次也没有跑过。** 记录在 `projects/stackchan-firmware/records/` 下。

⚠️ **核心、后端、Pet 的画面与运动、Stack-chan 的行为层及其守护进程、外发的帧与电线是绿的**——**28 个文件、439 项测试，实测 2026-10-18**——**而绿意味着机构「按被吩咐的那样算了」。** **对于是否有东西「在那里」，它什么也不意味。**

## 在把机体接上之前

⛔ **这里没有任何东西会打开端口，也没有任何东西能停下马达。** 如果你正要把控制箱插进计算机，先读 **[`docs/first-contact.md`](docs/first-contact.md)**——**第一个小时要了结的四个问题、让 Backend 设计悬置的那一个检查，以及任何文档都了结不了的、关于机体的九件事。**

⚠️ **这是清单，没有任何东西会让它响**——**那份代价写在页面上。** **它为之而存在的是机体到来的那天**——**站在箱子前、从设计笔记里把这一切重新拼出来，正是它要防的那个局面。**

## 骨架

```
.claude-plugin/     plugin.json 与 marketplace.json——必须承载同一个版本的两个文件
docs/               文档。英语为正典，-ja 与 -zh 镜像并列其旁
tools/              check_i18n.py——镜像。check_vocabulary.py——语汇的表。purity.py——禁止输入清单
tests/              测试——28 个文件、439 项测试
schemas/            motion-intent.schema.json——Motion Intent 的类型。stackchan-command.schema.json——通往机器 2 的帧。stackchan-pose.schema.json——每个刻度的姿势行
engine/             决定论的核心。⚠️ 不调用 LLM，也不 import 任何会浮动之物
engine/backend/     送出的一侧——协议、周期、门、轴对应、发送器、Mock
skills/             唯一的写者——写出 Motion Intent 的那个 Skill
references/         运动的语汇——以行写出，以名字取用，在使用中生长
assets/             本仓库的脸（README 的 hero）
locales/            程序自己的话——en / ja / zh
projects/pet/       Pet——五张脸、承载它们的帧，以及跑起来的运动
projects/stackchan/ 电线之上的层——从事件到阶段、脸与光；没有机器 2 的数字
projects/stackchan-firmware/  那条电线的机体一端——已构建、已烧写，2026-10-18 有一次台架移动
install.sh          安装这个 Skill（--local 写进 .claude/skills/，那一份会被提交）
```

**作品与记录的存放处只有 `projects/`。没有 `examples/`。** ⚠️ **单位是有意不定的**——**一次反应、一天的会话、Pet 的一生，都进入同一个容器。**

⚠️ **`projects/pet/` 是住进那里的第一件东西。** 五张脸是从概念文档逐字抄来的，**Pet 是猫不是默认，而是决定**——**那两个决定记录在那个目录的 README 里。** **核心与画面如今接上了**：`motions/greeting.json` 是一次会话写下的 `Motion Intent`，**而 `motion.py` 把它带着穿过准入、门与 Mock，同时从同一个刻点画出脸。**

✅ **`projects/stackchan/` 是第二件。** 它把 Claude Code 的钩子事件映射到六个阶段、那五张脸和六种光——⛔ **并且什么也不发送，因为机器 2 的数字不在任何记录里。** **映射不需要测量；运动需要。** 它建在检查能响的那一侧，**是 Stack-chan 路线中，在烧写固件之前就能检查的部分。**

## 还没有的东西

- **没有串口层。** 后端负责切帧、设门、送出——**但没有任何一处打开端口。** ⛔ **机体唯一握着的就是这一层**——机器1的控制箱有两个世代，协议在两者之间不同——**而 Mock 与实机分歧最大的地方，恰恰就在这里。**
- ⛔ **没有通往机器 2 的传输路径，也没有一个帧到达那里。** 帧已经定了、被编码、被解码、被测试，**并作为它本该送出的那一行写进守护进程的日志**——**但它要走的路径尚未选定**，守护进程一根也不打开。⚠️ **如今固件所做的是拒绝**: 没有 `gesture → 角度` 的表，而猜出来的角度在源文件里与实测角度无法区分。✅ **它已经不再只有源码**——2026-10-18 它被构建、被写入，一条台架命令转动了头；**那是机体在动，不是一个帧在到达。**
- ⚠️ **语汇持有一行，不是五行。** **出发点的五个动词——倾倒／倒下／下沉／弹跳／后退——之中有三个指向机器1没有的自由度。** **而映射带一个明示的栏，说出那个差是什么。** ⛔ **缺的那四行，是没被用过的那些**——**现在写，就是把从未跑过的东西写下来。**
- ⚠️ **没有引擎跑过的记录，而有一份机体动过的记录。** `--motion` 打印出数字，随即被冲走。**记录的容器是 `projects/`**（见 `CLAUDE.md`）——✅ **而自 2026-10-18 起，那里有一份**: `projects/stackchan-firmware/records/2026-10-18-first-arrival.md`——**被观察到的东西是脊梁，程序的数字是引用在其中的证据。** ⛔ **那份记录是一条台架命令的记录，不是这套引擎的记录**——没有读 `Motion Intent`，没有计算轨迹，没有经过闸门。⛔ **而「机体一次都没有动过」从来不是缺的那样东西**——**作者手上的机体动过：是供应商的 SETUP 向导驱动的，而这件事在 2026-10-15 被看见了。** **一直缺的是抵达，而第一次抵达如今已经写下。**

## 语言

**英语为正典，`-ja` 与 `-zh` 镜像并列在同一目录**（接尾辞方式——不使用子文件夹。**子文件夹会改变深度，而深度一变，文档内所有相对路径都会错位**）。`tools/check_i18n.py` 读取它们。

⚠️ **程序自己也说三种语言。** `--lang {en,ja,zh}`——或者 `EMBODIED_KINETIC_LOOM_LANG` 环境变量——决定 Pet 打印出来的东西用哪种语言；**默认是 `en`。** 字符串住在 `locales/`，**而核心够不到它们**: 核心返回代码，把它们变成句子的是边缘。

**本工房的工作语言是日语**——**因此 `HISTORY.md` 与提交信息用日语书写。** **那是与文档正典语言不同的另一回事。**
