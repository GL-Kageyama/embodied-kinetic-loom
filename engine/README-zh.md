# engine/

**决定论的核心**——**插值、缓动、平滑、限幅。** 这四样是函数，**因此是这个工房能够严格检验的四样。**

## 这里有什么

```
intent.py           Motion Intent 的读取，以及针对 schemas/ 的验证
trajectory/
  profile.py        机体族——末端速度为零的曲线
  easing.py         表现族——CSS 的 cubic-bezier。⛔ 不交给机体
  smooth.py         不移动两端的平滑
  limits.py         逐轴上限，以及合成上限
  plan.py           轨迹，及其采样
  admit.py          通过或拒绝——只限计划时这一侧
```

## 为什么两个族住在两个模块里

**因为屏幕与机体，对曲线要求的是相反的东西。**

`Back`、`Elastic`、`Bounce` 在向前移动之前先向后加速。**在屏幕上那是「预备」；在机体上，那是反方向的加速度。** 因此表现族留在 `easing.py`，**只有机体族——`min-jerk` 与 `trapezoid`——能够交给 `plan`。**

⛔ **从一个族到另一个族的映射并不存在，而这个引擎不去发明它。** 设计笔记关于那个映射，**自己写着「那是提案，不是设计」。** 写在这里，就会变成这个仓库的发明。⇒ `easing.MAPPING_TO_MACHINE` 保持为 `None`，**并由一项测试看着它现在仍是 `None`**——**在有人写出它的那一天，让那项变更是有意的、可见的。**

## 是什么让它成为决定论的

**同样的输入，产出同样的位串。而这个主张由两种方式守着。**

- **`tests/test_purity.py` 读取 `engine/` 下每个文件的 import，其中若有 `random`、`time`、`os`、`socket` 或 LLM 客户端，就会失败。** **只跑两遍来比较是不够的**——**那两遍可能只是碰巧一致。** **该看的是 import。**
- **采样时刻是数出来的，不是累加出来的**——是 `duration * k / (count - 1)`，而不是 `t += step`。
- **`easing.py` 的二分法次数固定。** 若改用收敛判据，结果作为输入的函数就只剩名义上的了。

⚠️ **轨迹的两端是精确放置的。** 第一个采样就是给定的起点本身，最后一个是终点本身——**在浮点里 `start + (end - start)` 未必等于 `end`，** **而一条只差最后一个单位没到达目标的指令，就是没有到达的指令。**

## 关卡，与尚未决定的席位

**`admit.py` 是一个判定，不是一个位置。** **Safety 是层还是关卡尚未决定；无论哪种，这个函数都会被调用**——**文件名不叫 `safety.py` 正是为此。** 那样自称，就等于把仍然敞开的问题关上了。

⛔ **而且这只是计划时的那一侧。** **设计笔记明言：只有计划时的保证是不够的。** **运行时的关卡还不存在**——它需要机体和后端。

## 回退所支付的代价

**`trapezoid` 在五项检查中，有两项是结构上就过不去的——两端加速度不为零，角点上加速度的导数无定义。**

**那不是代码的缺陷。梯形剖面本来就是这样。** **但它意味着「选择回退」等于「关掉一项检查」**——**因此本仓库不把它留给发现，而是写进测试。** **设了加加速度上限，`admit` 就一台梯形也不放行；不设，就通过。**

## 这里没有的东西

**没有后端、没有 Mock、没有 Pet 的画面、没有声音。** 它们都需要机体的回应，**而这里的东西从未驱动过一台物理机器。** **也没有词到值的映射**——**本该填满类型中 `quality` 一栏的词汇表，停着。** **也没有运行时的监视。**

## 运行测试

```
python3 -m pytest tests/
```
