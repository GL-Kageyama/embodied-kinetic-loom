# engine/

**决定论的核心**——**插值、缓动、平滑、限幅。** 这四样是函数，**因此是这个工房能够严格检验的四样。**

## 这里有什么

```
intent.py           Motion Intent 的读取，以及针对 schemas/ 的验证
trajectory/
  profile.py        机体族——末端速度为零的曲线
  easing.py         表现族——CSS 的 cubic-bezier。⛔ 不交给机体
  smooth.py         不移动两端的平滑
  limits.py         逐轴上限，以及合成上限
  plan.py           轨迹，及其采样
  admit.py          通过或拒绝——只限计划时这一侧
backend/
  protocol.py       5 字节的帧。⛔ 三个危险，以及有意不写的那一个
  cycle.py          周期循环——截止是绝对时刻，时钟由外部传入
  gate.py           对实际离开之物设的门。⛔ 拒绝不是沉默
  axis_map.py       自由度→电机。⛔ 没有默认值——对应关系没有正准
  transmit.py       用墙上时钟拉轨迹——不是下一个采样，而是最近的一个
  mock.py           装作控制箱的东西。⚠️ 它是协议的测试，不是安全的测试
```

## 为什么两个族住在两个模块里

**因为屏幕与机体，对曲线要求的是相反的东西。**

`Back`、`Elastic`、`Bounce` 在向前移动之前先向后加速。**在屏幕上那是「预备」；在机体上，那是反方向的加速度。** 因此表现族留在 `easing.py`，**只有机体族——`min-jerk` 与 `trapezoid`——能够交给 `plan`。**

⛔ **从一个族到另一个族的映射并不存在，而这个引擎不去发明它。** 设计笔记关于那个映射，**自己写着「那是提案，不是设计」。** 写在这里，就会变成这个仓库的发明。⇒ `easing.MAPPING_TO_MACHINE` 保持为 `None`，**并由一项测试看着它现在仍是 `None`**——**在有人写出它的那一天，让那项变更是有意的、可见的。**

## 是什么让它成为决定论的

**同样的输入，产出同样的位串。而这个主张由两种方式守着。**

- **`tests/test_purity.py` 读取 `engine/` 下每个文件的 import，其中若有 `random`、`time`、`os`、`socket` 或 LLM 客户端，就会失败。** **只跑两遍来比较是不够的**——**那两遍可能只是碰巧一致。** **该看的是 import。**
- **采样时刻是数出来的，不是累加出来的**——是 `duration * k / (count - 1)`，而不是 `t += step`。
- **`easing.py` 的二分法次数固定。** 若改用收敛判据，结果作为输入的函数就只剩名义上的了。

⚠️ **轨迹的两端是精确放置的。** 第一个采样就是给定的起点本身，最后一个是终点本身——**在浮点里 `start + (end - start)` 未必等于 `end`，** **而一条只差最后一个单位没到达目标的指令，就是没有到达的指令。**

## 两道门，与尚未决定的席位

**`admit.py` 是一个判定，不是一个位置。** **Safety 是层还是关卡尚未决定；无论哪种，这个函数都会被调用**——**文件名不叫 `safety.py` 正是为此。** 那样自称，就等于把仍然敞开的问题关上了。

⛔ **而且这只是计划时的那一侧。** 它拿轨迹去核对限制，**对时钟一无所知。** **`backend/gate.py` 是另一侧**——**它看着离开的那一帧。而且经过时间是实测出来的，不是假设的。**

**只有运行时的门才看得见的东西，以及原因:**

| 什么 | 为什么计划时看不见 |
|---|---|
| **相邻两帧之间的落差** | ⛔ **上游固件既没有软启动也没有软停止。** 一条指令是否成为落差，**取决于它被送出的间隔**——而计划没有时钟 |
| **送出的时刻本身** | 计划是 `t` 的函数。它不知道 `now` |
| **某个自由度去哪个电机** | ⛔ 没有正准的对应，所以**门不去决定它**——由调用方传入 |

⛔ **而门最重的一个决定，是「拒绝的形状」：它不会什么都不返回。**

> **停止发送后，15 秒内扭矩会降到大约 1/4——而电机不会停。**

⇒ **因此拒绝会返回最后放行的那一组，并继续送它。** **在这台机体上，那是最接近「站着不动」的东西。** ⚠️ **而那也不是「停下」**——**协议里没有停止指令。** **门修不了这一点。它能做的，只是不把坏的那一帧送出去。**

⛔ **但仅仅保住会让轴冻住，而这一点是在写测试的过程中发现的。** 门的基准是*它最后放行的值*，而发送器提议的是*墙上时钟的值*——**提议会一直往前跑，所以差距永不闭合。** ⚠️ **而且每次拒绝都会推进门的时钟，于是它积攒的时间每次都被丢掉。** **一次拒绝之后，那根轴再也不动了。**

⇒ **因此被拒的轴会以门自己所允许的速度朝目标靠近**——`velocity × elapsed`，**也就是门本来就会放行的大小。** ⛔ **安全论证里不会进入任何新的假设；门称之为「阶跃」的最大大小，就变成它愿意取的最大大小。** ⚠️ **包络之外的目标仍然被保住，而不是被靠近**——**包络之外不是可以朝它移动的地方。**

⚠️ **门按组判定。** 一个一个电机地放行，**就会有谁也没规划过的组合出现在机体上。**

## 时钟不被 import

**`engine/` 不得 import `time`**——**因为读时钟的轨迹不是函数**（纯粹性检查守着这一点）。**因此周期循环从调用方接收 `now()` 与 `sleep()`。**

⚠️ **这并不只是为了满足纯粹性。** **让周期可被检验的，正是这一点**——**把时钟传进来，设计笔记只能写成*形状*的两条（「以截止方式书写」和「不要每次都调用 `sleep(period)`」）就成了运行时的主张。** `grep` 看得见那一行在源码里。**它看不见那一行跑起来时是否成立。**

⛔ **而且 `period` 没有默认值。** 笔记实测了**同一台机器会取 5 ms 与 10 ms 两种状态**。**把其中一个当作默认值，就等于把实测变成了常数。**

## 这里没有的东西

**没有串口层、没有 Pet 的画面、没有声音、没有词到值的映射、没有运行时的监视。**

⚠️ **机体唯一握着的就是串口层**——控制箱有两个世代，协议在两者之间不同——**而 Mock 与实机分歧最大的地方，恰恰就在这里**: `flush()` 被实测在 macOS 的 pty 上无限阻塞。**Mock 坐在串口层之上，所以 Mock 是绿的，对那一根线什么也没说。**

## 回退所支付的代价

**`trapezoid` 在五项检查中，有两项是结构上就过不去的——两端加速度不为零，角点上加速度的导数无定义。**

**那不是代码的缺陷。梯形剖面本来就是这样。** **但它意味着「选择回退」等于「关掉一项检查」**——**因此本仓库不把它留给发现，而是写进测试。** **设了加加速度上限，`admit` 就一台梯形也不放行；不设，就通过。**
